# 日本語用語集

プロンプト階層の規則群で使われる用語を、統一した語彙で定義する。
この用語集は管理資料であり、システムプロンプトには展開されない。
各ファイルの本文は、この用語集に依存せず単体で伝わる語を使う。

## 語彙の原則

- 機械的に照合される値・ID のうち、外部コード（テンプレート変数、ファイル名、スキル名）と一致するものだけ英語のまま維持する。
- それ以外の制御語彙は、バックティックで囲んだ日本語で表す（文字列照合は言語非依存なので、英語である必要はない）。
- 区別する必要のない概念は、1つの語に統一する。同じ概念を別の語で呼ばない。
- 定義が必要な語は命名が悪い。語は単体で伝わるものにする。

## 1. 手続きと段階

| 用語         | 意味                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 要件レビュー | 要件契約候補または派生契約を、意味上の義務の有限集合として検査すること                                 |
| 初回レビュー | review-orchestration の第1段階。固定した検査集合を観点別に展開して実行する                             |
| 独立監査     | review-orchestration の第2段階。新規のエージェントが、固定した指摘集合の処理だけを確認する             |
| 裁定         | 親エージェントが指摘を採用/却下/要調査/対象外の4値へ分類すること                                       |
| 採否         | 監査結果に基づき、監査対象（完成修正候補または元の対象）を採用するか不採用にするか                     |
| レビュー対応 | 固定した指摘集合を現成果物と作業契約へ1回だけ再現し、4値分類と修正契約を決めること                     |
| 準備完了判定 | 実作業の前に必要な拘束、未決事項、合否を区別する観測結果を判定し、要件契約と実作業の入口を確定すること |

## 2. 主体

| 用語                 | 意味                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| 親エージェント       | サブエージェントを起動し、手続きを所有・運営するエージェント。入力の固定、裁定、候補作成、採否を担う |
| 新規のエージェント   | 手続き内のどのタスクも引き継がないで起動したエージェント。独立監査の実行者はこれに限る               |
| 実行者               | レビューまたは監査を割り当てられたサブエージェント                                                   |
| 汎用サブエージェント | general-fast / general-strong                                                                        |
| 専用エージェント     | requirement-reviewer / review-audit                                                                  |

## 3. 入力と成果物

| 用語               | 意味                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| 入力               | スキル・サブエージェントが要求する情報一式。本文に直接書く場合も、ファイルパスで渡す場合も同じ         |
| 制御入力           | 手順、禁止、出力形式などの指示。検査対象の入力と混ぜてはならない                                       |
| 依頼引用           | 依頼本文と後続の訂正・追加・選択の逐語引用。要件契約の基底であり、後段が会話の記憶なしに拘束へ到達する経路 |
| 判定根拠版         | レビュー判定の根拠となる資料の版                                                                       |
| 検査対象版         | レビューまたは監査で検査される対象の版。要件レビューでは要件契約候補を指す                             |
| 差分元の版         | 完成修正候補の差分を取る基準となる版                                                                   |
| 要件契約候補       | レビュー前の契約ドラフト。依頼引用と、そこに存在しない拘束の列挙からなる。レビューを通過して要件契約になる |
| 要件契約           | レビューを通過し正式に固定された契約。依頼引用に、その逐語引用になかったが後段を拘束する拘束だけを加えたもの |
| 完成修正候補       | 採用した指摘の修正契約だけから作られた隔離済み成果物                                                   |
| レビュー対応成果物 | review-response の出力。4値分類とレビュー対応契約                                                      |
| 手続き記録         | review-orchestration の手続き記録書式                                                                  |

## 4. 検査と観点

| 用語     | 意味                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 検査集合 | 固定した検査の集まり                                                     |
| 検査単位 | レビュースキルが固定する検査の単位（例: RR-OBL-\<連番\>、RR-CONTRACT-1） |
| 検査項目 | 検査単位内の個別項目                                                     |
| 全検査   | 検査の全部                                                               |
| 観点     | レビュースキルが提供する検査面（関心 / プロファイル）ごとの分割単位      |
| 検査ID   | 検査単位を特定するID（RR-OBL-\<連番\>、RR-CONTRACT-1。英語のまま）       |
| 検査被覆 | 検査の実施状況（検査被覆表）                                             |
| 確認方法 | 検査や指摘を再現する手順                                                 |

## 5. 結果の値

| 用語                             | 意味                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 反例未確認 / 破綻確認 / 判定不能 | 検査項目の3値。破綻確認は失敗を観測した、反例未確認は失敗を観測しなかった、判定不能は情報・環境・権限の不足 |
| 合格 / 不合格 / 判定不能         | 手続きの結果。検査単位の合否は件数から判断する                                                              |
| 判定結果                         | 準備完了判定の値。合格 / 不合格                                                                             |
| 採用 / 却下 / 要調査 / 対象外    | 指摘の4値分類                                                                                               |
| 指摘                             | 破綻確認から生成される。検査ID、対象箇所、破綻、根拠、確認方法、侵害する条件を持つ                          |
| 侵害する条件                     | 指摘が侵害する条件。種類（明示要求/範囲/受け入れ条件/不変条件/該当なし）＋IDまたは逐語引用                  |

## 6. 失敗の選別

| 用語     | 意味                                                               |
| -------- | ------------------------------------------------------------------ |
| 失敗記録 | report-failure が保存する失敗の正式記録。採掘、選別、是正の対象    |
| まとまり | 失敗の選別で観測できる現象ごとに分類した単位。クラスタとは呼ばない |
