# プロンプトと AI 委任に関する問題分析に係る作業規則

プロンプトの変更、スキルの調整、作業規則の変更と統治に関わる作業を行う場合に守るべき規則。

## 目的

- プロンプトを通常のコードや仕様と同様に保守対象として扱うための最小原則と運用ルールを定義する。

## 改善介入ポリシー

- 過去の失敗記録を参考にする。
  - 失敗記録は `./.opencode/local-failure-logs/` にある。概要を知ることができるが、分析が間違っている型の失敗も存在する。
  - より実態に迫るにはセッションログを直接採掘する。OpenCode は sqlite3
    - Claude Code: `~/.claude/projects/`
    - Codex: `~/.codex/sessions/`
    - OpenCode: `~/.local/share/opencode/opencode.db` または `opencode db --format json "SQLITE3 QUERY"`
    - Oh-My-Pi: `~/.omp/agent/sessions/`
    - Pi Coding Agent: `~/.pi/agent/sessions/`
  - 過去のセッションの採掘レポートは `./.opencode/local-failure-logs/session-mining/` にある。
  - 蓄積事例のトリアージレポートは `./.opencode/local-failure-logs/triage/` にある。
- 失敗記録の作成日時とこのリポジトリの git 履歴を照合し、当時存在しなかった規則が現在は存在しているかどうかを確認する。
- 試験や検証の記録は実際の失敗事例ではないので別の検証記録として扱う。

## 関連資料

- 目的と問題の分析: `references/problem-analysis/fundamental-problem-map.md`
- 指示と規則の妥当性に関する判断軸: `references/quality-principles.md`

## 作業前の確認項目

- [ ] 追加ではなく、まずは言い換え・統合・移設、プロンプト編集以外の介入方法で対応できるか検討し、決定した対応方針とその理由を人間に合理的に説明した
- [ ] どの層（システムプロンプト / スキルの `description` / スキル本文）へ何をするかを決定し、なぜその層であるのかを説明し、人間の同意を得た
- [ ] 重要な条件文について、その時点で可視な情報だけで判定できるか確認した
- [ ] 条件分岐が別スキルや別工程の結果を要求していないか確認した
- [ ] 必須動作と保持すべき能力 / 制約を編集前に分けて洗い出し、説明した

## 作業後の確認項目

- [ ] 重複している規則は残っていないか
- [ ] 同じ指示を別表現で複数書いていないか
- [ ] 既存の用語、章名、見出しをそのまま使い、同じ概念や手順に新しい章や節を作っていない
- [ ] 同じ概念を指す表記が本文全体で一致している（表記揺れがない）
- [ ] 長い行動規範が常設プロンプトに残っていない
- [ ] 例外条件が本文に埋もれていない（必要なら専用のスキルに移す）
- [ ] 未解決事項や受け入れ条件の不足を、実行不能な阻害要因と取り違えていない
- [ ] タスクや場面に固有の権限や禁止事項が適切な層に書かれているか
- [ ] 変更が失敗対応のためである場合、変更の理由と影響範囲を関連する失敗報告またはトリアージレポートに記録した
- [ ] 追跡対象のプロンプトファイルには確定済みの規則だけがある
- [ ] 未整理の証拠・長い会話断片・生ログ・到達不能なファイルパスがプロンプト本文に存在しない（`.opencode/work/local-failure-logs/**` など）
- [ ] 抽象的な価値判断を、観測可能な代理条件や具体的な発火条件に分解した
- [ ] サブエージェント等の別主体が担うべき認可、レビュー、検証を、監督対象自身の判断、自己確認、自己申告で代替していない
- [ ] 挙動上意味のある指示を削除した場合、同層の言い換えまたは別層への明示的な移設で保存した。または、その挙動を削除することこそが介入であることを示した
- [ ] 目的 / 発火条件 / 必須出力 / 禁止行動 / 検証対象が、該当能力の階層全体から抜け落ちていない
- [ ] コマンド名、引き渡し先、スラッシュコマンド表記が一貫している
- [ ] 本文に、このリポジトリのテンプレート実体化のために使われるファイルパス（`.chezmoitemplates/`、`dot_agents/`、`dot_config/` などの実体化前のパスおよびそれを前提とする相対ファイルパス）を含めていない
- [ ] 規則や手順をファイル名で参照していない
- [ ] 規則や手順の参照は概念名またはプロンプト本文中に記載のある章や節の名前で書かれている
- [ ] スキルのフォルダに配置した関連ファイルへの参照はスキル名のフォルダを基点とした相対パスで書かれている
- [ ] `scripts/check_vocabulary.py` の結果、`unaccounted` / `dangling` / `dead` / `file-ref` がすべて 0 である
- [ ] `scripts/check_vocabulary.py` で検査対象となる語彙の数が必要最低限度であり、すべての語彙の必要性と欠落した場合に想定される混同が容易に推測できる
- [ ] `references/obligation-vocabulary.md` に記載の曖昧語彙がプロンプト本文に存在しない
- [ ] スキルはそれ単独で理解可能な本文になっている
- [ ] スキルとサブエージェントの `description` はそれ単独で他の統治規則や他のハーネス拡張機能、このリポジトリのローカル規則、他のスキルの存在と理解を前提とせずに説明されている
- [ ] スキルとサブエージェントの `description` で使うべき条件、使わざるべき条件を示している
- [ ] スキルとサブエージェントの `description` で示された条件が他のどのスキルとも重複していない
- [ ] 共通システムプロンプトでスキルやサブエージェントへの誘導をしていない。確実な状態遷移のためにやむを得ずスキルへの誘導が必要な場合でも、そのスキルやサブエージェントの `description` に書いてあることを改めて説明していない
- [ ] 共通システムプロンプトの構成に使用するテンプレート断片で、複数のファイルで同じ説明が書かれていない
- [ ] `references/quality-principles.md` に記載の設計原則に違反するプロンプト本文が存在しない
