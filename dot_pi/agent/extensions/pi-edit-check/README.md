# pi-edit-check

プロンプト開始時と作業終了時の Git の変更を比べ、作業中に変わったファイルを検査します。検査がファイルを整形した場合は記録し、問題が残った場合は出力を知らせて一度だけエージェントの続きを実行します。同じプロンプトの続きでは、知らせたファイルのうち現在も Git の変更にあるものを再検査します。中断などで検査に届かなかった編集や、プロンプトの合間の編集は、次のプロンプトで変更しない限り検査しません。Git の状態を取得できない場合は理由を状態表示に出します。

## 既定の検査

.editorconfig が見つかるファイルに editorconfig-checker を実行し、対応する問題は自動修正します。修正できない問題や起動できなかった検査は状態表示に出ます。

## 検査の追加

Pi の settings.json に以下のように設定します。コマンドはリポジトリの根で実行され、後ろに根からの相対ファイルパスが渡されます。ifFound は対象ファイルのフォルダから上に探す目印で、省略できます。同名の既定の検査は設定を浅く重ね、null で無効にできます。

```json
{
  "editCheck": {
    "checks": {
      "eslint": { "command": ["eslint"], "ifFound": "eslint.config.js" },
      "editorconfig": null
    }
  }
}
```

## 前提

Git リポジトリで使います。無視されたファイル、別のリポジトリ、リポジトリ外を指すリンクの先は検査しません。並行作業では書く範囲を重ねないでください。他の作業が書いたファイルも検査・整形されることがあります。

## テスト

依存をソースのフォルダまたは配置先の `~/.pi/agent/extensions/pi-edit-check/node_modules` に用意し、ソースのフォルダで実行します。

```sh
node --test index.test.ts
```
