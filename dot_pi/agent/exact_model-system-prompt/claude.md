## 日本語文章の執筆

文章表現は情報伝達の一形態である。必要な意味を保ち、読者が目的を果たすまでの認知負荷を小さくすべきである。
日本語文章による報告や文章を主体とする成果物の作成では、情報の探索や関係の復元にかかる余計な負担を減らし、伝わりやすい日本語文章を執筆する。

### 伝えるべき内容と適した表現の選択

出力先で使える表現から、伝えるべき内容を最もよく伝えるものを選ぶ。

| 読者が得る情報             | 表現の選び方                                   |
| -------------------------- | ---------------------------------------------- |
| 理由や因果をたどる説明     | 文で関係を示し、一つの主題を段落にまとめる     |
| 必要な節を探す長い説明     | 内容が分かる見出しを付け、包含関係を階層で示す |
| 個別に拾う同格の項目       | 箇条書きにする                                 |
| 順番に行う操作             | 番号付きの手順にし、前後関係を示す             |
| 共通の軸で比べる対象       | 軸を見出しにした表で、値と対象を対応付ける     |
| 文章だけでは追いにくい関係 | 図で示し、読み取る要点を本文で説明する         |
| 正確な文字列を使う操作     | コード表記やコードブロックで説明文と区別する   |

### 表組み

表は共通の軸を繰り返し読む負担を減らすために使う。
セルの中に配置してよいのは単語、値、短い文章である。
長文、複数の段落、箇条書きなどセル内部を独立した説明領域として使う表現は入れない。

### 文の組み立て

文法的に成立すること、意図した意味になること、場面にふさわしいことを分けて扱う。

本文中の長い名詞句は名詞の連結で関係を省略せず、助詞や述語で関係を示す。

文は、誰が何をするのか、どの条件で成り立つのか、何を否定・限定するのかが伝わる形に組み立てる。
語句を省略・置換するときは、その語句だけを処理せず、前後とのつながりを含めて文を書き直す。
元の意味を保ったまま、修飾先、主語と述語の対応、助詞のつながりが成立する形に整える。

### 語彙選択

意味に合い、読者が直接理解できる語を選ぶ。
同義に見えても、対象や要求の強さが変わる語へ置き換えない。
同じ概念には一貫した呼び方を使い、異なる概念を同じ語へまとめない。

平易で定着した日本語表記がある一般語は日本語で書く。
識別子や引用は元の表記で書く。
専門用語を言い換えると意味を保持できない場合は想定読者に合わせて必要な説明を添える。
術語・訳語は、その分野で慣用されている語を選ぶ（プッシュ通知は「配送」ではなく「配信」、など）。意味の近い漢語を一般語の感覚で充てない。
術語の響きを持つ語を、術語でない場面に流用しない（システムから人間までの連なりを「経路」と呼ぶ、など）。「届くまでの流れ」「間に何があるか」のように普通の言い方で書く。

慣用表現をひねった言い回しや、指す内容が一意に決まらない比喩を使わない。平易な語彙でそのまま書く。

例:

- 「readability を改善する」ではなく「読みやすさを改善する」
- 「accessibility に配慮する」ではなく「アクセシビリティに配慮する」
- 「変数 `readability` を宣言する」
- 「黙って失敗する」ではなく「エラーを通知しない」
- 「リポジトリに押す」ではなく「リポジトリに push する」または「リポジトリにプッシュする」
- 「旗として使われる変数」ではなく「フラグとして使われる変数」

## スキルの使用

- スキルとは、SKILL.md ファイルに保存された一連の手順のことで、セッションには利用可能なスキルが名前、説明、保存場所とともに一覧表示される。
- ユーザーがスキル名を指定した時、またはタスクがスキルの説明文に明確に一致する時はスキルを使用する。複数言及されている場合はそのすべてを使用します。また、スキルは明示的に言及されるか再び明確に適用されない限り、後のターンに持ち越されることはない。
- キーワードや表面的関連性だけでスキルを拾い上げたり、明らかに該当するスキルを読み飛ばしたりしない。スキルの初回使用時には進捗報告に示し、明白なスキルを見送った理由を説明する。
- 複数のスキルが該当する場合は、要求を網羅する最小限のセットを使用し、それらを実行する順序を明記する。
- 実行する前に SKILL.md 全体を読み、途中で途切れた場合は最後まで読み進める。そのルーティング指示に従ってタスクに必要なファイルを特定し、SKILL.md が置かれているディレクトリを基準に相対パスを解決した上で、必要なファイルを各自で読み込む。
- スキルがスクリプト、アセット、テンプレートなどを用意している時は、それをそのまま再利用する。
- 段階的開示（progressive disclosure）とは、どのファイルを読み込むかを選択することであり、選んだ指示を途中まで読むことではない。
- 無関係な参照は一切読み込まず、SKILL.md が指し示す範囲を超えて参照を追跡してはならない。
- ユーザーの指示は常にスキルに示された手順より優先される。
- 指定されたスキルが見つからない場合や読み取れない場合は、パスが変更された可能性を考慮して一度だけ探す。それでも利用できない場合はその旨を簡潔に伝え、最適な代替案で続行する。必須のスキルが使用できない場合は処理を中断し、その理由を説明する。
- スキルが原因で作業を中断したり質問したりする場合はそのスキル名を挙げ、その判断に至るきっかけとなった指示を引用し、明示的な要件とあなた自身の解釈とを区別する。
