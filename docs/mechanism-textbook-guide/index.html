mechanism-textbook の手順を読む

第1章　教科書を作る仕事の全体像

本書は、mechanism-textbook の手順と参照資料を対象に、規則として定められた仕事と情報のつながりを説明する。対象の版は出典に記したコミットに固定する。読む順序と各章の前提は目次に示す。

読む順序：第1章 → 第2章 → 第3章 → 第4章

  1. 第1章　教科書を作る仕事の全体像（前提章なし）
  2. 第2章　対象理解と読者の出発点（第1章が前提）
  3. 第3章　説明の設計と執筆（第1〜2章が前提）
  4. 第4章　確認と修正の進め方（第1〜3章が前提）

幅の広い図表は、その枠内を横に送って読める。出典番号は章末の注に対応する。

人に仕組みを理解してもらう説明を作りたいとき、対象について詳しく調べる仕事と、その知識を人が学べる形にする仕事が必要になる。mechanism-textbook は、この二つを分けてから、実際の文章や図表を作る。ここでは、その受け渡しと、先へ進む前に確かめるものを見ていく。[1]

1.1　調査・設計・制作の役割

最初に、対象を説明できるようになることと、その説明を読者が理解できる順に組むことを分けて考える。この違いが、調査の後に設計を置く理由になる。[1]

出発点では、読者に何ができるようになってほしいかを決める。これが到達点である。「何の用語を載せるか」ではなく、「どんな性質や関係を説明できるようにするか」「学んだ関係から、別の場面の結果まで導けるようにするか」を定める。あわせて、読者がすでに知っていること、つまり既有知識を確かめる。名前を知っていることと、推論に使える性質まで知っていることは区別する。[2]

到達点が決まったら、書き手は資料を調べ、対象の性質が、何を前提に、どんな規則や関係によって成り立つかを組み立て直す。これが知識体系の再構成である。事実を集めるだけでなく、その事実を結んで結果を説明できる状態にする。[3]

しかし、対象の性質を支える前提が分かっても、その前提を読者が知っているとは限らない。そこで、必要な前提を読者の既有知識までたどり、何から教えれば先へ進めるかを決める。対象の構造や資料の目次をそのまま写すのではなく、読者が学ぶ順序へ組み直す。調査で得た関係と、読者についての情報が、ここで一緒に使われる。[5]

表現の分担とは、示すべきことを文章・表・図などに割り当てることで、次節「学ぶ順序と表現の分担」で選び方を扱う。[13]

その結果を、章ごとに「何が理解できるようになる章か」「どの章を前提にするか」「各節で何をどう示すか」として記録する。この記録が章の設計である。制作では、これに沿って図を描き、本文を書く。設計に記録したことが、制作する内容の根拠になる。[6][9]

三つの仕事で受け渡すもの。[3][5][6][9]
仕事使う材料次へ渡すもの
対象を理解する到達点と、対象の資料・実装など性質を支える前提・規則・関係と、その根拠[3]
説明を設計する対象の前提関係と、読者の到達点・既有知識章と節の順序、推論の道筋、表現の分担[5][6]
表現と本文を作る確認を終えた設計と、対象の根拠読者が読む文章・図表など[9]

表では、同じ「使う材料／次へ渡すもの」という観点で三つの仕事を比べた。次の図は、材料がどこで合流するかを示している。図中の「導出」は、前提と関係を使って結果へ至る推論の道筋を指す。細かい分け方は次節「学ぶ順序と表現の分担」で扱う。[6]

全体を通して、対象の理解、説明の構成、最後の本文の一貫性に責任を持つのが編集責任者である。一人で書くなら執筆者が兼ねる。調査や執筆を分担しても、この全体の責任は残る。[11]

1.2　学ぶ順序と表現の分担

説明の設計では、知識を並べる順序と、その知識をどう見せるかを決める。同じ仕組みでも、読者にたどってもらう関係と、比べてもらう関係とでは、必要な表現が変わる。[5][13]

章の順序は、理解の前提で決まる。ある章で読者に結果を導いてもらうために、別の章で教える性質を使うなら、性質を教える章を先に置く。これが前提にする章という関係である。単に別の章の名前に触れることではなく、そこで得る理解を結果の導出に使うかどうかで決める。[5]

各節では、何を説明する節なのかを決める。これを節の問いと呼ぶ。そこに推論があれば、結果へ至るまでに当てはめる関係を、一段に一つずつ書き出す。これが導出の段である。各段には、必要な前提をどこで教えるか、対象の事実の根拠はどこにあるかも記録する。段ごとに前提が見えるので、何を先に教える必要があるかを照らせる。[6]

そのうえで、節の問いと導出から、示すべき関係と、それを使って読者がすることを取り出す。「項目を比べる」のか、「分岐をたどる」のか、「理由から結論へ進む」のか。それぞれの仕事を文章・表・図などに割り当てたものが表現の分担である。[13]

たとえば、このスキルが定める四つの確認を説明する場面を考えよう。確認の種類と時点は、次節「制作の途中に入る確認」で扱う。四つの確認は、対象も時点も異なる。その違いを比べる仕事と、確認を挟んで先へ進む経路をたどる仕事は、同じものではない。スキルは、共通の観点で項目を比べる仕事には表、分岐や合流の経路をたどる仕事には図、理由から結論へ進む筋道には文章を選ぶと定めている。この規則を当てはめると、次のように分担できる。[9][13]

四つの確認を説明するときの表現の分担。[9][13]
読者がすること取り出した関係担当する表現
四つの確認の違いを比べる各確認について共通の観点をそろえる表：対象と時点を行列にする
本文に進むまでの経路をたどる前後の依存、図がある場合とない場合の分岐図：接続と分岐条件を示す
その順序が必要な理由を理解する前提から結論へ進む筋道文章：何を前提に、なぜ次が決まるかを結ぶ

このように、一つの節にも複数の表現を使える。同じ節を図だけ、文章だけに固定せず、それぞれの仕事を章の設計へ記録する。[13]

図に割り当てた仕事には、さらに図の計画を作る。何を思い描かせる図か、それが成り立つ空間はどこか、その空間で何に答えるか、答えは何か、操作して読むか、どの形で描くかを決め、置く節も記録する。図の形の選択は、この計画の中に含まれる。[14][6]

1.3　制作の途中に入る確認

確認は、原稿を書き終えた後だけに行う仕事ではない。後の作業が使う前提を、その作業の前に確かめるため、対象理解・設計・図・本文のそれぞれに置かれる。ここでは、新しく本を作るときの確認の位置をたどる。[9][18]

まず、対象について「何が何につながり、どちらへ作用やデータが流れるか」を書き出す。これが形の仮定である。物理的な形だけでなく、信号や情報の向きも含む。この仮定を支えるのが、規格、仕様、実装、実測の記録などの一次資料である。形の仮定は、出典の一次資料が本当にその関係を述べているか、章の設計に進む前に確認する。[4]

章の設計では、読者が本の説明から結果を導けるかを調べるため、本文では答えを述べない別の例も作る。これを確認用の例と呼ぶ。その例についても導出の段を書き、本文で教える知識と既有知識だけで結果まで届くかを確かめる。確認用の例は、演習に使う場合を除き、読者に読ませる本文ではなく執筆側の記録に置く。[6]

四つの確認は、次のように異なるものを比べる。確認者は、確かめる対象を作っていない、新しく起動した別のエージェント、つまり作業を担当するAIである。書き手が意図を知っているために、書いていない前提や描いていないものを補って読むことを避けるために分ける。[9][19]

四つの確認の対象と時点。[4][6][9][17]
確認何を何と照らすかいつ行うか
① 形の仮定の確認対象の接続・作用・流れについての仮定と、出典の一次資料対象理解の後、章の設計へ進む前[4]
② 設計の確認全章の設計・確認用の例・導出と、理解のために定めた条件すべての章の設計を記録した後、図と本文の制作前[6][24]
③ 図の読み取り説明文を隠した図から読み取った問いと答えを、図の計画と照合その章の図を描いた後、本文を書く前[25]
④ 内容と表示の確認本文と設計・根拠・書き方の規則、および実際のページの表示[9]各章の本文を書き終えたとき[26]

③の図の読み取りでは、確認者に図の計画や本文を見せない。図だけから何が読めたかを返してもらい、編集責任者が、その返答と計画を照合する。図の意図を先に教えてしまうと、その意図を確認者が補って読めてしまうからである。何を渡し、何を隠すかの違いは、第4章「確認者に渡す情報」で詳しく扱う。[17][19]

この順序で重要なのは、確認をした印を付けることではなく、後の作業が前提にする問題を解消してから進むことである。形の仮定を確かめてから設計し、設計を確かめてから図を描く。図がある章では、その図から必要なことが読めるかを確かめてから本文を書く。図を説明する本文を、まだ読み取れない図の上へ作り込まない順序になっている。[18]

元のスキルの「手順6」は、この四つの確認を定める場所である。その番号は、確認をすべて最後にまとめるという実行順を意味しない。各確認は、図に示した前後関係で途中に入る。すべての章が書き終わった後には、章をまたぐ記述の一致、用語の意味、章や節の順序について、本全体の確認も行う。[9][18]

別のエージェントを起動できない場合に限って、編集責任者が同じ条件を使って自分で確認する。その場合は、独立した確認をしていないと記録し、報告する。[21]

1.4　作業途中の判断をたどる

前節の確認時点を、二つの作業状況に当てはめてみる。どちらも「一章を先に書きたい」という場面だが、先にそろっているものが違うと、進める作業も変わる。

一章分だけ設計ができている場合

第一章の設計はできたが、残りの章はまだ設計していない、とする。本文を書き始める前には、すべての章の設計と確認用の例、導出の段を記録し、本全体について設計の確認を受ける必要がある。一章分だけでは、この確認に必要なものがそろっていない。したがって、この時点で進めるのは第一章の本文ではなく、残りの章の設計である。[6]

なぜ全体を先にそろえるのか。章の順序は、その章が別の章で教える理解を使うかどうかで決まる。使う側の章まで設計して初めて、どこで何を先に教える必要があるかを、本全体として照らせる。本文を先に固定する前に、この関係を検査する順序を採っている。[5][6]

全章の設計の確認が終わっている場合

今度は、全章の設計の確認が済み、制作の前提となる設計の問題も解消しているとする。第一章では図の読み取りと、定められた手順での指摘への対応を終え、本文の前提となる図の問題も解消した。一方、第二章の図はまだ制作中だとする。設計の確認後は、章ごとに図と本文の制作・確認を分担し、並行して進めてよい。全章の本文を一斉に書き始める必要はない。[11]

第一章では、必要な図の読み取りと指摘への対応を終え、本文の前提となる図の問題も解消しているので、本文へ進める。第二章ではまだ図の制作と読み取りを続ける。全章の設計を先に確認するという条件と、章ごとに必要な確認を終えて本文へ進むという条件を、両方満たす進め方である。[9][11][18]

この二つの状況から、作業は「全章まとめてそろえるもの」と「章ごとに先へ進めるもの」に分かれると分かる。全章の設計の確認が、章ごとの制作を始める境目になっている。[6][11]

1.5　本文と作業記録の役割

調査、設計、制作、確認を受け渡すには、何を根拠に決め、どこまで終わったかを保存する場所が要る。それが、執筆側の作業記録である。読者が読む本文と、必要なときに引く参照資料とは、役割を分ける。[10][11]

本文・参照資料・作業記録の使い分け。[10][11]
置く場所置く内容主な使い方
本文理解に必要な前提・関係と、結果を導く説明読者が読み進めながら理解を作る[10]
参照資料網羅的な一覧、長い抜粋など必要な項目をその都度引く[10]
作業記録到達点、既有知識と出どころ、対象理解、章の設計、確認と修正の状態執筆側が判断を引き継ぎ、制作と確認に使う[11]

章の本文は、作業記録にある設計から書く。確認者も、その設計と本文が一致するかを確かめる。そのため、設計を変えたら作業記録も更新する。記録の入力と保守は執筆側の仕事であり、読者や依頼者に記入してもらうものではない。[6][11]

一方、本文には対象の仕組みを説明する内容を置く。書き手が資料と照合した経緯や、確認を通ったことは、それ自体では対象の仕組みの説明にならない。検証の経過を渡す必要があれば、参照資料へ分ける。本文を理解するために不可欠な説明まで、参照資料へ追い出すことはしない。[10]

この分担により、読者は仕組みを理解する道筋を読み、執筆側はその道筋が何を根拠に、どんな設計で作られたかをたどれる。章をまたいで前提を使うときの具体的な書き方は、第3章「章の中で前提をそろえる」で扱う。[1][10][11]

確認を終えても、その事実だけで人間が無理なく学べたとは扱わない。エージェントによる確認が調べるのは、説明に必要として定めた条件を満たすかどうかである。人間の途中評価を受けられる進め方では、全体の見通しと十分な深さを含む代表部分を先に書き、読み手の判定を受けてから残りへ展開する。完了条件と人間の評価の関係は、第4章「完了と残るもの」で扱う。[9][11][12]
