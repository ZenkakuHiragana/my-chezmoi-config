# 実装

依頼で定まった目的、対象、保つ条件、完了確認に従って対象を変更し、実際の結果を確認する。変更中に露出した選択の扱いは「実装中の判断」に従う。

## 実装前の確認

次を実行前に確認する。

- 変更する対象と対象外
- 達成する結果
- 保つ意味、公開インターフェイス、設定、データ形式、既存経路
- 完了と判定する観測可能な結果
- 変更理由と、必要な根拠

対象に存在する受け入れ結果、公開インターフェイス、永続状態の所有先、結果を生む実経路、確認結果の意味が決まっていない場合は、変更を始めず、不足する判断を返答で示して停止する。対象に存在しない概念は該当なしとして扱い、未確認の意味を仮定してはならない。

## 読むもの

変更が影響する対象ファイル、入口、呼び出し元と利用側、公開契約、関連する型・スキーマ・設定、挙動を定めるテストと文書を直接読む。生成物や実行時の設定が結果を左右する場合は、それらの所有先も確認する。

## 編集原則

- 受け入れ結果を満たす最小のまとまりを変更する。
- 公開インターフェイス、設定キー、文書化された手順、データ形式を変えた場合は、直接影響を受ける関連面を確認する。
- 現在有効な内容を直接書き、古い規範文の墓標を残さない。
- 代替経路、機能切り替え、互換用の補助層、移行経路、警告抑制は、要求または既存契約があるときだけ追加する。
- 既存の利用者変更を戻さない。

## 実装中の判断

新しい選択が、受け入れ可否、公開インターフェイス、永続状態または所有先、結果を生む実経路、確認結果の意味のいずれかを変える場合、内部判断で閉じず、選択を持つ主体へ戻す。既存の所有境界と認可範囲内で、どの選択でも結果が変わらない下位実装だけを自分で選ぶ。

## 固定された指摘への対応

レビューや検査で既に示された指摘を扱う場合は、指摘の対象、場所、破綻、根拠、確認方法が揃っていることを確認する。指摘された問題が変更前の対象で再現することを同じ確認方法で確かめ、再現しない問題を変更理由にしてはならない。再現した問題だけをまとめて最小修正し、修正後に同じ確認方法と関連するテストを実行する。新しい問題を便乗修正してはならない。

## 失敗時の扱い

確認に失敗した変更を完了扱いにしてはならない。必須資料の読取、差分作成、書き込み、確認のいずれかが失敗または実行不能な場合も、その操作を完了扱いにせず停止する。

失敗したときは、失敗の観測と原因を残し、今回の変更だけを保つ条件を満たす最後の状態へ戻すか、安全な最小状態へ縮小する。今回の変更と既存の変更を安全に分けて戻せない場合は、戻す操作をせず未完了として、残った変更、失敗した確認、再開に必要な判断を返答で示す。既存の利用者変更を戻してはならない。

## 手順

1. 目的、対象、保つ条件、完了確認を確認する。
2. 関連面、利用経路、正本、テスト、文書を読む。
3. まとまった最小差分を作る。
4. 変更したファイルと直接影響を受ける関連面を再読する。
5. 受け入れ結果に直結する確認を実行する。
6. 依頼、認可された判断、確認した事実、実際の差分と結果、実施した確認を突き合わせる。照合のために新しい要求を作ってはならない。
7. 指摘への対応では、変更前後に同じ確認方法を実行する。

## 確認

次の順で、利用できる確認を実行する。

1. 変更したファイルの再読
2. 関連する診断、型検査、静的検査
3. 対象テスト
4. より広い確認

実行できない確認は、未実施の理由と、何を確認できなかったかを返答で示す。実行していない確認を成功と報告してはならない。

## 返す内容

返答には、変更した対象、挙動・文書・設定の変更、実行した確認と具体的な結果、残る未解決の制限、失敗時の再開条件を含める。返答の表示形式は固定しなくてよい。

## 完了条件

- 依頼の目的、対象、保つ条件、完了確認を満たした。
- 関連する正本、利用側、テスト、文書を確認した。
- 変更したファイルを再読した。
- 必須の確認を実行し、結果を観測として返した。
- 古い規範文と不要な互換経路を残していない。
- 新しい意味上の選択を無断で閉じていない。
- 確認失敗を完了扱いにしていない。
- 固定された指摘への対応では、変更前に再現し、変更後に同じ確認方法を通した。
