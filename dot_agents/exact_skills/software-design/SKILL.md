---
name: software-design
description: >-
  ソフトウェアや、エージェントが実行するスキルの実装に先立ち、
  データの表現、責務、インターフェイス、処理の区切りを設計し、
  利用例と変更例を作って設計を確かめるときに使う。
  実装依頼では設計工程を担い、具体的な設計案とその確認を求める依頼では設計を成果として返す。
  一般的な方針の相談、既存の仕組みの説明、実装済みのコードやスキルだけのレビュー、
  設計を変えない機械的な置換や整形には使わない。
---

```python
def condition(prompt: str) -> bool:
    """この指示を読む AI が、現在の対象と文脈に照らして prompt の条件を判定する。"""


def constraint(prompt: str):
    """
    with ブロックを実行している間の行動に prompt の制約を適用する。
    ブロックから呼んだ段階の中の行動にも適用し、ブロックを抜けたら適用を終える。
    """


def do(prompt: str):
    """
    この指示を読む AI が prompt の手順を実行し、完了してから次へ進む。
    先行する手順で確認した対象・資料・結果は、後続の手順でも参照する。
    """


def 実装前に設計を作り使って確かめる():
    with constraint("""
        この作業の成果は、依頼を実現するデータと処理の構造と、本体の実装前に、その構造で利用と変更が成立するかを確かめた結果とする。
        設計の説明を増やすことを、利用コード、値と状態の推移、変更を加えた案を作業物にすることの代わりにしない。
        確認の対象は、それらの作業物を使って調べる、守るべき条件との不一致と、同じ仕事をする別の設計との違いとする。

        対象は、ソフトウェアコードと、エージェントが実行するスキルとする。
        コードを扱う場面では、型、数値、API、状態、資源寿命などについての以下の具体的な指示をそのまま適用する。
        スキルを扱う場面では、以下の語を次の具体物と対応させて読む。スキルは指示であり、判断・操作を行う主体はそれを読むエージェントである。
        - 本体の実装・製品コード：採用するスキル本文、参照資料、補助プログラムの作成・変更
        - 利用入口・呼び出し側：スキルを選択して読み込む依頼や上位手順と、それを渡す利用者・エージェント
        - 利用コード：渡す依頼と情報、結果の受け取りと利用を記した具体的な利用例
        - 型・宣言・公開された操作や約束：呼び出し側へ示す適用条件、必要な入力、行える操作、結果とその受け取り方
        - データ・値・状態：依頼、参照情報、作業記録、途中結果と、それらの保持・更新状況
        - 関数・処理単位：指示された仕事の区切りと、その判断・操作を担う実行主体
        - 識別子・宣言と使用位置：用語、役割名、成果物名の定義と、それを使う指示や参照箇所
        スキルの補助プログラムには、コード向けの指示を適用する。対応のために、対象にない型や状態、工程を新設しない。

        依頼を受けた主担当が、設計の作成、記録の更新、確認の依頼、結果の反映、実装への引き渡しに責任を持つ。
        調査や設計の一部は委譲してよい。ただし、自分が作った設計や作業物を、自分で独立に確認したことにはしない。
        確認を担うのは、対象の設計を作っていない、新しい文脈のサブエージェントとする。これを確認者と呼ぶ。

        この手順が扱うのは設計工程である。実装の認可、既存の責務分離、作業対象に適用される規則、完成した実装の検証・レビューは置き換えない。
        設計だけの依頼では、製品コードを変更しない。比較用のコードや模型も、依頼で許された場所と操作の範囲を超えて作らない。
        現在そう動いていることだけを、今後も守るべき仕様とは扱わない。
        既に定められた責務分離と設計原則は、今回の依頼が変更を認めている部分を除いて前提にする。
        調べる範囲は、今回新設・変更するものと、その意味や利用が変わる接続先に絞る。リポジトリ全体の再設計を始めない。
        不足に依存しない作業まで止めないが、未確認の内容を前提に採用する設計は確定しない。

        作業記録に残すものは、設計案、根拠、確認する場面、作業物の所在と結果、採否と未確認の範囲とする。
        作業記録の更新は、作業中を通して主担当が担う。置き場は既存の作業用の置き場とし、既存の記録で足りる場合はそこを使う。
        確認者と実装者への受け渡しには、作業記録の所在を含める。
        設計と、確認に使う宣言・利用例には、同じ定義を参照させる。
        主担当が設計を変更した後に、その変更に依存する作業物を古いまま残さない。その更新のために、人間へ入力や同期を要求しない。
        利用の確認は、今回の内部設計と設計担当の利用コードを受け取っていない確認者に割り当て、その確認を終えるまで、その確認者にこれらを渡さない。
        同じ設計案を確認する確認者は、すべて同じ版を対象にする。確認者に渡した版は、その回の確認が揃うまで主担当が書き換えない。
        比較用の模型や試作を作るのは、設計上の選択を分ける箇所に限る。
        試作を動かすために本体を先に完成させたり、未認可の機能を追加したりしない。
        既に得た有効な実測・実行結果のうち、対象と条件が同じことを確かめたものは、取り直した結果と同じく根拠とする。
    """):
        依頼と実物から確認する場面を決める()
        六つの内容を一つの設計として組み立てる()
        設計を使って独立に確かめる()
        設計を組み直して採用する()
        実装へ渡す()


def 依頼と実物から確認する場面を決める():
    原依頼と既存の約束を読む()
    利用・変更・動作・読解の場面を選ぶ()
    不足を処理する()


def 原依頼と既存の約束を読む():
    do("現在有効な依頼、訂正、選択、承認を直接確認する。")
    if condition("要件契約など、原文と参照先を保持する記録が既にある"):
        do("その記録を使い、別の要件文書へ書き直さない。")
    if condition("既存の対象を扱う"):
        do("適用される作業規則、実際の利用入口、呼び出し側、型やデータ形式、外部との接続、既存の検証を読む。")
    do("読み取った事実、既に約束されている条件、今回選ぶ実現方法を区別する。")
    do("対象から実在する参照や受け渡しをたどる。")


def 利用・変更・動作・読解の場面を選ぶ():
    with constraint("""
        ここで選ぶ場面は、依頼の範囲を増やすものでも、すべての入力の正しさを証明するものでもない。
        仮想の将来機能を追加する場面は作らない。
        動作の場面を選ぶ根拠は、対象の仕様と実際の処理にある条件とする。珍しい入力を思い付いたことだけでは、対応義務を作らない。
        同じ条件と関係を確かめる場面は重複させず、役割が異なる場面は一つの成功例で代用しない。
        数を揃えるために場面を作らない。
        依頼された結果のうち、どの場面で確かめるか決まっていない部分を残さない。
    """):
        do("""
            設計案の良し悪しを見る前に、次の場面を依頼と既存の資料から取り出す。
            - 利用：依頼された入力を、実際の利用入口から渡して、求められた結果を受け取る。
            - 変更：既存の設定、拡張点、独立した規則について、一つを変え、変わらないものを保つ。
            - 動作：利用経路にある分岐、失敗、中断、状態の更新について、入力から結果まで進める。
            - 読解：その利用や変更を行う人が、出力の決まり方、状態の更新元、変更の影響先をコードから読み取る。
        """)
        do("""
            各場面に、行う操作、与える入力や初期状態、期待する結果と保つ条件、その出どころを添える。
            期待する結果は、設計案の出力から作らない。
            変更の場面には、何を変え、何を変えないかが決まる根拠も添える。
            期待結果やその出どころが見つからない場面は、見つからなかったことを添えて残す。
        """)
        if condition("該当例が無い場面の種類がある"):
            do("その種類について、対象のどの性質から該当しないかを示す。")
        do("選んだ場面と、それに添えた情報を、作業記録に残す。")


def 不足を処理する():
    if (
        condition("開けなかった参照先がある")
        or condition("食い違う資料がある")
        or condition("出どころが見つからなかった期待結果がある")
    ):
        do("確認した範囲と、その不足によって決められない箇所を分ける。")
    with constraint("資料に未記載だったことだけで、仕様が未決定だとは断定しない。"):
        do("不足のうち、主担当が取得できる資料や実物は自分で確認する。")
        if (
            condition("利用側への約束、永続状態の扱い、正本や責務の所有を変更する選択がある")
            and not condition("その選択が、依頼と既存の規則から決まる")
        ):
            do("その選択をユーザーへ返す。")
        do("既存の条件を満たす作り方の選択、転記漏れ、参照先の探索は、主担当の仕事として進める。")


def 六つの内容を一つの設計として組み立てる():
    with constraint("""
        この段階で組み立てる設計は、次の六つの内容を相互に対応させたものとする。
        この段階は、六つの文書や固定様式の表を作ることを求めない。説明、型定義、宣言、図、式、利用コードを、関係を確認できる形で使う。
        - 作業対象とその性質
          残す情報：成果物の形、実行・配布環境、実際の利用入口、維持する既存の約束と参照先
          対象に含める範囲：今回の成果物と、それを受け取る実際の環境・利用側
        - 最終的な入力と出力
          残す情報：意味、外から見える表現、入力の範囲、正常な出力として許す範囲とその根拠
          対象に含める範囲：今回増える、変わる、または変更の影響を受ける外部との受け渡し
        - 概念と識別子
          残す情報：概念の意味、他の概念との区別、既存の用語、コードでの表現と使用位置での名前
          対象に含める範囲：新設・変更する概念と、それを区別するために参照する既存の概念
        - 内部の情報と変換経路
          残す情報：生成元、保持する主体、寿命、更新元、利用先、変換前後の意味と変換理由
          対象に含める範囲：境界を横切る値、共有・保存する状態、結果の意味を決める変換
        - 処理内容と区切り
          残す情報：引き受ける仕事、内部で決めること、公開する操作と約束、依存先、既存の配置先との対応
          対象に含める範囲：新設・変更する処理単位と、責務の接続先
        - 考慮する例外・しない例外
          残す情報：条件、その条件で返す結果と保つ性質、入力の範囲を保証する担当、保証しない機能、その根拠
          対象に含める範囲：利用経路と適用仕様に現れる失敗・境界条件
    """):
        データから処理へ進む()
        例外で何を保つかを分ける()
        do("""
            六つの内容を相互に対応させて作業記録へ残す。
            対象固有の事実と既存の約束には、直接確認できる出どころを添える。
            データ表現や分割、入力の範囲、保証しない機能のうち今回選んだものは、事実や要求ではなく設計上の選択として区別する。
            既存の定義で表せるものは参照し、同じ定義を設計書へ複製しない。
        """)
        if condition("対象がスキル"):
            do("""
                各時点の実行主体と使える情報・権限、条件を判定する主体、操作する主体、受け渡す情報、
                開始・中断・終了の条件と次の担当への接続を、六つの内容へ対応させて作業記録へ残す。
            """)


def データから処理へ進む():
    with constraint("対象にない区別は作らないが、型が同じであることを意味が同じである根拠にしない。"):
        do("場面に登場する情報を先に整理する。")
        do("その情報をどのデータとして表すかを決める。")
        if condition("数値の受け渡しや変換がある"):
            do("型だけでなく、単位、座標系、絶対値と増分、量子化や精度の条件を確認する。")
    with constraint("処理の順番を、そのまま関数やファイルの分割にしない。"):
        do("入力から結果まで場面を進め、各操作を、必要な情報と判断を持つ既存の単位へ割り当てる。")
        if condition("既存の単位で引き受けられない仕事が残った"):
            do("その仕事を担う単位を設計する。")
    with constraint("外部に見える約束を変えず、一つの処理内部で完結する選択は、実装時の裁量として残す。"):
        do("境界を横切る操作について、入出力、副作用、呼び出し前後の条件、失敗の伝え方、資源や結果の寿命を定める。")
        if condition("結果の意味、精度、計算量、資源寿命を左右する計算がある"):
            do("""
                一つの処理内部で完結する場合でも、その計算を「適切に処理する」という文で隠さない。
                その計算を、式、擬似コード、小さな試作のいずれかで具体化する。
            """)


def 例外で何を保つかを分ける():
    with constraint("依存先の制約や共通の例外方針も、今回の対象へ適用される範囲で使う。"):
        do("""
            条件ごとに、機能をどこまで提供するかと、停止・破損・資源の喪失などを防ぐ約束を区別する。
            例えば表示領域に内容が収まらないことから、極端に狭い領域でも全文を表示する要求を作らない。
            一方、表示できないことを、停止や状態の破損まで許す理由にはしない。保つ性質は依頼と適用仕様から確認する。
        """)
        with constraint("""
            保証は一か所に置く。上流が保証する範囲を確かめ直す処理を今回の入口に足さず、入口で確かめた範囲を確かめ直す処理をその先に足さない。
            単に普段は来ない入力を、上流が防ぐ入力と同一視しない。
        """):
            for 入力の範囲 in 設計で扱う入力の範囲:
                do("""
                    その入力の範囲について、範囲の外の値が今回の入口より先の処理へ渡らないことを保証する担当を、次のいずれか一つに決める。
                    - 上流が保証する。値を作る時点で範囲に収めるか、今回の入口へ渡す前に範囲の外を拒む。
                    - 今回の入口が保証する。受け取った値を確かめて、範囲の外を拒む。
                    - どちらも保証しない。
                """)
                if condition("その入力の範囲を、上流が保証するとした"):
                    do("その保証を担う処理や、値の範囲を定めるデータ表現の所在を確認する。")
                    do("その保証が今回の入口にも適用される経路を確認する。")
                    if condition("""
                        その処理を通らない値が、今回の入口へ届く経路がある。
                        処理が中断されて書きかけになった値、別の作り手による値、以前の版が残した値がこれに当たる。
                    """):
                        do("その経路の値は上流の保証に含めず、その経路の値の担当を別に決める。")
                        if condition("その経路の値を、別の上流が保証するとした"):
                            do("""
                                その上流についても、保証を担う処理や値の範囲を定めるデータ表現の所在と、今回の入口に適用される経路を確認する。
                                その処理を通らない値が今回の入口へ届く経路があれば、その経路の値も同じように上流の保証に含めず、担当を別に決める。
                            """)
                if condition("その入力の範囲に、どちらも保証しないとした値がある"):
                    do("範囲の外の値が今回の入口より先の処理へ渡るものとして、その条件で提供する機能と保つ性質を決める。")
                    do("その決定の出どころを、依頼と適用仕様から探す。")
                    if not condition("その決定の出どころが、依頼と適用仕様にあることを確かめた"):
                        不足を処理する()


def 設計を使って独立に確かめる():
    do("確認を始める前に、確認の手順の資料（`references/review.md`）を読む。")
    with constraint("呼び出し側の利用の確認と、実行者の文脈で指示をたどる動作の確認を混同しない。"):
        do("""
            次の確認を、対象の設計を作っていない、新しい文脈の確認者へ割り当てる。
            担当人数は固定せず、同じ判断に必要な関係は分断しない。
            - 利用の確認：公開された型・操作・約束だけで利用コードを書き、入力、同期、呼び出し順に必要な仕事を比べる。
            - 変更の確認：指定された変更を作業用コピーへ適用し、追従が必要な関係と、変更しない振る舞いを確かめる。
            - 動作の確認：入力と初期状態から値、状態、外部への作用、最終結果を求め、期待結果と保つ条件へ照合する。
            - 既存設計との接続の確認：設計案を変更前の実物・原依頼・適用規則へ照合し、責務と外部との約束の変化を確かめる。
            - 命名・分割・読解の確認：宣言と使用位置、分割した形と展開した形、読むために必要な情報の配置を比べる。
        """)
        確認者への受け渡し()
        do("割り当てた確認者が返した結果を受け取り、その結果と作業物の所在を作業記録に残す。")


def 確認者への受け渡し():
    for 確認者 in 割り当てた確認者:
        do("""
            その確認者に、共通して次を渡す。
            - 確認の手順の資料（`references/review.md`）の所在と、担当する確認。
            - 現在有効な原依頼と、対象に適用される既存の規則・約束への参照。
            - 確認する設計案の版と、その前提となる対象知識、用語と利用上の慣習。
            - 確認する場面、その期待結果と保つ条件、各条件の出どころ。
            - 使える資料、道具、作業場所と操作の範囲。
        """)
        do("その確認者に、確認の手順の資料の「確認者に共通の規則」、担当する確認、「確認者が返すもの」を読ませる。")
        if condition("その確認者の担当に、修正案の確認がある"):
            do("その確認者に、確認の手順の資料の「修正前後を同じ条件で比べる」も読ませる。")
        if condition("その確認者の担当に、利用の確認がある"):

    with constraint("""

def 実装へ渡す():
    with constraint("""
        確認した場面の成功を、全入力での正しさや、人間にとっての読みやすさの保証と呼ばない。
        一つの処理内部で完結する実装上の選択は、未完了の設計として列挙せず、実装担当へ委ねる。
        完了時に恒久的な資料へ残すのは、後の利用や変更で必要になる決定理由と、既存の記録先に置くべき情報とする。
        関数一覧や現在状態の写しを、新しい保守台帳として残さない。
    """):
        do("""
            設計工程を終える前に、次の状態を確認する。
            - 今回の入出力、データの意味、責務、境界の約束が対応し、原依頼と既存の規則へ戻って確認できる。
            - 指定した場面を用いた確認が完了し、守る条件との不一致が残っていない。確認できなかった項目を、成功として数えていない。
            - 命名・分割・読解の確認結果と、比較によって採否を決めた理由が残っている。
            - 境界の約束や責任を実装者が新しく補わなければ進めない未決事項が残っていない。
        """)
        if (
            condition("今回の入出力、データの意味、責務、境界の約束が対応し、原依頼と既存の規則へ戻って確認できることを確かめた")
            and condition("指定した場面を用いた確認が完了したことを確かめた")
            and condition("""
                守る条件との不一致が残っていないことを確かめた。
                確認できなかった項目は、成功として数えない。
            """)
            and condition("命名・分割・読解の確認結果と、比較によって採否を決めた理由が残っていることを確かめた")
            and condition("境界の約束や責任を実装者が新しく補わなければ進めない未決事項が、残っていないことを確かめた")
        ):
            do("設計工程を終える。")
            if condition("設計だけの依頼である"):
                do("現在の設計、利用・変更の作業物、確認した範囲、残る判断を返して終える。")
            if condition("実装も依頼されている"):
                with constraint("""
                    別の実装計画へ書き写さず、設計完了を依頼全体の完了にしない。
                    設計書に同じ定義を残して二重管理しない。
                    境界の約束や状態の所有を変える必要が実装で生じたら、対応する設計とその確認へ戻し、その確認を終えるまで、その変更を実装しない。
                    設計に合わせるために誤った実装を維持しない。
                """):
                    if condition("実装を別担当へ渡す"):
                        do("その担当へ、原依頼と適用規則、設計、対応する利用例と確認結果へ直接到達できる参照を渡す。")
                    while condition("原依頼と確認済みの設計から決まる実装の作業が残っている"):
                        do("""
                            原依頼と確認済みの設計を直接使って実装を続ける。実装を別担当へ渡した場合は、その担当に続けさせ、その結果を受け取る。
                            宣言や利用コードを実装・テストへ使える場合は、同じ作業物を育てる。
                            境界の約束や状態の所有を変える必要が生じたら、その変更に取りかかる前に、この手順を区切る。
                        """)
                        if condition("実装で、境界の約束や状態の所有を変える必要が生じた"):
                            do("対応する設計とその確認へ戻す。")
                            if not condition("戻した設計の確認を終えたことを確かめた"):
                                do("その変更を実装せず、確認できた設計と残る範囲を分けて返す。")
                                break
                    do("原依頼と確認済みの設計から決まる実装の作業と、実装で必要になった変更が、すべて終わったかを確かめる。")
                    if condition("原依頼と確認済みの設計から決まる実装の作業と、実装で必要になった変更を、すべて終えたことを確かめた"):
                        do("完成した実装について、実際の利用入口から依頼された結果を確かめる。")
                        do("完成した実装について、対象に適用される検証とレビューを行う。")
        else:
            do("設計工程を終えたことにせず、満たしていない状態とその理由、確認できた設計と残る範囲を分けて返す。")
```
