# 依頼と作業対象の対応付け

ユーザーが求めた仕事を、対象の実態に結び付ける。
依頼に対応する箇所を調べ、その役割と実際の使われ方を確かめる。
そこで従うべき仕様や、周囲との関係によって成り立つ条件も明らかにする。

## 依頼を読み取る

現在有効なユーザーの発言から、何を求められているかを確認する。
発言の意味と強さを保ち、許可や希望を義務に変えたり、要求や禁止を弱めたりしない。

新しい発言を受け取ったら、以前の発言に何が加わり、どこが変わったかを読み取る。
訂正や撤回と両立しない理解は直し、それを前提にした対象との対応付けも見直す。

## 対象を調べる

依頼が指す対象を直接確認する。
名前や配置だけで対応を決めず、その箇所の内容と実際の使われ方を確かめる。

対象だけでは意味や動作が分からない箇所は、呼び出し元や参照先をたどる。
対象の内容や動作を定める仕様は、正本を読み、適用条件とともに確認する。
生成物であれば、その原本と生成処理までたどり、どこで内容が決まるかを確かめる。

観測した事実と、その事実を依頼へ結び付けた解釈は区別する。
一般知識は調べる先を探す手掛かりに使い、対象で確認していない関係を事実として扱わない。

## 分かったことを理解へ反映する

新しい事実を得たら、それまで想定していた対応先や関係が実際に成り立つかを確かめる。
想定と違う場合は、その事実が関わる対象理解を直す。対象の実態を理由に依頼の意味や強さを変えない。

依頼の指す先について複数の候補がある場合は、観測や仕様から区別できるかを調べる。
確認した事実と両立しない候補を除いた結果、対応先が定まるなら、その対応を以後の対象理解として扱う。
対応先が定まらない場合は、対象の実態だけでは確定できないものとして残す。
ここで確定するのは依頼と対象の対応であり、その対象でどの実現方法を採るかは決めない。

ユーザーが既に許可した変更については、その変更によって、確認済みの関係が崩れないかを調べる。
例えば、利用側が使えなくなる、説明と実態が食い違う、同期していた情報が一致しなくなるといった影響を確認する。
影響がある場合は、原因となる変更と、崩れる関係とのつながりを確かめる。

関係先や問題が見つかったこと自体を、調査や変更の範囲を広げる許可として扱わない。
今後も背負う責務と拘束が新たに発生するような案は、観測した事実だけを根拠に採らない。

## 確認できないことを伝える

調べても依頼と対象の対応を確かめられない場合は、確認した事実と、それでも分からない点をユーザーへ示す。
依頼と対象の実態や仕様が食い違う場合は、どの箇所がどう食い違うかを示す。

不足を埋めるために、新しい要求や設計を作らない。
ユーザーへの質問の必要性や内容、実装案も、このスキルでは決めない。
