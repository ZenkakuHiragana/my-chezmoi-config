# 内容と表示を確かめる

この資料は、章の内容と表示を確かめる方法を定める。
どうなっていたら観点を満たさないとするかは、確認の手順の資料（`references/review.md`）の「観点と、満たさない条件」に従う。
この資料の方法は、その条件に当たる箇所を見つけるために使う。

- 執筆者は、章の図を描き終えたときと、本文を書き終えたときに、「2. 表示を確かめる」の確認用スクリプトを実行し、報告された問題を直してから、編集責任者に渡す。
- 内容と表示の確認を依頼された確認者は、この資料の 1 と 2 の方法で、正確さ 1〜11、説明の十分さ 3、読み進めやすさ 1、3〜8、11、成果物の動作の条件に当たる箇所を探し、編集責任者へ返す。章のファイルは変更しない。
- 編集責任者は、確かめた範囲、方法、結果を作業記録に残す。

## 1. 内容を確かめる

正確さと読み進めやすさの条件は、次の突き合わせで確かめる。

- 図と模型：模型を作った対象の図は、図を作るスクリプトを模型から実行し直し、章の図と一致するかを比べる。図の中の数値や名前に含まれる値が、模型の入力や出力から作られているかを、図を作るスクリプトと模型のコードを読んで確かめる。
- 数値：図の説明、図に添えた数値、本文の数値を、模型の出力と比べる。
- 照合の記録：作業記録に、模型の値を模型とは別に得た値と照合した結果があるかを確かめる。別に得た値とは、実装を実行した結果、試験、実測、公開された値、元データの一部を別の方法で数え直した結果などである。実装を読んだだけのものは含めない。
- 根拠の資料：本文の定義、式、主張、コードの抜粋を、根拠にした資料（規格、論文、仕様、実装など）の記述と比べる。書き手が作業記録に写した抜粋ではなく、資料そのものを開いて比べる。主張が成り立つ条件や例外を、資料が付けているのに本文が落としていないかも比べる。
- 章の中と本の中：同じ量や性質についての記述どうしを比べる。
- コードの例：本文が示す環境と手順で動かせる例は、動かして本文の説明と比べる。動かせない場合は、確かめられないと返す。
- 参照：リンクと参照の先を開き、本文が案内した情報があるかを確かめる。
- 節ごとの設計：節ごとに、本文が導入している要素、使っている要素、主張に至る段を拾い、作業記録の節ごとの設計（導入する要素、使う要素、導出の段）と比べて、読み進めやすさ 11 に当たる違いを探す。あわせて、既有知識の記録にもそれまでの本文にも無い語、記号、前提（読み進めやすさ 1）を探す。
- 見出し：すべての見出しを階層ごとに一覧にし、読み進めやすさ 4 に当たる見出しを探す。
- 作業記録との対応：到達点と章の役割に照らして、本筋に関わらない図、逸話、段落を探す。本文が誤解を持ち出して否定している箇所を探し、その誤解が作業記録に読者の誤解として記録されているかを確かめる。

## 2. 表示を確かめる

### HTML の場合

スキルのフォルダにある確認用スクリプトで、ページを実際のブラウザで開く。

```bash
node <スキルのフォルダ>/scripts/check-page.mjs <ページのパスまたは URL> <画像の保存先>
```

- ページは、読者が開くのと同じ方法で開く。読者がファイルを直接開くならファイルのパスを渡し、サーバーから配るならその URL を渡す。
- 操作できる図は、`--state <名前>=<JavaScript>` で状態を作り、その状態の画面も保存する。状態は、操作の部品（スライダーや入力欄など）ごとに最小と最大の値にしたものと、図の説明で触れる値にしたものを作る。作業記録に状態の JavaScript があればそれを使い、欠けている状態は足す。`--state` を指定するたびに、ページを開き直してから JavaScript を実行する。
- 幅は既定で 390 px と 1280 px を確かめる。読者の画面が分かっている場合は `--width` でその幅を加える。
- ブラウザが見つからない場合は、`--chrome <実行ファイル>` か環境変数 `CHROME_PATH` で指定する。
- スクリプトの実行には Node.js 22 以降が要る。
- `--bare` を付けると、図ごとに説明文を隠した画像も保存する。手順 6 の図の読み取りのために、編集責任者が付けて実行する。
- そのほかのオプション（画面の高さ、待ち時間、ブラウザに渡す引数）は、スクリプトの冒頭の説明にある。

スクリプトは、機械的に判定できる問題を報告する。

- コンソールのエラーとスクリプトの例外
- 読み込みの失敗
- 横へのはみ出し
- 説明文の無い図、大きさが 0 の図
- 存在しない場所へのページ内リンク
- 存在しないファイルへのリンク（ページをファイルのパスで開いた場合）
- 表示できなかった画像
- 式の組版の失敗（KaTeX、MathJax）と、Mermaid の図の描画の失敗
- `--state` の JavaScript の失敗

執筆者は、報告された問題をすべて直してからスクリプトを実行し直し、報告が 0 件になるまで繰り返す。
ページの側では直せない問題（確かめる環境から外部の配信元に届かないなど）が残った場合は、その問題と理由を作業記録に残し、報告で伝える。
ページを URL で開いた場合、他のページへのリンクはスクリプトでは確かめられない。リンク先のページもこのスクリプトで開いて確かめる。

スクリプトは、文字の重なりや図の中身を判定しない。
保存された図ごとの画像と、ページ全体の画像を開いて、成果物の動作 2〜8 と読み進めやすさ 3 の条件に当たる箇所を探す。
数式の区切り記号や Markdown の記法が文字のまま残っていないかは、本文の文字列も検索して確かめる。

スクリプトの終了コードは、0 が問題なし、1 が問題あり、2 が確かめられなかった（ブラウザが見つからない、起動できない、ページを開けない）ことを示す。
終了コードが 2 のときは、表示を確かめていない状態として作業記録に残す。
確かめていない表示を、機能すると報告しない。

### Markdown の場合

- 埋め込んだ画像のファイルがあり、本文の参照先と一致しているかを確かめる。
- 画像を開いて、HTML の場合と同じ条件（動作 1 を除く）に当たる箇所を探す。
- 読む場所がその画像の形式（SVG、PNG）を表示できるかを確かめる。確かめられない場合は、確かめていないことを作業記録に残す。
