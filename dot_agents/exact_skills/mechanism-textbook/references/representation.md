# 表現を選び、描く

各章の本文を書き始める前に、この資料を読む。
本文の各箇所で読者が何を判断し、何を推論するかから表現の形を選び、描く手段を決める。
本文を書く前に、「表現を選ぶ」で各箇所を文章、番号付きの手順、箇条書き、表、図のどれで示すかを決める。図は、「図の形を決める」で形を決め、手順 6 の設計の確認を受けてから描き、図の読み取りで確かめてから本文に組み込む。

## 媒体を決める

手順 1 で確かめた、読者が読む場所と成果物の形式から媒体を決める。

- 3 次元の形、条件を変えて試す操作、計算した形を重ねて見せる図が要る場合は、HTML のページにする。
- 読む場所が Markdown しか表示しない場合は、計算で作った画像（SVG か PNG）を本文に埋め込む。操作が要る図は、代表的な状態を並べた静止図にする。
- ページが使うライブラリ（KaTeX、Three.js など）は、ファイルとしてページと一緒に置く。読者の環境から外部の配信元（CDN）に届くと依頼者が明言した場合は、配信元から読み込んでもよい。
- 読者がファイルを直接開く場合、ブラウザは別ファイルのモジュールスクリプトを読み込まない。スクリプトはページに埋め込むか、通常のスクリプトとして読み込む。

## 表現を選ぶ

本文の各箇所を、文章、番号付きの手順、箇条書き、表、図のどれで示すかを、その章で示す関係のつながり方から選ぶ。
文章も選ぶ形の一つである。ほかの形に当たらないことだけを理由に文章にしない。

文章は、関係を一つの並び順でしか示せない。
関係が一本の筋につながっていれば、文の順序を関係の順序に合わせられ、読者は直前に読んだ事柄に次の関係を結び付けて読み進められる。
関係が枝分かれ、合流、輪を含むと、どの順に並べても、前に読んだ事柄へ戻って結び付ける箇所ができ、読者はその事柄を覚えておくか、前を探し直さなければならない。
図は関係を位置で並べ、一つの推論に使う関係を同じ場所に集めるので、離れた箇所に書かれた関係を探して結び付け直す手間が減る。
形、位置、距離、向き、時間の長さは、文章で書くと、読者が頭の中で配置し直さなければ比べられない。

### 示す関係を書き出す

章の設計の節の構成に、節ごとに、その節で示す関係を書く。
関係とは、事柄どうしの間に成り立つ定義、規則、式、事実である。その節で教える関係と、その節で述べる推論の導出の段が当てはめる関係を含める。
事柄は、確認の手順の資料（`references/review.md`）の事柄の照合と同じく、同じ事柄を指す語を一件にまとめて数える。

関係は次のように書く。

- 二つの事柄を結ぶ形で書く。データ、信号、力などが渡る関係は、渡す側と受け取る側を結び、渡るものは関係の内容に書く。
- 三つ以上の事柄を一度に結ぶ関係のうち、二つの事柄を結ぶ関係に分けて書けるもの（「B は A の後、C の前に行う」など）は、分けて書く。式のように分けて書けない関係は、結ぶ事柄をすべて書く。
- 向きのある関係（呼ぶ、依存する、渡す、ある変化が別の変化を起こす、後に起きるなど）は、向きも書く。
- 同格の項目のそれぞれが共通の観点でどうであるかを述べる関係は、項目、観点、値の三つを書く。

関係ごとに、次の種類のどれかを添える。種類は、形を選ぶためだけに使う。

- **位置：** 形、位置、距離、向き、時間の長さの関係
- **性質：** 同格の項目のそれぞれが、共通の観点でどうであるか
- **順序：** 何の後に何を行うか（読者や作業者が行う操作、プログラムや装置が行う処理の手順）。何の後に何が起きるかという出来事の前後は、その他とする。
- **その他：** 上のどれでもない関係（つながり、データの流れ、作用、出来事の前後、式、値の大小など）

位置の関係にも当たる性質の関係（項目ごとの位置や大きさなど）は、位置とする。

### 束を作る

章ごとに、次の二種類の束を作る。

- **対象の関係の束：** 節の構成に書いた関係のうち、事柄を共有するものを一つの束にまとめる。共有をたどって届く関係は、すべて同じ束に入れる。性質の関係は性質の関係どうしで束ね、それ以外の関係は種類を問わずまとめて束ねる。同じ受け渡しを「呼ぶ」とも「渡す」とも書けるので、種類で分けると合流や枝分かれが見えなくなるからである。
- **推論の束：** 本文で述べる推論ごとに、その推論の導出の段を一つの束にまとめる。推論の束の段どうしのつながりは、どの段の結果をどの段が前提にするかであり、導出の段の記録から読む。確認用の例の導出の段は本文に載らないので、束にしない。

対象の関係の束が一本の筋であるとは、束の事柄を一列に並べたとき、どの関係も列で隣り合う二つの事柄だけを結び、向きのある関係はすべて列の前から後ろへ向くように並べられることである。
二つの事柄から一つの事柄へ向かう関係（合流）、一つの事柄から二つの事柄へ向かう関係（枝分かれ）、たどると元の事柄へ戻る関係（輪）、三つ以上の事柄を一度に結ぶ関係のどれかを含む対象の関係の束は、一本の筋ではない。分けて書けない三つ以上の事柄を一度に結ぶ関係は、一つの事柄が他の複数の事柄と同時に結び付くので、合流と同じに扱う。

推論の束が一本の筋であるとは、段を一列に並べたとき、どの段も、前の段の結果としては直前の段の結果だけを前提にし、どの段の結果も直後の段だけが前提にするように並べられることである。
二つ以上の前の段の結果を前提にする段（合流）か、二つ以上の後の段が前提にする結果（枝分かれ）を含む推論の束は、一本の筋ではない。

### 形を決める

対象の関係の束と推論の束のそれぞれについて、次の上から順に、最初に当たる形を選ぶ。

1. 関係を一つも示さない節（一つの事柄の定義や、一つの値で表せる状態だけを述べる節）は、文章にする。
2. 到達点の推論が、条件を変えて結果の変化を確かめることである場合、その条件と結果の両方の事柄を含む対象の関係の束（条件から結果まで関係をたどれる束）は、図にする。
3. 性質の関係の束は、二つ以上の項目が観点を共有するなら表、それ以外（観点を共有しない同格の項目）は箇条書きにする。
4. 本文の導出の段か確認用の例の導出の段が当てはめる位置の関係を含む対象の関係の束は、図にする。推論に当てはめない位置の関係は、5 と 6 の判定ではその他の関係と同じに扱う。
5. 一本の筋の束は、対象の関係の束ですべて順序の関係なら番号付きの手順、それ以外は文章にする。束が長いことを理由に図にしない。
6. 一本の筋でない束は、図にする。

図を選んだ束は、「図の形を決める」で図ごとの形を決める。

### 表現の選択を記録する

形を決めたら、章の設計の表現の選択に、束ごとに次を書く。関係を一つも示さない節は、関係が無いことと文章を選んだことを書く。

- 対象の関係の束か推論の束か。対象の関係の束は含む関係、推論の束は含む段
- 一本の筋か。一本の筋でなければ、その理由（合流、枝分かれ、輪、列の前から後ろへ向きをそろえられない向きのある関係、分けて書けない三つ以上の事柄を一度に結ぶ関係のどれを含むか）
- 選んだ形。節によって形が変わる対象の関係の束は、節ごとの形
- 文章、番号付きの手順、箇条書き、表を選んだ束は、置く節。図を選んだ束は、その束を示す図の名前。図を置く節は、図の計画に書く。

対象の関係の束の形は、その束の関係を示す節ごとに、その節までに示した束の関係（同じ章のそれより前の節と、その節の節の構成にある関係）に「形を決める」を当てて決める。章の束全体では図になる束でも、それより前の節では、その節までの関係で決まる形で示す。
文章以外の形になった節には、その節までに示した束の関係を描いた形（図、表、番号付きの手順、箇条書き）を置く。対象の関係の束の図は、その節までに教えた関係、その節で教える関係、既有知識の記録にある関係だけを描く。
推論の束に図を選んだ場合は、その推論を述べる節に、段どうしのつながりを描いた図を置く。
図や表の隣で、それが示す関係や推論を文章で説明してよい。

系の構造を説明する本では、見方（構成要素のつながり、実行時のデータの流れ、配置など）ごとに図を分け、見方ごとに、全体の図から詳細の図へ段階を下りる図の組にする。段階は、読者の推論に要るものだけを描く。詳細の図には、全体の図のどの部分を詳しくしたものかを示す。

図ごとに、その図を置く節と、その図が描くもの（対象の関係の束の図では束の関係、推論の束の図では段どうしのつながり）を図の計画に書く。

## 図の形を決める

図は、描く前に次の順で形を決め、決めた内容を図の計画として図ごとに作業記録に残す。

1. 図を描く空間を決める。外に描く図の構造は、読者の頭の中に作らせたいものの構造に合わせる。到達点（手順 1）に書いた頭の中に作らせたいもののうち、その図が受け持つものを、その節の理解の型（手順 2）に照らして図の計画に書き、それが成り立つ空間に描く。仕組みの振る舞いを思い描かせるなら、仕組みが実際に動く空間（光線ならシーンの空間、やり取りなら実際の時間軸、形の計算なら実際の座標）に描く。式の関係を思い描かせるなら、変数を軸に取ったグラフに描く。データから主張までの推論をたどらせるなら、処理の段の並び（段ごとの入力と出力）に描く。一つの節で振る舞いと式の関係の両方を思い描かせる場合は、図を分け、図ごとに空間を決める。推論の束の図は、頭の中に作らせたいものではなく推論の段どうしのつながりを受け持つ図なので、この空間の決め方に代えて、前提から結論へ段を並べた空間に描く。
2. 図に持たせる問いを、1 で決めた空間で答えられる形で一つ決め、その答えを出す。問いは、その節の到達点から立てる。推論の束の図では、導出の段の記録（どの段の結果をどの段が前提にするか）から答えを出す。それ以外の図のうち、手順 2 で模型を作った対象の図では、模型の出力から答えを出す。模型を作らない対象の図（構造の見取り図など）では、作業記録の形の仮定から答えを出し、拠った形の仮定を図の計画に書く。答えが拠る事柄（何が何に接し、データがどの向きに流れるかなど）が形の仮定に書かれていなければ、手順 2 と同じく一次資料の出典を付けて形の仮定に書き加える。出典が見つからない事柄に答えが拠る問いは図に持たせず、出典のある形の仮定から答えられる問いに替える。書き加えた形の仮定は、図を描く前に形の仮定の確認を受ける。
3. 読み方を決める。読み方は、読者が図を操作して読むか（操作して読む図）、操作せずに見るだけで読むか（見るだけで読む図）のどちらかである。読む場所が操作できない場合（印刷、Markdown など）と、依頼が操作せずに理解することを求める場合は、見るだけで読む図にする。それ以外の場合で、到達点の推論が条件を変えて結果の変化を確かめることである図は、操作して読む図にする。
4. 1 で決めた空間に描ける形を、下の表と形ごとの注意を使って選ぶ。
5. 選んだ形で描く。

操作して読む図では、最初の状態で答えに関わる現象が見えているようにし、何を操作して何を見るかを図の中か図の説明に書く。答えに関わる値を図の中に表示する場合も、図の形そのものから答えが読み取れるようにする。読み出しの数値だけで答えを示す図にしない。
見るだけで読む図では、操作の部品に頼らずに答えが読み取れるようにする。

本文が読者に推論させる量や関係を、図から読み取れないと分かった場合は、図の説明に「この図からは読み取れない」と断り書きをして済ませない。この手順の 4 へ戻り、形を選び直す。

## 読者の推論に合わせて形を選ぶ

同じ情報でも、表現の形によって読者が楽にできる推論が変わる。
本文の箇所ごとに、読者に要る判断や推論を決めてから形を選ぶ。
「図の形を決める」の 4 で形を選ぶときは、この表を使う。

| 読者に要る判断や推論 | 形 |
|---|---|
| 量を正確に比べる | 共通の軸の上の位置（点、棒の端） |
| 全体に対する割合を見る | 共通の軸の上の位置、または円の角度 |
| 複数の動き手が、時間の中でいつ何を受け渡すか | 実際の時間を縮尺にした時間軸の図 |
| 状態や段階の移り変わり | 段階ごとの静止図を並べる |
| 2 次元の形、位置、距離、方向 | 実際の座標に描いた図 |
| 3 次元の形、位置、向き | 要る面が見える向きの 3 次元の図と、測らせる平面の断面図 |
| 定義から結果を導く | 数式と、記号の対応を示した図 |
| 推論の段の合流や枝分かれ | 前提から結論へ段を並べ、どの段の結果がどの段の前提になるかを線で示した図 |
| 二つのものの違い | 対応する部分をそろえて並べた図や表 |
| 何がどこにあり、何とつながるか | 見取り図 |
| データから主張までの推論 | 処理の段ごとに入力と出力を示す図 |
| 多数の項目から必要なものを探す | 本文には概観を置き、全件は参照資料に置く |

形ごとの注意を次に示す。

- **量:** 面積、体積、色の濃さは、位置ほど正確には比べられない。量を正確に比べさせる箇所では使わない。
- **時間:** 縮尺の無いシーケンス図は、やり取りの順序しか示さない。周期、待ち時間、何かを読み落とす間隔が推論に関わる場合は、動き手ごとに横の帯を引き、実際の時間の縮尺でそろえる。桁の違う時間は、拡大図に分ける。桁の違う周期どうしを一つの図で比べる場合に限り対数の軸を使い、軸が対数であることを図に書く。
- **段階:** アニメーションは一度流れると見直せない。段階を見比べさせたい箇所では静止図を並べる。動かす場合も、止めて一段ずつ送れるようにする。
- **2 次元の形:** どの部分を使って何を計算するか（例: 曲線のどの点から点 P への最短距離をとるか）を、線、記号、寸法線で図に描き込む。
- **3 次元:** 自分で回せることより、推論に要る面が見えていることが理解を左右する。最初から、要る面が見える向きで表示する。回せるようにするのは、向きを変えて確かめることが理解を助ける場合でよい。透視図では距離や角度を正確に読めないので、測らせる距離や角度は、その平面の断面図に寸法線で示す。
- **式:** 図は形と位置をつかませ、式は厳密さと一般性を担う。両方を置く場合は、式の記号が図のどの部品に当たるかを、図の中か図のすぐ隣に書く。読者に記号と図の対応を探させない。
- **違い:** 同じ軸、同じ縮尺、同じ並び順にそろえ、違わない部分も同じ形で並べる。違う所だけが目に入るようにする。
- **データから主張まで:** 各段で何を数え、何を除き、何と何を比べたかを、入力と出力の数値で示す。別の説明の可能性と、それを退けた根拠も、該当する段に置く。コードや長い文の羅列で推論を示したことにしない。
- **操作できる図:** 「図の形を決める」の 3 で操作して読む図にした図に使う。図を描く者は、操作の部品（スライダーや入力欄など）ごとに最小と最大の値にした状態と、図の説明で触れる値にした状態を作る JavaScript を、作業記録に残す。操作して読む図では、操作の順に並べる状態の列（一つの部品の値を小さい方から大きい方へ変えた状態など）も残す。手順 6 の確認で使う。

## 模型から描く

手順 2 で模型（入力から結果を計算するスクリプトやシミュレーション）を作った対象では、模型の出力から図の形と数値を作る。
座標や数値を手で置かない。

- 図と、図に添える数値は、同じ模型の出力を使う。同じ量を別々に計算しない。
- 推論の束の図が描く段どうしのつながりは、模型の出力ではなく導出の段の記録から描く。その図に添える数値は、模型の出力を使う。
- 図やシミュレーションは、本文と同じ条件と規則に従わせる。
- 説明のために仮の入力（実測ではない例の値）を使う場合も、模型にその入力を与えて図を作る。図の説明には、使った入力の値を、図に示した結果が成り立つ条件として書く。仮の入力から得た結果を、対象の実測値として書かない。

模型を作らない対象の図（構造の見取り図など）も、描いた部分とその関係を形の仮定に合わせる。対象と食い違う関係を、説明のために描かない。図の問いに要らない部分を省くのは図の観点の選択なので、図の説明に断り書きを書かない。

## 図と本文を対応させる

- 図は、それを説明する文のすぐ隣に置く。図と説明が離れていると、読者は両方を行き来しながら頭の中に保持しなければならない。
- 1 枚の図に、答える問いを 1 つ持たせる。全体の位置関係をつかむ図と、変化や導出を理解する図は分ける。問いと答えは「図の形を決める」の手順で作業記録に残し、手順 6 の図の読み取りで、確認者が読み取った問いと答えに照合する。
- 図の説明文（HTML では `figcaption`）には、何を見ればよいかを書く。図から読み取ることを本文と結び付ける。
- 名前は凡例より、線や点のすぐ横に書く。
- 写実的な絵より、推論に要る部分だけを描いた図を選ぶ。
- 飾りの図、本筋に要らない写真や逸話は入れない。本筋に要らない情報は理解を下げ、一度に保持できる情報の少ない読者ほど影響が大きい。
- 本文で色の名前を使って図の部分を指す場合は、その色が表示の設定（明るい表示と暗い表示など）によって変わらないようにする。

## ページを組む（HTML の場合）

- 本文の 1 行が長くなりすぎない幅にする。
- 狭い画面でも、ページ全体が横にはみ出さないようにする。幅の広い図、表、コードは、その要素の中で横に送れるようにする。
- 章ごとにページを分ける場合は、各ページに目次と前後の章へのリンクを置く。
- 演習の解答は、折りたたむか別の位置に置き、読者が先に考えられるようにする。

## 描く手段

対象と読む場所に合う手段を選ぶ。次は代表的な組み合わせである。

| 図 | 手段の例 |
|---|---|
| 2 次元の形、時間軸の図 | 模型のスクリプトから出力した SVG |
| データや計算結果のグラフ | matplotlib など |
| 3 次元の形、3 次元の空間での光線の経路 | Three.js など |
| 数式 | KaTeX、MathJax |
| 縮尺が意味を持たないつながりや順序 | Mermaid でもよい |

描いた図は、手順 6 の確認を終えるまで完成としない。
