# 表現を選び、描く

各章の本文を書き始める前に、この資料を読む。
本文の各箇所で読者が何を判断し、何を推論するかから表現の形を選び、描く手段を決める。
図は、本文を書く前に「図を描く箇所を決める」と「図の形を決める」で描く箇所と形を決め、手順 6 の設計の確認を受けてから描き、図の読み取りで確かめてから本文に組み込む。

## 媒体を決める

手順 1 で確かめた、読者が読む場所と成果物の形式から媒体を決める。

- 3 次元の形、条件を変えて試す操作、計算した形を重ねて見せる図が要る場合は、HTML のページにする。
- 読む場所が Markdown しか表示しない場合は、計算で作った画像（SVG か PNG）を本文に埋め込む。操作が要る図は、代表的な状態を並べた静止図にする。
- ページが使うライブラリ（KaTeX、Three.js など）は、ファイルとしてページと一緒に置く。読者の環境から外部の配信元（CDN）に届くと依頼者が明言した場合は、配信元から読み込んでもよい。
- 読者がファイルを直接開く場合、ブラウザは別ファイルのモジュールスクリプトを読み込まない。スクリプトはページに埋め込むか、通常のスクリプトとして読み込む。

## 図を描く箇所を決める

手順 2 で対応物が無いとした事柄のうち、その分野で普段使う表現（コード、ログ、測定値、式など）には現れない状態を持つものは、その状態を図に描く。現れない状態とは、読者がその表現を読んでも直接は見えず、頭の中で組み立てなければならない状態である。
たとえば、コードには現れないメモリ上の配置、通信の記録には現れない装置の内部状態である。
図ごとに、その図を置く節を図の計画に書く。

## 図の形を決める

図は、描く前に次の順で形を決め、決めた内容を図の計画として図ごとに作業記録に残す。

1. 図を描く空間を決める。外に描く図の構造は、読者の頭の中に作らせたいものの構造に合わせる。到達点（手順 1）に書いた頭の中に作らせたいもののうち、その図が受け持つものを、その節の理解の型（手順 2）に照らして図の計画に書き、それが成り立つ空間に描く。仕組みの振る舞いを思い描かせるなら、仕組みが実際に動く空間（光線ならシーンの空間、やり取りなら実際の時間軸、形の計算なら実際の座標）に描く。式の関係を思い描かせるなら、変数を軸に取ったグラフに描く。データから主張までの推論をたどらせるなら、処理の段の並び（段ごとの入力と出力）に描く。一つの節で振る舞いと式の関係の両方を思い描かせる場合は、図を分け、図ごとに空間を決める。
2. 図に持たせる問いを、1 で決めた空間で答えられる形で一つ決め、その答えを出す。問いは、その節の到達点から立てる。手順 2 で模型を作った対象の図では、模型の出力から答えを出す。模型を作らない対象の図（構造の見取り図など）では、作業記録の形の仮定から答えを出し、拠った形の仮定を図の計画に書く。答えが拠る事柄（何が何に接し、データがどの向きに流れるかなど）が形の仮定に書かれていなければ、手順 2 と同じく一次資料の出典を付けて形の仮定に書き加える。出典が見つからない事柄に答えが拠る問いは図に持たせず、出典のある形の仮定から答えられる問いに替える。書き加えた形の仮定は、図を描く前に形の仮定の確認を受ける。
3. 読み方を決める。読み方は、読者が図を操作して読むか（操作して読む図）、操作せずに見るだけで読むか（見るだけで読む図）のどちらかである。読む場所が操作できない場合（印刷、Markdown など）と、依頼が操作せずに理解することを求める場合は、見るだけで読む図にする。
4. 1 で決めた空間に描ける形を、下の表と形ごとの注意を使って選ぶ。
5. 選んだ形で描く。

操作して読む図では、最初の状態で答えに関わる現象が見えているようにし、何を操作して何を見るかを図の中か図の説明に書く。答えに関わる値を図の中に表示する場合も、図の形そのものから答えが読み取れるようにする。読み出しの数値だけで答えを示す図にしない。
見るだけで読む図では、操作の部品に頼らずに答えが読み取れるようにする。

本文が読者に推論させる量や関係を、図から読み取れないと分かった場合は、図の説明に「この図からは読み取れない」と断り書きをして済ませない。この手順の 4 へ戻り、形を選び直す。

## 読者の推論に合わせて形を選ぶ

同じ情報でも、表現の形によって読者が楽にできる推論が変わる。
本文の箇所ごとに、読者に要る判断や推論を決めてから形を選ぶ。
「図の形を決める」の 4 で形を選ぶときは、この表を使う。

| 読者に要る判断や推論 | 形 |
|---|---|
| 量を正確に比べる | 共通の軸の上の位置（点、棒の端） |
| 全体に対する割合を見る | 共通の軸の上の位置、または円の角度 |
| 複数の動き手が、時間の中でいつ何を受け渡すか | 実際の時間を縮尺にした時間軸の図 |
| 状態や段階の移り変わり | 段階ごとの静止図を並べる |
| 2 次元の形、位置、距離、方向 | 実際の座標に描いた図 |
| 3 次元の形、位置、向き | 要る面が見える向きの 3 次元の図と、測らせる平面の断面図 |
| 定義から結果を導く | 数式と、記号の対応を示した図 |
| 二つのものの違い | 対応する部分をそろえて並べた図や表 |
| 何がどこにあり、何とつながるか | 見取り図 |
| データから主張までの推論 | 処理の段ごとに入力と出力を示す図 |
| 多数の項目から必要なものを探す | 本文には概観を置き、全件は参照資料に置く |

形ごとの注意を次に示す。

- **量:** 面積、体積、色の濃さは、位置ほど正確には比べられない。量を正確に比べさせる箇所では使わない。
- **時間:** 縮尺の無いシーケンス図は、やり取りの順序しか示さない。周期、待ち時間、何かを読み落とす間隔が推論に関わる場合は、動き手ごとに横の帯を引き、実際の時間の縮尺でそろえる。桁の違う時間は、拡大図に分ける。桁の違う周期どうしを一つの図で比べる場合に限り対数の軸を使い、軸が対数であることを図に書く。
- **段階:** アニメーションは一度流れると見直せない。段階を見比べさせたい箇所では静止図を並べる。動かす場合も、止めて一段ずつ送れるようにする。
- **2 次元の形:** どの部分を使って何を計算するか（例: 曲線のどの点から点 P への最短距離をとるか）を、線、記号、寸法線で図に描き込む。
- **3 次元:** 自分で回せることより、推論に要る面が見えていることが理解を左右する。最初から、要る面が見える向きで表示する。回せるようにするのは、向きを変えて確かめることが理解を助ける場合でよい。透視図では距離や角度を正確に読めないので、測らせる距離や角度は、その平面の断面図に寸法線で示す。
- **式:** 図は形と位置をつかませ、式は厳密さと一般性を担う。両方を置く場合は、式の記号が図のどの部品に当たるかを、図の中か図のすぐ隣に書く。読者に記号と図の対応を探させない。
- **違い:** 同じ軸、同じ縮尺、同じ並び順にそろえ、違わない部分も同じ形で並べる。違う所だけが目に入るようにする。
- **データから主張まで:** 各段で何を数え、何を除き、何と何を比べたかを、入力と出力の数値で示す。別の説明の可能性と、それを退けた根拠も、該当する段に置く。コードや長い文の羅列で推論を示したことにしない。
- **操作できる図:** 条件を変えて関係を確かめることが理解を助ける箇所に使う。すべての章に置く必要はない。図を描く者は、操作の部品（スライダーや入力欄など）ごとに最小と最大の値にした状態と、図の説明で触れる値にした状態を作る JavaScript を、作業記録に残す。操作して読む図では、操作の順に並べる状態の列（一つの部品の値を小さい方から大きい方へ変えた状態など）も残す。手順 6 の確認で使う。

## 模型から描く

手順 2 で模型（入力から結果を計算するスクリプトやシミュレーション）を作った対象では、模型の出力から図の形と数値を作る。
座標や数値を手で置かない。

- 図と、図に添える数値は、同じ模型の出力を使う。同じ量を別々に計算しない。
- 図やシミュレーションは、本文と同じ条件と規則に従わせる。
- 説明のために仮の入力（実測ではない例の値）を使う場合も、模型にその入力を与えて図を作る。図の説明には、使った入力の値を、図に示した結果が成り立つ条件として書く。仮の入力から得た結果を、対象の実測値として書かない。

模型を作らない対象の図（構造の見取り図など）も、描いた部分とその関係を形の仮定に合わせる。対象と食い違う関係を、説明のために描かない。図の問いに要らない部分を省くのは図の観点の選択なので、図の説明に断り書きを書かない。

## 図と本文を対応させる

- 図は、それを説明する文のすぐ隣に置く。図と説明が離れていると、読者は両方を行き来しながら頭の中に保持しなければならない。
- 1 枚の図に、答える問いを 1 つ持たせる。全体の位置関係をつかむ図と、変化や導出を理解する図は分ける。問いと答えは「図の形を決める」の手順で作業記録に残し、手順 6 の図の読み取りで、確認者が読み取った問いと答えに照合する。
- 図の説明文（HTML では `figcaption`）には、何を見ればよいかを書く。図から読み取ることを本文と結び付ける。
- 名前は凡例より、線や点のすぐ横に書く。
- 写実的な絵より、推論に要る部分だけを描いた図を選ぶ。
- 飾りの図、本筋に要らない写真や逸話は入れない。本筋に要らない情報は理解を下げ、一度に保持できる情報の少ない読者ほど影響が大きい。
- 本文で色の名前を使って図の部分を指す場合は、その色が表示の設定（明るい表示と暗い表示など）によって変わらないようにする。

## ページを組む（HTML の場合）

- 本文の 1 行が長くなりすぎない幅にする。
- 狭い画面でも、ページ全体が横にはみ出さないようにする。幅の広い図、表、コードは、その要素の中で横に送れるようにする。
- 章ごとにページを分ける場合は、各ページに目次と前後の章へのリンクを置く。
- 演習の解答は、折りたたむか別の位置に置き、読者が先に考えられるようにする。

## 描く手段

対象と読む場所に合う手段を選ぶ。次は代表的な組み合わせである。

| 図 | 手段の例 |
|---|---|
| 2 次元の形、時間軸の図 | 模型のスクリプトから出力した SVG |
| データや計算結果のグラフ | matplotlib など |
| 3 次元の形、3 次元の空間での光線の経路 | Three.js など |
| 数式 | KaTeX、MathJax |
| 縮尺が意味を持たないつながりや順序 | Mermaid でもよい |

描いた図は、手順 6 の確認を終えるまで完成としない。
