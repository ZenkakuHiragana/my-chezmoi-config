# 本文の決まり

本文を書く者が、本文を書くときに読む決まり。

## 目的と原則

本文で述べる推論、前提、対象についての主張は、どれも、作業記録のその章の設計（節ごとの記録、導出の段、対応物の記録、図の計画）にあるものにする。書く段階で、設計に無い推論、前提、主張を足さない。

再構成した前提と関係と、そこから導く結果を結び付けて教える。

部品の構成や API などの一覧は、本文ではなく参照資料に置く。
対応物のある事柄は、独立した節を立てて一から説明し直さない。
確認用の例は、演習に使う場合を除いて、本文に載せない。

読者がすでに知っている事柄はひとまとまりとして扱えるが、知らない事柄は一つずつ保持しなければならない。そのため、同じ説明でも負荷の重さは読者の既有知識によって変わる。

結び付く先が頭に残っていない文に出会うと、読者は前を探し直すか推測で補うしかなく、理解の負荷が大きく増える。
対象をよく知る書き手ほど、読者が知っていることを多く見積もりやすい。

そのため、説明は、読者が別の章の内容を覚えていることに頼らない書き方にする。別の章で教えた事柄を言い直すのは、推論がその性質を前提にする箇所と、章の最初の段落でその章が必要になる場面を示す箇所に限る。
章を読み始める読者は、その章が前提にする章（スキルの手順（`SKILL.md`）の「章の順序と重みを決める」で決める。前提にする章がさらに前提にする章を含む）を読み終えており、章の中では先頭から順に読むものとする。
節は、章の直下の見出しで区切ったまとまりである。章の直下に見出しが無い章は、章全体を一つの節とする。
章の中で使う事柄（語、記号、図の部分と、それらが表す概念や性質、推論が前提にする事実）は、次のどれかに当たるようにする。

- その章の中で、使う箇所より前に説明している。
- 読者の既有知識の記録に、今の説明に使う性質まで含めてある。名前を知っているとだけ記録された事柄は、名前で指せることだけが記録にあるとみなす。記録が既有知識の範囲を文書で示している場合は、その文書に含まれる事柄が記録にあるとみなす。
- その章が前提にする章で教えた事柄である。名前や記号で指すだけの箇所では、教えた箇所と同じ名前や記号で使い、言い直さない。推論の前提にする箇所では、その推論に使う性質を一文で言い直し、教えた節の名前を示す。図の部分であれば、言い直す代わりに、その図を再び示してもよい。
- まだ教えていない事柄か、その章が前提にしない章で教える事柄であり、使う箇所で、そこで知っていれば足りることを述べ、教える節の名前を示している。ただし、学んだ知識から結果を導く過程を示す箇所と演習（「学んだ知識を結び付け、結果を導いて見せる」）では、この事柄を推論の前提に使わない。

推論の前提にする箇所とは、本文が「だから」「ため」などで結んだ推論か、作業記録の導出の段が、その事柄の性質を前提にする箇所である。

章の最初には、図、表、式、箇条書きより前に、文章の段落を置く。その最初の段落では、その章で説明することと、それが必要になる場面を示す。必要になる場面は、その章が前提にする章の内容か読者の既有知識から言い直して示す。
この段落は何の話をするのかを示すためのものであり、前提にする章の内容を復習する段落を別に置くことは求めない。
節の最初にも、図、表、式、箇条書きより前に文章の段落を置き、その節で説明することを示す。
以下、この二つの段落と上の四つをあわせて「章と節の書き方」と呼ぶ。

章と節の書き方は、読者が何を覚えているかを予測しなくても満たせる。
そのため、読者本人がいなくても、本文と、作業記録にある読者の既有知識の記録、前提にする章、導出の段だけから、満たしているかを確かめられる。

仕様や定義が、再構成した前提と関係のうちの前提に当たることも、具体的な結果が理解の入口になることもある。

既知の問いへの回答、API の一覧、資料の要約は材料として使えるが、それらを並べるだけで理解の道筋を作ったことにはしない。

この手順の段階の並びは、執筆の進め方であり、章の見出しの型にしない。

## 冒頭に置くもの

冒頭には、読み方の案内を置く。各章が何に答え、どの章を前提にし、どの順に読めるかを示す。読める順序が複数ある場合（入口の章から読む順と、入口の章を飛ばして読む順など）は、それぞれを示す。入口の章を飛ばして読む順を示すのは、後の章が入口の章を前提にしない場合に限る。
あわせて、本全体の枠（扱う対象、版や条件、主張が拠る資料）を示す。途中で枠を変える箇所では、変えることと新しい枠を、その箇所で述べる。
対象の仕組みの全体像を冒頭に示すことは必須にしない。示した全体像を後の章で推論の前提に使う場合は、使う箇所で必要な部分を言い直すか、図を再び示す。
まだ知らない細部を理解していなければ読めない概説にしない。
説明が進んだところで全体へ戻り、学んだことの位置付けを確かめてよい。

## 新しい知識の必要性と意味を伝える

新しい知識を導入するときは、それが何を理解するために必要なのか分かるようにする。
身近な例から始める、既知の考え方を拡張する、複数の事柄に共通する関係を示す、従来の理解では説明できない例を示すなど、話の筋に合う方法を選ぶ。
毎回、反例や驚きを作る必要はない。

読者の誤解を取り上げるのは、読者がその誤解を持っていることが、読者本人や依頼者の発言、記録、途中の評価で観測された場合に限る。「誤解しているかもしれない」という推測は、誰のものであっても観測に数えない。
観測されていない誤解を想定して持ち出し、否定する説明にはしない。読者は書かれたことには理由があると考えて読むため、持ち出された誤解から、ありもしない前提を読み取る。
考え方が分かれる所を示すときは、読者の頭の中を推測しなくても分かる、次の違いを使う。

- 本文がそれまでに説明した仕組みや規則が、成り立たなくなる条件
- 資料の中に実在する違い（規格の定義と実装の計算、二つの実装の計算方法など）。対応する部分をそろえて並べ、どこで分かれるかを示す。
- 本文が持ち込んだ類推が、成り立たなくなる所

用語は必要になる場所で意味を説明し、以後は同じ意味で使う。用語を教える節より前でその用語を使う場合は、「目的と原則」で述べた章と節の書き方に従う。
定義を置くだけでなく、何を表し、他の知識とどう関係し、そこから何が分かるかを説明する。

用語の名前と、用語の意味の説明は分けて扱う。
用語の名前には、その分野の日本語の文書（根拠にした資料の日本語版、公式の日本語の文書、解説記事など）で使われている表記（カタカナ語など）を使う。表記が複数あれば、根拠にした資料の日本語版と公式の日本語の文書の表記を優先する。日本語の文書で使われている表記が無ければ、根拠にした資料が使う名前（原語など）をそのまま使う。
日本語の文書の表記を使う場合は、用語を導入する箇所で、根拠にした資料が使う名前も示す。
本の中だけで通じる訳語や言い換えを、用語の名前として作らない。読者は本を読んだ後、資料、コード、他の人の説明でその名前に出会い、本で学んだことと結び付けるからである。
用語の意味は、平易な語で説明する。
専門分野で定着した記号と図示の慣習も尊重する。

「なぜ」は、前提と関係から結果へ至る筋道として説明する。
定義や取り決めそのものと、そこから導ける性質を区別する。
作り手の意図を述べる場合は根拠を確かめ、記録がなければ創作しない。
意図が不明であることを、仕組みの説明を省く理由にしない。

式を使う場合は、記号の意味を示し、何を表す式なのかを説明する。単位を持つ量は単位も示す。
変形や計算では、その操作によって何を明らかにしようとしているかを伝える。
コードや表を掲載するだけで説明を代用しない。

重要な仕組みには、理解に必要な詳しさを確保する。
長くなる場合は意味のまとまりに沿って分け、必要に応じて途中で整理する。
短くするために前提や関係を削らず、詳しくするために同じ説明や本筋に要らない細部を増やさない。

見出しは、章、節、それより下の階層のどれでも、その箇所で扱う話題で示し、その時点の読者に何を学ぶ箇所か分かるものにする。
結論の命題を見出しにしない。見出しだけを拾って読む読者に、理由をたどる前の答えだけを渡すことになるからである。
未説明の概念を含む結論だけを渡し、理解したつもりで先へ進ませない。
結論を本文の先に示すのは、読者がその時点までの知識で結論の意味を理解できる場合に限る。

理由や因果のつながりは、箇条書きに切り分けず、主語、条件、理由、結論を文と接続表現で結ぶ。箇条書きは、個別に拾う同格の項目に使い、各項目を独立に拾えるようにする。

## 学んだ知識を結び付け、結果を導いて見せる

学んだ知識を使って、具体的な結果が得られる過程を示す。
何を前提に、どの関係を使い、その結果から何が分かるのかを読者が追えるようにする。

説明の順序と表現は対象に合わせる。
動作を理解するなら時間順に追う方法があり、数学なら仮定から結論への論証、幾何なら条件と形の関係を示す方法がある。
これらは選択肢であって、すべての教材に要求する項目ではない。

対象が分析である場合は、データの出どころとそれが直接または間接に観測しているもの、処理の各段の入力と出力、処理の結果から主張へ進む推論、別の説明の可能性とそれを退けた根拠を、段ごとに示す。

既習事項の応用として示す箇所で、未説明の知識を使わない。
新しい知識を教える段階へ進む場合は、既習事項だけで導ける部分との境目を明らかにする。

一つの例だけで、条件が変わっても同じ結果になるように見える場合は、条件を変えた例や比較を示し、何が共通し、何が変わるかを説明する。
比較対象を本筋と同じ詳しさで扱う必要はない。

到達点が、読者が本を読み終えた後に対象について自分で行うこと（本文に無い場面で結果を導く、実装する、保守する、誤りを見つける、判断するなど）を求める場合は、読者がそれを試す演習を置く。到達点が求めることが複数あれば、それぞれについて置く。
演習の形は、到達点に書いたことと同じ形にする。たとえば、ライブラリの保守が到達点なら、機能を実装する課題や、誤りを含むコードから誤りを見つける課題にする。本文の答えを探せば済む演習にしない。
到達点がそうしたことを求めない場合（用語や結果を思い出せること、仕組みを説明できることだけを求める場合など）は、演習を置かない。
解答を付ける演習では、解答に導く筋道を示し、解答を折りたたむか別の位置に置いて、読者が先に考えられるようにする。

## 表現と参照資料

本文は、理解を積み上げるための読み物にする。
必要な前提と関係は読み進める道筋に置く。
網羅的な一覧、長い抜粋、検証記録などは、必要なときに引ける参照資料へ分ける。
本文には対象についての説明を書き、根拠に支えられた主張だけを置く。
根拠の届かない主張を、但し書き（確かめていない、仮定である、単純化した、など）を添えて置くこともしない。但し書きを添えても根拠の無い主張であることは変わらず、根拠のある主張と同じ本に並べると、本全体の主張の確かさがそろわなくなるからである。
書き手が本を作るために行ったこと（資料や実装と照合したこと、模型の値が一致したこと、確認を通ったことなど）は、対象についての説明ではないので本文に書かない。検証の経過と結果を読者に渡す必要があれば、参照資料に置く。
冒頭の本全体の枠では、主張が拠る資料（規格、実装、実装を実行した結果など）を示す。照合の結果（一致したことなど）は、そこにも書かない。
一方、主張や式が成り立つ条件と、資料や分析で確かめた対象の性質（本が説明する規格がその場合を定めていない、実装が近似式で求める、分析するデータでは二つの原因を区別できない、など）は、対象についての説明なので本文に書く。書いてよいかは、その文が対象について述べているか、書き手の作業や根拠について述べているかで見分ける。
ただし、主張や式が成り立つ条件と例外は、対象の性質として述べられるものも含め、節ごとの記録に記録したものだけを本文に書く。記録に無いものは本文に書かず、参照資料に置くか、載せない。「冒頭に置くもの」が定める本全体の枠と途中で変える枠、表現の資料（`references/representation.md`）の「模型から描く」が定める図の説明の入力の値のように、ほかの規則が置くことを求めている記述は、その規則に従う。
根拠にした資料に何が載っていないか、根拠では何が確かめられないかを述べる文は、出典のある事実の形をしていても、書き手の根拠の状態を述べるもので、但し書きと同じく本文に書かない。ただし、その資料が本全体の枠の扱う対象に含まれる場合（分析するデータ、本が説明する規格や実装など）は、その資料についての文は対象についての説明である。
対象が分析である場合、データの処理、処理の結果から主張へ進む推論、別の説明を退けた根拠は説明の対象であり、ここでいう検証の経過には当たらない。
本文に置くか参照資料に置くか迷う内容は、読者が作業の最中に引くものか、作業から離れて理解するために読むものかで分け、前者を参照資料に置く。
本文を理解するために不可欠な説明まで付録へ追い出さない。

媒体の決め方、表現の選び方、図の形、模型からの描き方、図と本文の対応、ページの組み方、描く手段は、表現の資料（`references/representation.md`）に従う。

本文の各主張には、根拠の具体的な箇所を指す短い参照番号を付ける。
番号に対応する注を章末に置き、資料名と、URL やパス、版、節・ページ・行・関数などの根拠箇所を特定する情報を書く。出典の所在としてのこれらの情報は、本文の括弧内などに列挙しない。
参照番号は支える文の末尾に置く。同じ資料の同じ箇所が段落の全主張を支えるときは、段落末にまとめる。根拠箇所が変わる文では番号を分ける。一文が複数の根拠に拠る場合は、対応する番号を併記する。
図表の参照番号は説明文の末尾に置く。図表内で根拠箇所が異なる部分には、その部分に番号を置く。
根拠から導いた主張では、資料が支える前提と、そこからの導出を区別して説明する。
説明の対象となるファイル名・API 名、本文に書く成立条件、引用文やコードそのものを読む箇所の抜粋は、本文に残す。
読む場所で使える記法で番号と注を対応させ、リンクできる媒体では番号から注へリンクする。脚注機能が使える媒体では、章末の注を脚注にしてよい。
