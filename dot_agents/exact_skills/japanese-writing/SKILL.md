# 日本語で情報を伝える

文章表現は情報伝達の一形態である。書き手は、必要な意味を保ったまま、読者が情報を受け取るためのコストと摩擦、認知負荷を最小化する表現を選ぶ。短くすること自体ではなく、読者が目的を果たすまでの負担を小さくすることを目指す。

## 読者に何を渡すか

依頼と対象から、誰が何のために読む文章なのかを捉える。仕組みを理解したい読者には関係の説明が要り、項目を調べたい読者には探せる構造が要る。同じ情報でも、利用の仕方によって配置と形式を変える。

読者の出発点は、その文章を受け取る時点で持つ知識と、そこから通常の経路で得られる情報である。書き手が知る会話や編集の経緯を、そのまま読者の前提にしない。会話への返答では会話の文脈を使い、独立した文書では文書の読者に必要な前提を本文に置く。

伝える内容が決まったら、その中の主題を定める。理解に必要な前提から新しい情報へ進み、主張には理由を、操作には必要な条件を結び付ける。読者が必要とする位置に短い説明を置くことで読み戻りを減らせるなら、文字数だけを理由に省かない。

## 情報の関係に形式を合わせる

生成物で利用できる形式から、読者の目的に合うものを選ぶ。一つの形式で文書全体をそろえる必要はない。

| 読者が扱う情報 | 表現の選び方 |
| --- | --- |
| 理由や因果をたどる説明 | 文で関係を明示し、一つの主題を段落としてまとめる |
| 必要な節を探す長い説明 | 内容が分かる見出しで区切り、包含関係を階層で示す |
| 個別に拾う同格の項目 | 箇条書きにする。短く、その場で一括して読めるなら文中に収めてもよい |
| 順番に行う操作 | 番号付きの手順にし、前後関係を見せる |
| 共通の軸で比べる対象 | 軸を見出しにした表で、値と対象を対応付ける |
| 文章だけでは追いにくい関係 | 図で関係を示し、読み取る要点を本文で説明する |
| 正確な文字列を使う操作 | コード表記やコードブロックで説明文と区別する |

形式は意味関係を省略してよい箇所を作る。列挙が成り立つのは、項目が共通の役割で並び、その集合を示すことに意味があるときである。因果や役割の違いが重要なら、関連する名詞を並べる代わりに、その関係を述べる。箇条書きへ改行するだけでは、失われた関係は戻らない。

表は同じ比較軸を繰り返し読む負担を減らせるが、長文をセルに押し込むと読みにくくなる。短い説明は文のままでよい。見出しは節の主題を示すために使い、各文を見出し付きの断片にしない。

## 文法を使って意味を表す

何がどうするのかを述語で組み立て、その述語に対する名詞の役割を助詞で示す。修飾先が読み取れる語順を選び、語の関係を名詞の連結だけに任せない。主体が文脈から定まる間は省略できる。主体が変わるところでは、読者が前の主体を補い続けないように示す。

文法形式を変えると、出来事だけでなく、その捉え方も変わる。対象を中心に述べる受身を、機械的に能動へ直さない。進行と完了を混同せず、否定や限定が及ぶ範囲を保つ。推量を断定へ、許可を義務へ変えれば、簡潔になっても同じ内容ではない。

節をつなぐときは、前後の関係を表す接続を選ぶ。時間的に続いたことと、原因になったことを区別する。条件を言い換える際も、前提と出来事の順序を保つ。使い分けの詳細は [文法と意味](references/grammar.md) を参照する。

## 語を選ぶ

伝えたい意味に合い、読者が直接理解できる語を選ぶ。同義に見える語でも、指す対象や要求の強さが変わるなら置き換えない。同じ概念には一貫した呼び方を使い、別の概念を同じ語へまとめない。

平易で定着した日本語表記がある一般語は、日本語で書く。「ファイル」のように定着したカタカナも日本語表記である。操作や照合に必要な識別子、正式名称、引用は原表記を保つ。専門語を言い換えると精度が落ちる場合は、その語を残し、読者に必要な説明を添える。

未知の用語は、この位置で何を指すか分かるように導入する。仕組みの説明では役割から入ると理解を助けられる。名前を調べる参照資料では、名前から説明へ進む方が探しやすい。どちらの順序も、読者が概念の意味を保留したまま進まずに済むように使う。

語義や慣用に疑いがあれば、[資料の使い分け](references/sources.md) に従って辞書や用例へ戻る。なじみのなさだけで誤用と決めず、表す意味と使われる場面を分けて考える。

## 補足と対比を置く

本文には主題を理解するための情報を置く。括弧や注記には、その位置で解釈を助ける補足を置く。判断に不可欠な条件は本文へ組み込み、本文を言い直すだけの補足は加えない。例は抽象的な内容を具体化するために添え、例示と対象の全範囲を区別する。

否定は不成立や禁止そのものを伝えられる。対比は、候補の違いが読者の理解や選択を変えるときに使う。書き手だけが知る却下案を持ち出す必要はない。編集指示への応答を本文へ混ぜず、読者が今回知るべき内容を述べる。

参照は、読者が必要な情報へ進む道として置く。リンク先で何が分かるかを示し、現在の説明に必要な接続まで参照先へ追いやらない。強調は、読み落とされると理解や行動が変わる箇所を目立たせるために使う。

## 文体と媒体に合わせる

説明の正確さを保ちながら、読者との関係と場面に合う文体を選ぶ。丁寧さを増すことと、敬語が正しく成立することは別である。本文の文体は一貫させ、引用や画面上の固定文言は原文を保つ。

技術文書を書く場合は [技術文書の構成](references/technical-writing.md) を読む。文書を生成する場合は [媒体に合わせた表現](references/document-production.md) を読み、表示できる構造に合わせて書く。表現を残す場合と変える場合の違いは [使い分けの例](references/examples.md) に示す。
