# 技術文章の設計

技術文書を作成・修正する書き手は、読者が対象を理解し、必要な判断や操作を行う順序で構成する。ここでは文書の種類に応じた情報配置を扱う。

## 文章種別ごとの中心

書き手は、文章の用途に従って中心に置く情報を選ぶ。複数の用途を扱う文書では、見出しや接続文で役割の切り替わりを示す。

| 種類 | 読者に伝える中心 | 構成するときの着眼点 |
| --- | --- | --- |
| 仕様 | 条件に対してどの結果が成立するか | 適用対象と条件を示し、通常の結果と例外を対応付ける |
| 手順 | 何をどの順に行い、どう成功を確認するか | 開始条件から操作、分岐、結果の確認へ進む |
| 説明 | 概念が何を担い、ほかの概念とどう関わるか | 理解に必要な定義から中心の仕組み、具体例へ進む |
| 設計 | 何を実現し、どの責務と関係で成立させるか | 確定した判断とその理由を示し、境界と制約を説明する |
| 参照資料 | 目的の項目を引き、値や意味を確定すること | 読者が探す名前と共通の項目構成を使う |
| 報告 | 何を観測し、そこからどこまで結論できるか | 結果と根拠を結び、条件と限界を明示する |

## 説明の粒度と順序

書き手は、中心となる動作や関係を先に説明し、その理解を使って詳細や例外を説明する。概要には、最初の理解を支える情報を置く。後の操作や判断で使わない内部名を、詳しく見せるために導入しない。

仕組みを説明する書き手は、実際に何が何へ作用するかを書く。処理の順序とデータの関係を同じ一覧に押し込まない。文章だけでは追いにくい関係には図を使ってよいが、図の名前や記号も本文と同じ意味で使う。

## 指示文・プロンプト

指示文を書く書き手は、実行者が読む順に構成する。役割と使用条件を示し、入力から操作、結果の確認へつなぐ。使用しない条件、禁止事項、停止条件は、その判断が必要になる操作と対応付ける。

書き手は、誰が条件を判定し、誰が何を行うかを明記する。別の主体へ情報を渡す指示では、渡す人、受け取る人、渡す内容、その後の利用を区別する。実行主体ではないスキル名や文書名を、人のような判断主体にしない。

書き手は、完了時に実行者が出力する内容と、その確認方法を示す。能力固有の説明へ、その能力の意味を成立させない運用手順を加えない。既存の手順を文章化する場合は、書式の項目を埋めるために新しい入力や停止条件を作らない。

## 固定文字列と説明文

書き手は、操作・照合される名前、キー、値、コード、テンプレートの原表記を保つ。説明文は日本語で書き、固定文字列が何を指すかを初出時に示す。

書き手は、例示用の値とそのまま入力する値を区別する。文書内の名称が実物の名称と一致し、説明の参照先から対象を特定できるかを確かめる。命令例を読みやすくするために、動作を変える文字や空白を変更しない。
