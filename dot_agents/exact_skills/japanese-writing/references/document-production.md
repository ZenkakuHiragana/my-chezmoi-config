# 媒体に合わせた表現

文書を生成するときは、読者が利用する形式で意味の伝わる記法と配置を選ぶ。同じ内容でも、画面幅やページ分割、利用できる文書構造によって適する表現は変わる。

## 構造を記法へ写す

見出しには、対象の形式で見出しを表す記法を使う。太字にするだけでは、目次や見出し移動に使える構造にならない場合がある。見出しの階層は内容の包含関係に合わせる。

箇条書きには項目の区切りを、手順には順序を表す記法を使う。項目内の補足は、その項目に属することが分かるように配置する。番号そのものを参照する文書では、読者が番号と対象を対応付けられる表現を選ぶ。

表では、各セルがどの行・列の見出しに対応するかを明らかにする。狭い画面で長文の列が並ぶなら、表を分けるか、項目ごとの説明にする。表は比較のために使い、文字を左右へ置くためだけの枠にしない。

## 図と補足を読む順に置く

図は、本文だけでは把握しにくい関係を示す場所に置く。表題と本文で図の主題を示し、線や記号の意味が必要なら説明する。色や形だけに重要な違いを負わせず、文字でも区別を伝える。数値を示す図では軸や単位を明示する。

例や注記は、説明対象との関係が分かる位置に置く。操作前に必要な条件を、離れた脚注へ追いやらない。短い補足は括弧に収められるが、主題の理解に必要な長い説明は本文として扱う。

リンクには目的が伝わる文字列を使う。現在の文の理解に必要な説明は本文に残し、詳しい情報へ進むために参照を使う。

## Markdown の強調境界

日本語の本文で `**` による太字や `*` による斜体を使い、前後の文字が ASCII 文字でない場合は、表示事故を避ける執筆上の方針として、構文の外側を ASCII 空白で区切る。行頭・行末には区切る相手がいないため、追加の空白は要らない。

```markdown
設定を **保存する** と反映される。
これは **重要な条件。** 次の操作より前に満たす。
用語を *強調する* 場合も外側を区切る。
```

句点を強調範囲に含める場合も、句点と閉じる `**` の間へ空白を入れない。空白は強調構文の外側へ置く。

この空白方針は、日本語に隣接する強調が必ず不成立になるという意味ではない。CommonMark では、区切りの内外にある空白や句読点の位置関係が強調の成立に関わる。特に強調の内側が括弧などの記号で始まる場合は、外側との境界が重要になる。記法の詳細は [CommonMark 0.31.2 の強調規則](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis) による。

## 固定文字列とページ構成

長いパスやコードは、読者が全文を取得できる配置にする。意味を変える空白や改行を文字列へ加えるのではなく、表示幅やブロックの配置で扱う。本文から文字列をコピーする用途があるなら、説明や行番号と混ざらない形にする。

PDF やスライドでは、ページ内で必要な関係を読めるように置く。表の見出しだけが前のページに残る配置や、説明対象から離れた注記は避ける。内容を収めるために文字を小さくし続けるのではなく、主題に沿って分割する。表紙から各節へ進む順序と、見出し番号が示す構造を一致させる。

## 根拠資料

- [文化庁「公用文作成の考え方」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93651301_01.pdf): 読み手に合う媒体、見出し、図表、注記の使い方。
- [W3C WAI の表の手引](https://www.w3.org/WAI/tutorials/tables/): 行列の論理関係と、見出しに対応するセルの構造。
- [W3C WAI の見出しの手引](https://www.w3.org/WAI/tutorials/page-structure/headings/): 見出しが伝える文書構造。

ウェブ固有の実装を、PDF や Markdown へそのまま移すものではない。対象の形式で表せる範囲で、同じ意味関係を読者に届ける。
