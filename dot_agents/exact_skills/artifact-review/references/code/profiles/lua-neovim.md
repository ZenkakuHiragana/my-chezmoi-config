# Lua + Neovim レビュー用プロファイル

Neovim の Lua 設定やプラグインについて、読み込み順とエディターの状態に照らして動作を確認する。
Lua 言語自体の意味は「Lua レビュー用プロファイル」（`references/code/profiles/lua-generic.md`）でも確認する。

## 起動と適用範囲

対象が個人設定なのか、他の利用者へ提供するプラグインなのかを確認する。
対応する Neovim の版と実際のプラグイン構成を調べ、その環境で利用できる API を使っているかを確かめる。
対象に必要のない旧版対応を、一般的な互換性として追加させない。

起動処理から機能を使う場面までをたどり、モジュールの読み込みと初期化が先に行われるかを確認する。
遅延読み込みでは、読み込みを起こす条件と、その機能を使う条件を照合する。
モジュールが読み込み済みであることと、必要な設定を適用済みであることを同一視しない。

設定値やキーマップは、意図する対象へ作用するかを調べる。
現在のバッファーへ設定する場合と、後で作るバッファーの既定値を変える場合を区別する。
バッファーやウィンドウに固有の変更が、グローバルな設定によって他へ広がらないかを見る。
有効範囲は API とオプションごとに確認し、すべてに同じ指定方法があるとは扱わない。

## 登録と解除

autocmd やキーマップの登録では、実行するたびに追加するものと、既存の定義を置き換えるものを区別する。
設定の再適用やバッファーへの再接続が想定される場合は、通知が重複したり、不要になった処理が残ったりしないかを調べる。
再読み込みを繰り返せること自体は、すべてのプラグインへ一律に要求しない。

autocmd グループを消去する処理では、そのグループに含まれる登録を確認する。
あるバッファーの設定を更新するために、別のバッファーで必要な登録まで消していないかを調べる。
解除や上書きについても、自分が管理する登録と、利用者や他のプラグインの設定を区別する。

終了後に残るタイマーや購読は、停止と後始末を確認する。
モジュールのキャッシュを消して再実行するだけでは、以前の実行が登録した処理まで解除されたことにならない。
公開するコマンド名と文書化された操作も、登録内容に一致するかを確かめる。

## コールバックが動く時点の状態

コールバックでは、発生したイベントの対象と、実行時に現在選択されている対象を区別する。
別のバッファーへ切り替えた後も、意図したバッファーやウィンドウへ操作しているかを確認する。

タイマーなどからエディターの API を呼ぶ場合は、その呼び出し元で操作が許されるかを仕様に照らす。
実行を予約して後へ回す必要がある場合も、予約した時点の状態が実行時まで保たれるとは判断しない。
すべてのコールバックを機械的に遅延させず、操作に必要な実行条件を確かめる。

非同期の結果を適用する場合は、対象がまだ存在するかに加え、結果を求めた時点から内容や依頼が変わっていないかを確認する。
対象が有効でも、古い結果で新しい編集を上書きする可能性は残る。遅れて返った結果を適用してよい条件を調べる。

文字位置を扱う API は、行番号の起点、終端を含むかどうか、列の単位を確認する。
バイト位置と文字数、画面上の幅を取り違えていないかを、複数バイトの文字やタブを含む対象で確かめる。
似た API の座標規則を推測で流用しない。

## Neovim 上での検査

既存のテストやヘルスチェックを使い、対象の設定が読み込まれた Neovim で、実際の利用場面を確認する。
対象となる複数のバッファーや再接続によって結果が変わる処理は、その条件まで検査する。

検査用の設定変更や登録の解除は、許可された対象に限る。
表示や操作感を確認していない場合は、ヘッドレス実行の成功と区別する。
指摘には、問題を起こすイベントと対象の状態、影響する設定や処理を示す。
