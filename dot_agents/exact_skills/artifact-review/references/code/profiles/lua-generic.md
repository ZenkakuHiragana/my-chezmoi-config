# Lua レビュー用プロファイル

Lua の値とテーブル、関数呼び出しの意味を、実際の実行環境に照らして確認する。
言語として許される書き方でも、共有状態や戻り値の扱いによって利用側の期待が崩れないかを調べる。

## 実行環境とモジュール

使用する Lua の版と実装を確認する。LuaJIT やアプリケーションへ組み込まれた Lua では、対応する言語機能と提供される API をその環境の仕様から確かめる。
別の版の構文やライブラリー機能を、そのまま利用できる前提にしない。

変数の読み書きでは、局所変数か、共有する環境の値かを確認する。
意図しないグローバルへの代入と、組み込み先が提供する正当なグローバル API を区別する。
モジュールを読み込む順序やキャッシュによって、初期化が一度しか行われない箇所と、呼び出すたびに行う箇所も調べる。

モジュールが返すテーブルは、どの利用者が同じものを共有するかを確かめる。
設定やテストで書き換えた値が、後の呼び出しにも残らないかを確認する。

## テーブルと条件判断

テーブルを配列として使う場合は、要素の数と終端をどう表しているかを確認する。
`#` が要素の総数を返すとは限らず、途中に nil がある列で期待する長さを得られるかは別に調べる。
`ipairs` の停止位置や `pairs` の順序へ依存する処理も、実際のデータ構造と照合する。

キーへ nil を代入することと、そのキーに false を保存することを区別する。
Lua では nil と false だけが偽として扱われるため、0 や空文字列を未指定とみなす条件になっていないかを確認する。
`value or default` は有効な false も既定値へ変えるので、未指定と無効化を区別する設定では結果を確かめる。

テーブルの代入や引数渡しは、独立した複製を作るものではない。
別名で同じテーブルを更新する経路と、入れ子のテーブルを共有したままの浅いコピーを調べる。
深いコピーへ変える場合も、共有すること自体が必要な関係まで壊さないかを見る。

## 関数呼び出しと暗黙の処理

複数の戻り値を扱う箇所では、関数呼び出しが式のどこに置かれるかを確認する。
`return f()` と `return (f())` のように、括弧や配置によって引き継ぐ戻り値の数が変わる箇所を調べる。
途中の nil を含む結果をテーブルへ収める場合は、必要な個数を後から復元できるかも確かめる。

メソッドの呼び出しでは、コロン形式が渡す `self` と、関数側の引数を照合する。
コールバックとして関数だけを渡す場合も、必要な受け手が失われていないかを見る。
クロージャーは、作成時に使った値だけでなく、呼び出す時点で参照する変数の値を確認する。

メタテーブルを使う処理は、読み書きや比較によって呼ばれる処理までたどる。
見た目は単純な参照でも、副作用や失敗が起きる条件を調べる。
生のテーブル操作でその処理を迂回する箇所も、保つべき条件と照合する。

`pcall` や `xpcall` では、保護した呼び出しがエラーを投げなかったことと、その関数の戻り値が示す成否を区別する。
戻り値として失敗を返す関数を呼んで、保護呼び出しの成功フラグだけで成功と判断していないかを確認する。

## 費用と検査

繰り返しの中で作るテーブルや文字列は、作り直す必要と回数を調べる。
共有して再利用すれば速い場合も、その更新が他の呼び出しや保持中の値へ漏れないかを確かめる。
名前を文字列で振り分ける処理では、登録する側と利用する側の対応が、追加や改名後も保たれるかを見る。

検査には既存の静的解析とテストを使い、組み込み先の API が関わる部分は、その実行環境で確認する。
テストの代替 API が都合のよい値だけを返していないかを調べる。
問題を指摘するときは、実際の値や呼び出し順から何が変わるかを示し、環境を確認できない部分は分けて返す。
