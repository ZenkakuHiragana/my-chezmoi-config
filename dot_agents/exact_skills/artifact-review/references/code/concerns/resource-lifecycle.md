# 資源寿命

取得した資源を必要な間だけ有効に使い、役目を終えたときに後始末できるかを確認する。
資源には、メモリだけでなく、明示的に閉じたり解除したりする接続や購読も含む。

## 取得から解放まで

資源を取得する処理から、保持する主体と解放する処理をたどる。
所有して後始末する側と、一時的に借りて使う側を区別し、引き渡しによって責任が消えたり重複したりしないかを調べる。

同じ資源の解放処理へ複数回到達する経路では、その時点の資源の状態と、解放 API が許す呼び出し条件を確かめる。
繰り返しを許す API の再呼び出しと、解放済みの資源を再び解放する誤りを区別する。

参照を外へ返す場合は、その参照を使い終わるまで元の資源が有効かを確認する。
非同期処理へ渡した値も、実際の完了まで追う。
共有するバッファを先に再利用した結果、まだ利用中の内容を上書きしないかを確かめる。

解放が言語や基盤の仕組みによって保証される場合は、その保証が及ぶ範囲を確認する。
保証の外で手動管理している部分では、取得と解放の対応を各呼び出し側の注意だけに任せていないかを調べる。

## 途中で処理が終わる場合

取得途中に失敗しても早期終了しても取得済みの資源が後始末されるかを確認する。
未取得の資源を解放したり、解放済みの資源を再び使ったりしないかを調べる。
後始末自体が失敗する場合は、残る資源と、その失敗を扱う処理を確認する。

終了や再読み込みでは、前の実行が作った登録や処理が残らないかを確かめる。
例えば通知の購読が残れば、新しい実行と重複して呼び出されたり、不要になった値を保持し続けたりする。
メモリが自動回収されることだけで、これらの後始末まで済むとは判断しない。

一時的に共有状態を切り替える処理では、元へ戻す条件と復元する値を確認する。
入れ子の呼び出しや途中終了でも、外側の処理が使う状態を壊さないかを調べる。

## 長く保持する資源

キャッシュやプールは、保持する期間と量を実際の用途に照らす。
無効になった資源の再利用、参照されなくなった値の滞留、異なる実行による一時ファイルの衝突を調べる。

長く保持すること自体を問題にせず、どの条件で無効な利用や容量不足が起きるかを示す。
管理の仕組みが読めない場合は、その不足を特定し、存在しない後始末を補って安全としない。
