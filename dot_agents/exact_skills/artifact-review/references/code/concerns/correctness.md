# 正しさ

呼び出し元が受け取る結果と、処理によって変わる状態を調べ、対象の仕様が約束する動作になっているかを確認する。
変更差分をレビューする場合は、変更された経路と、その影響を受ける既存の経路を比較する。

## 入力から結果まで

対象を呼び出す箇所を読み、渡される値と、呼び出す前に成立している条件を確かめる。
その条件を使って処理をたどり、戻り値だけでなく、保存や通知など外部への作用まで確認する。
関数内の計算が正しくても、利用側が異なる意味で結果を扱っていれば、その食い違いを調べる。

条件分岐では、どの入力や状態が結果を変えるかを確認する。
件数を条件にしていれば空の場合と境界値を、順序に意味があれば順不同や重複の扱いを調べる。
境界条件は、仕様と処理の分岐から選ぶ。
呼び出し側の保証によって起こらない状態と、単に普段は起きていない状態を区別する。

値の変換では、必要な情報が変換後にも残るかを確かめる。
例えば、丸めが比較結果を変えたり、欠落値を既定値へ変えたことで未指定と明示指定を区別できなくなったりしないかを調べる。
違いが結果に影響する箇所で、単位や文字の解釈を利用側まで照合する。

参照される処理は、使用時点で意図した定義へつながるかを確認する。
動的に登録する処理や生成されるコードでは、名前の一致だけでなく、読み込みや登録が先に行われるかを調べる。
変更された分岐から到達する共通の後続処理も検査する。

## 失敗と再実行

途中で失敗する箇所ごとに、既に行った変更と、呼び出し元へ伝える結果を確認する。
一連の操作を不可分に扱う仕様なら、一部だけ成功した状態が残ったり、途中の値を他の処理へ見せたりしないかを調べる。
部分成功が許される場合は、完了した範囲を利用側が区別できるかを確かめる。

例外の捕捉や代替値の返却は、失敗を成功に見せていないかを確認する。
回復を担当する処理へ必要な原因が届き、回復後にも約束した結果を満たすかを調べる。

再試行を選ぶ箇所では、失敗原因と適用される仕様に照らし、再試行する条件と失敗を返す条件を確認する。
前提を変えなければ回復しない失敗を繰り返したり、再試行が求められる失敗を取り違えて打ち切ったりしていないかを調べる。

再実行される操作では、前の実行がどこまで進んだかを確認する。
応答が届かなかった場合も、外部への作用は既に完了している可能性がある。
同じ依頼をやり直したときに作用が重複しないか、途中から続けたときに処理が抜けないかを確かめる。

指摘には、問題を生む入力や状態と、処理をたどった結果が仕様からどう外れるかを示す。
コメントやテストとの一致だけで正しいとせず、それらの期待も仕様に照らす。
