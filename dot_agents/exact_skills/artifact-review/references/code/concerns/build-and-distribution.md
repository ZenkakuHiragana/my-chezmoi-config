# ビルドと配布

必要な原本から成果物を作り、想定する利用環境で使える形として届けられるかを確認する。

## 原本から出力まで

ソースと設定が、生成やビルドを経て、どの出力へ入るかをたどる。
追加したファイルが取り込まれず、削除した機能が古い生成物に残るなど、原本と出力の食い違いを調べる。

生成物を使う処理では、必要な入力が変わったときに出力を更新できるかを確かめる。
依存する処理の順序が明確で、並列実行でも未生成や更新途中のファイルを使わないかを確認する。
前回の出力が残っている場合だけ成功する構造にも注意する。

ビルドに使う道具と依存を確認し、特定の開発者の環境にしかないものへ依存していないかを調べる。
対象の環境ごとの設定が、実際に生成するコードや取り込む資源へ反映されるかを見る。
設定ファイルの構文が正しくても、意図した対象に作用しているとは限らない。

再現性が必要な場合は、ソース以外の入力も含め、何が成果物の内容を決めるかを調べる。
同じ機能を再構築できることと、同じバイト列を生成できることを区別し、対象が求める水準に照らして確認する。

## 配布されたものの利用

実際の配布物を調べ、起動と動作に必要なコードや資源が含まれるかを確認する。
開発用の探索先に依存していたり、対象環境では存在しない道具を呼び出したりしないかを調べる。
不要な秘密情報が配布物へ混入していないかも確かめる。

検査の対象がソースから起動したものか、梱包した配布物かを区別する。
前者のテストが通っただけで、利用者が受け取るものも動くとは判断しない。

配置が途中で失敗する場合は、利用側から見える状態を確認する。
古いファイルと新しいファイルが混ざった状態で動き始めたり、再配置しても必要な更新が行われなかったりしないかを調べる。
切り戻しが必要な場合は、既に変わったデータも含めて扱えるかを確かめる。

指摘では、原本から利用までのどこで必要な内容が失われ、どの環境で問題になるかを示す。
実行していない構成について、他の構成の成功をそのまま保証に使わない。
