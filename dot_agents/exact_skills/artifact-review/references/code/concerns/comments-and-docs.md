# コメントと文書

コードを使う人と保守する人に必要な説明があり、その内容が実装と対応しているかを確認する。
文章そのものの品質と文中の論理的整合性は「文書レビュー」（`references/documents/review.md`）で扱う。

## 説明する内容の正確さ

利用者向けの説明を、実際の呼び出し方と結果に照らす。
使える条件、失敗時の扱い、外部への作用が、コードと同じ意味になっているかを調べる。
存在しない機能や古い設定を説明したままになっていないかも確認する。

保守用のコメントでは、コードだけからは分かりにくい理由や、変更時に守る条件を確認する。
外部仕様による制限や、単純に見える書き換えが不適切になる理由が抜けていないかを見る。
複雑な計算を理解するための説明も、その利用に必要なら役割を持つ。

## 読者が必要な場所で使えるか

実装を使う場面と変更する箇所から、必要な説明がどこに置かれているかを確認する。
公開する契約が内部コメントにしかなかったり、局所的な注意が離れた資料にしかなかったりする場合は、そのために何を見落とすかを調べる。

コメントが長い箇所では、説明の不足だけでなく、名前や構成が意味を隠していないかも確認する。
実装の問題を説明で正当化していないかを見る。

## 更新して保つ内容

実装の変更によって、どのコメントや関連文書の記述が古くなるかをたどる。
利用者が行う作業の変化が説明へ反映されているかを確認する。
移行や復旧が必要な変更では、その手順と制限も実態に合うかを確かめる。
