# 指示レビュー

レビュー担当者は、スキル本文、システムプロンプト、AGENTS.md その他の指示として使われる文書について、用途・目的に対する内容の妥当性と、想定する実行者が指示を実行できるかを検査する。

レビュー担当者は文書レビューも併用する。検査観点が指定されていない場合は、以下の７観点をすべて検査対象にする。

## 記述の役割と検査の適用

レビュー担当者は、文書全体の用途と、個々の記述が担う役割を区別する。目的の説明、背景知識、構成や参照先の案内、行動要求が同じ文書にあっても、すべてを命令として解釈しない。

レビュー担当者は、文書全体には用途に必要な情報を伝えているかを問い、個々の記述にはその役割に該当する検査を適用する。説明や案内に行動要求、実行主体、終了条件がないこと自体は欠陥ではない。説明の事実誤認、必要な背景の欠落、説明と義務の境界による誤読は検査対象とする。レビュー担当者は、目的や状況の説明から実行者への新しい義務を導かない。

レビュー担当者は、文書レビューを併用するときも、説明の長さや重複だけを理由に不要と判定しない。条件や補足を増やさない繰り返し、対象と異なる説明の混入、必須の指示が背景説明に埋もれる構成について、読者が必要な意味や指示をどこで取り違えるか、または見つけられなくなるかを確認する。説明には、誤解の防止、理解の共有、参照先を探す負担の軽減という役割もある。レビュー担当者が有用性や行動の変化を説明できないだけでは、不要と断定したり削除を求めたりしない。

## 実行者文脈

レビュー担当者は、想定する実行者が指示の発動時点と各動作の時点で実際に利用できる入力、状態、権限、参照先を、検査対象と判断根拠となる正本から確認する。

レビュー担当者は、レビューのために与えられた情報を指示の正しさとの照合に使う。実際の実行時にも実行者へ渡ることを確認できる情報だけを、実行者が利用できる文脈として扱う。

## 検査方法

レビュー担当者は、依頼・要件・仕様に示された目的と利用場面を、文書が伝える内容および要求する結果と照合する。個々の規則だけでなく、規則を組み合わせた経路全体でも、必要な結果の欠落や目的からの逸脱がないかを確認する。

レビュー担当者は、想定する実行者として指示の発動から結果の返却までの経路を順にたどる。各時点で実行者が実際に持つ入力、状態、権限だけを使い、必要な判断と動作が成立するかを確認する。条件が変わる境界、入力を得られない場合、操作の失敗や拒否、中断についても、対象の利用場面に即して停止・返却・回復の経路を確認する。常時稼働する指示では、継続条件と中断・終了要求への応答を確認する。

レビュー担当者は、他の指示や成果物との接続先を直接確認し、必要な情報と責務が実際に接続するかを調べる。

問題の候補を見つけたレビュー担当者は、実行者がどの時点で何を知り、どの記述をどう解釈した結果、必要な理解・判断・動作・結果のどれが成立しなくなるかを再現する。説明の問題では、行動要求を仮定せず、その説明を読む場面での理解や参照への具体的な支障を示す。判断根拠が不足する場合は、欠陥や問題なしと断定せず、判断できない事項と不足している情報を返す。

レビュー担当者は、静的な照合と経路の確認で分かったことを、実際のモデルが指示に従うことの保証として報告しない。モデルによる無視・誤解や実運用での効果は、実行による評価がなければ未確認として区別する。
