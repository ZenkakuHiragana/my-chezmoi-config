# 文体の方針

文体の観点では、文法上成立し、正本の意味を保つ表現が、想定読者、利用場面、文章の種類、媒体に合っているかを検査する。好みや特定語の出現ではなく、読者が概念を特定できない、文書内の立場を取り違える、重要箇所を見失うといった利用上の破綻を根拠にする。

誤字、脱字、余分な文字、固有名詞や固定文字列の一意に決まる誤りは、誤記の観点で扱う。正本と条件や確かさが違う場合は、自然な表現であっても意味の不一致として扱う。

## 読者と場面に合う語彙

読者向けの説明では、読者が意味を直接理解できる定着した日本語があるかを確認する。一般語を理由なくアルファベット表記にした結果、読者が別の概念を探したり、意味を推測したりする箇所は指摘対象となる。外国語由来でも定着したカタカナ語は、由来だけを理由に問題としない。

原表記の正確な文字列が、操作、検索、照合、概念の識別に必要な場合は残っていることを確認する。正式名称、設定名、コード、パス、識別子、引用、対象読者が通常その表記で識別する略称がこれに当たる。日本語へ置き換えると区別が失われる原表記を、読みやすさだけで変更することは要求しない。

略称や内部呼称は、想定読者がその概念と役割を特定できるかを確認する。読者に説明が必要な場合は、原表記を消すことではなく、原表記と説明の関係が本文から分かる状態かを検査する。

## 表記と用語の一貫性

同じ概念、作業、資料、システム、組織を指す表記が文書内で一致しているかを確認する。本文に表記規則、用語集、正式名称、略称の指定がある場合は、その適用範囲と各出現箇所を照合する。

表記揺れを指摘する場合は、異なる表記とそれぞれの出現位置を示し、同じ概念を指すと判断できる根拠を付ける。同じ語を含む指標名、画面名、ログ名、資料名であっても、別の概念の名称要素である場合がある。本文と正本から同じ概念かを確定できなければ、推測した統一案を示さず `判定不能` とする。

一方、区別すべき概念を同じ語で表したため、読者が対象や状態を取り違える場合も文体上の問題となる。見た目をそろえることより、概念の区別が保たれていることを優先する。

## 文書の立場と待遇表現

文末、敬語、呼び掛けは、書き手と読者の関係、場面の改まり、依頼が相手に与える負担に合っているかを確認する。尊敬語、謙譲語、丁寧語は、誰の行為を誰に対して述べるかが違う。丁寧に見せるために重ねた結果、行為者や相手を取り違える場合は問題となる。

同じ立場から続く本文では、文体や同じ動作を表す述語の違いによって、義務の強さや話者の立場が変わって読めないかを確認する。引用、会話、異なる主体の発言では文体が変わり得るため、文書内に複数の文体があることだけで指摘しない。

## 補足、反復、範囲の表し方

括弧は、用語の別名、短い例、本文に従属する補足をその位置で示せる。括弧があることや、見出しに補足があること自体は問題ではない。括弧を外しても情報が増減せず、本文や見出しを言い直すだけで探索を妨げる場合や、判断に不可欠な条件を補足へ押し込めて見落とさせる場合に指摘する。

反復は、独立して読まれる箇所の前提、長い説明の要約、安全条件の再確認として必要な場合がある。削除したときに読者が前の箇所を探し直す必要が生じるなら、単なる冗長さとは扱わない。同じ内容を言い直すだけで主題へ進むのを妨げる場合や、表現の差から別の条件と誤読させる場合に指摘する。

「としては」「においては」「に対しては」「については」のような形も、対比や話題の限定を表せる。例えば「構文としては正しいが、仕様には合わない」では、二つの判断軸を区別している。語の有無だけで冗長とせず、その限定や対比が読者の理解に寄与するかを確認する。

「など」「等」は例示に使える。有限な対象をすべて特定する必要がある手順で範囲を未確定にする場合は問題となるが、例示であることが明らかな説明から一律に削除しない。

推量表現も、未確定の事実を未確定のまま伝える役割を持つ。「可能性がある」「考えられる」「場合がある」を見つけただけで指摘しない。根拠が確定しているのに責任や結論を不明にする場合、または根拠より強い確かさを与える場合に、意味の不一致との境界を示して指摘する。

書き手の都合や編集履歴を説明する前置きは、読者が文書の範囲を判断するために必要かを確認する。「この文書では簡潔にまとめる」のような文が何を扱うかを示さず、主題へ進むのを遅らせるだけなら問題となる。適用範囲や扱わない対象を知ることが読者の選択を変える場合は残せる。

## 句読点と空白

句読点は、係り受け、並列、語句の切れ目を読者が追えるかを確認する。読点の数や一文の文字数だけで文体の適否を決めない。表記規則が指定されている場合は、その規則が対象とする文章の種類と媒体を確認して照合する。

日本語の語と語の間にある空白は、区切りとして意図されているかを確認する。空白によって語のまとまりを誤認する場合や、文書内の表記規則に反する場合は指摘できる。日本語とアルファベット、数値、記号の境界に空白があることだけでは問題としない。コード、コマンド、識別子、媒体の記法では空白が意味を持つため、散文の表記規則を機械的に適用しない。

## 太字・斜体構文の境界

この文書レビューでは、Markdown の太字（`**`）と斜体（`*`）について、構文の外側に隣接する文字が ASCII 文字でない場合、その境界に ASCII 空白を置く方針を保持する。これは媒体をまたいで安定した表記を得るための文体方針である。

```markdown
悪い例は**こうだ**。
良い例は **こうだ。**
文が続く場合は **ここまでを強調する。** 次の文を始める。
```

句点を強調範囲に含める場合は、`**ここまで。**` のように句点を閉じ記号の内側へ置く。`**ここまで。 **` のように、句点と閉じ記号の間へ空白を入れない。閉じ記号の後に日本語の文が続く場合は、閉じ記号と次の文の間に ASCII 空白を置く。

[CommonMark 0.31.2 の強調に関する仕様](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)では、強調の成立を区切り文字の内外にある Unicode の空白と句読記号から判定する。非 ASCII 文字に隣接するかどうかだけで決まる仕様ではない。例えば `これは**重要**です` は強調として成立し得る一方、`これは**「重要」**です` は内側の括弧と外側の文字の関係によって強調にならない実装がある。開始記号の直後や終了記号の直前に空白を入れた `** 重要 **` も強調として成立しない。

したがって、次の二つを分けて報告する。

- 実際の表示で強調記号が文字として残る、内容が消える、意図しない範囲が強調される場合は、媒体での表示失敗である。
- 実際には強調として表示されても、外側の非 ASCII 境界に ASCII 空白がない場合は、この文書レビューの表記方針への不適合である。

表示失敗は、対象の Markdown 解釈系または最終生成物で確認する。CommonMark の仕様を根拠に、すべての非 ASCII 境界で空白が必須だとは報告しない。

## 外部資料

文体の判断では、対象の読者と文章の種類に適用できる範囲で次の一次資料を参照する。

- [文化庁「分かり合うための言語コミュニケーション」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/wakariau/pdf/r1403493_01.pdf): 正確さ、分かりやすさ、場面へのふさわしさ、敬意と親しさの関係を確認できる。
- [文化庁「敬語の指針」](https://www.bunka.go.jp/seisaku/bunkashingikai/sokai/sokai_6/pdf/keigo_tousin.pdf): 尊敬語、謙譲語、丁寧語が誰の行為と関係を表すかを確認できる。
- [国立国語研究所「『外来語』言い換え提案 利用の手引き」](https://www2.ninjal.ac.jp/gairaigo/Teian1_4/tebiki.html): 読者と文脈に応じた言い換え、説明、原語保持の判断を確認できる。
- [日本翻訳連盟「JTF日本語標準スタイルガイド（翻訳用）」](https://www.jtf.jp/tips/styleguide): 実務翻訳での表記統一を確認できる。対象が採用していない規則を日本語一般や Markdown の仕様として強制しない。
- [国立国語研究所「日本語の文章で読点のルールはどうなっていますか」](https://kotoba.ninjal.ac.jp/qa/yokuaru/qa-53/): 読点が係り受けや語の切れ目に果たす役割と、文脈による判断の幅を確認できる。
