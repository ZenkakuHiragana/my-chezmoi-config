# 構成の方針

構成の観点では、文書全体、節、段落、複数の文書に配置された情報を、読者の利用順に検査する。読者が必要な情報を見つけ、情報同士の関係を復元せずに理解し、目的の判断や操作へ進める状態かを確認する。

## 主題と情報の範囲

文書の目的と利用場面に照らし、冒頭から主題を特定できるか、各節と段落がその主題に必要な説明を進めているかを確認する。中心となる主張や操作に必要な条件が欠けている場合だけでなく、読者の利用に関わらない詳細が中心を見つけにくくしている場合も、具体的な利用上の破綻を示して指摘する。

書き手が受けた編集指示、却下案、レビュー履歴は、読者が文書を利用するための情報とは限らない。本文に現れる否定や対比については、比較対象を読者が既に知っているか、その差が判断や操作を変えるかを確認する。比較対象が読者の文脈に存在しないため、未知の候補を理解してから捨てなければ主題へ進めない場合は問題となる。否定された事実そのものが結果である場合や、既出の候補との差が必要な場合は、否定や対比を問題にしない。

## 情報の導入と進行

読者がある情報を理解するために別の定義、条件、識別子を必要とする場合は、必要な情報へ先に到達できるかを確認する。後段の説明を先取りしなければ読めない箇所や、未定義の作業番号、略称、内部呼称を保持したまま読み進める必要がある箇所は指摘対象となる。

用語の名前を定義文の先頭に置いただけでは問題としない。その文または直後の文で役割を理解できる場合や、読者が既に知る名前から説明を探す参照資料では、名前を先に示すことが利用に合う。指摘するのは、名前と役割の順序によって読者が以後の説明を解釈できない場合である。

中心となる仕組みと例外や分岐の順序も、読者の利用に照らして確認する。中心の理解がなければ例外を位置付けられない文書では中心を先に読める必要がある。一方、入口で条件を選ぶ手順書では、分岐を先に示した方が目的の操作へ早く進める場合がある。常に単純な場合を先に置くことは要求しない。

## 情報同士の関係

主張と根拠、原因と結果、条件と結論、全体と部分が、語句と配置から読み取れるかを確認する。隣接しているだけの文を因果関係として読ませたり、同じ一覧に手順と分類を混ぜたりした結果、読者の判断が複数に分かれる場合は問題となる。

矛盾は、同じ対象について同じ条件と同じ作用を述べた記述が、両立しない結論を要求するときに成立する。例えば「本番環境では機能を有効にしない」と「本番環境で機能を有効にする」が同じ対象へ同時に適用されるなら、読者は最終状態を決められない。「検証環境で有効にする」と「確認後に設定値を本番環境へ保存する」のように、環境や作用が違う文を表面上の対比だけで矛盾としない。

同じ概念を複数の用語で示したため別物と読める箇所は、構造上の関係を失わせているか確認する。単なる表記の違いは文体で扱う。

## 重複と複数文書の配置

同じ説明が複数箇所にある場合は、それぞれが読者の利用に担う役割を確認する。独立して読まれる節で前提を再掲する、長い説明の後で判断事項を要約する、操作の直前に安全条件を再確認するといった重複は、必要な説明になり得る。一律に参照へ置き換えない。

指摘するのは、重複によってどれを正として使うか決められない場合、一方だけが古く条件や結論が食い違う場合、または再説明が新しい情報を加えず目的の箇所を探しにくくする場合である。

複数文書を対象とする場合は、各文書の役割と通常の利用経路を確認する。別文書が所有する定義や一覧を複製した結果、更新後の内容を一意に得られない場合は問題となる。参照でつなぐ場合は、参照先で何を得られるかが分かり、利用時に到達できるかも確認する。

## 表現形式の選択

形式の多さや少なさではなく、読者が情報をどう利用するかと、情報同士の関係が形式に表れているかを検査する。

| 形式 | 読者の利用 | 指摘が成立する状態 |
| --- | --- | --- |
| 本文と段落 | 説明や因果を順に理解する | 文を分けたため関係が失われる、または異なる主題を一つの段落から分離できない |
| 見出し | 必要な節を探し、全体の階層をつかむ | 見出しが内容を識別できない、または階層と本文の関係が一致しない |
| 箇条書き | 同じ役割を持つ項目を拾い、集合として確認する | 何の集合か分からない、項目の役割が混ざる、または本来必要な因果や条件が項目間で失われる |
| 番号付き手順 | 操作の順序や個数を追う | 順序が結果を左右するのに順番を再現できない、または番号が順序以外の分類と混同される |
| 表 | 共通の軸で値や選択肢を比較する | 行と列の対応が分からない、異なる比較軸が同じ列に混ざる、または表示時に内容が失われる |
| 図 | 要素間の関係や全体像をつかむ | 記号や線の意味を特定できない、または図だけに必要な意味が閉じて利用できない |
| コード | 固定文字列、構文、入出力を正確に識別する | 説明文との境界がなく、入力する文字列や例示の範囲を確定できない |
| 注記 | 主な流れを保ったまま補足を確認する | 判断や安全に不可欠な条件が遠い注記へ分離され、適用箇所で見落とされる |
| 強調 | 重要な箇所を他の本文から見つける | 多用や対象の不明確さによって、どこを優先して読むか区別できない |
| 参照リンク | 別の資料へ進み、詳細や正本を得る | 参照目的が分からない、到達できない、または必要な説明を得られない |

短い列挙を文中に置いても、同じ述語に対する役割が分かり、読者が一続きの文として利用できるなら問題ではない。箇条書きの項目に条件分岐が含まれていても、どの条件がどの行動や結果に対応するかを項目内で追えるなら問題としない。項目の品詞や長さがそろっていないことだけでも指摘しない。

短い説明に見出し、表、図を加えると、読者が構造の意味を解釈する負担の方が増える場合がある。形式を使っていないこと自体ではなく、必要な情報が得られない箇所や、関係を組み立て直すために余計な読み戻りが生じる箇所を示す。最終的に意味が分かっても、同じ説明の反復や項目間の行き来によって利用を妨げるなら検査対象とする。

## 外部資料

構成と形式の判断では、資料の適用範囲を確認したうえで次の一次資料を参照する。

- [文化審議会「公用文作成の考え方」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93651301_01.pdf): 読み手に応じた媒体、段落、箇条書きの選択を確認できる。公用文向けの目安を全種類の文書の正誤へ広げない。
- [デジタル庁デザインシステムの見出し](https://design.digital.go.jp/dads/components/heading/): 見出しが内容の階層と探索に担う役割を確認できる。
- [デジタル庁デザインシステムの箇条書き](https://design.digital.go.jp/dads/components/list/): 項目と番号が表す情報を確認できる。
- [W3C WAI の表に関する手引き](https://www.w3.org/WAI/tutorials/tables/): 論理的な行列関係を表で伝える条件を確認できる。
- [W3C のリンク目的に関する解説](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html): リンク文字列と読者が利用できる文脈の関係を確認できる。
