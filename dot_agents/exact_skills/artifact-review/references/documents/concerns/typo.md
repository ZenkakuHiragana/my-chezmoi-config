# 誤記

文字の抜けや重複、誤変換など、意味や表現を選び直さずに訂正できる誤りを確認する。
正しい文字列を一つに確定できるものだけを、誤記として扱う。

## 正しい表記との照合

本文だけでなく、見出しや表、注記にある文字も確認する。
リンクの表示文字列やコード例も対象に含める。
固定文字列は、一文字や空白の違いで意味が変わり得るため、散文として自然かではなく、正本と一致するかを確かめる。

正しい文字列を、次の根拠から確定できるかを調べる。

- 同じ文書内に正式な表記があり、一部の出現だけが異なる。
- 対象に適用される表記規則や用語集が、正しい表記を定めている。
- 判断根拠となる正本に、名称や操作に使う文字列の正確な表記がある。
- 文脈から文字の抜けや重複、明らかな変換誤りと分かり、正しい表記の候補が一つに決まる。

誤った文字列と正しい文字列を対応付け、どの根拠によって訂正が一つに決まるかを確認する。
用例が少ないことや検索で見つからないことだけを、文字の誤りの証拠にしない。

## 意味の判断が必要な場合

訂正候補が複数ある場合は、どれが書き手の意図かを推測して誤記にしない。
助詞を変えると動作の主体が変わる文や、推量を断定へ変える文は、文字の置換ではなく意味の判断を必要とする。
こうした箇所は、文法や意味の問題として扱う。

本文から曖昧さを確認できる場合は、その問題と、正しい意図を確定できないことを分ける。
訂正内容を選べないからといって、確認できた曖昧さまで問題なしにしない。

同じ概念に異なる表記が使われ、どれを正式とするか決まっていない場合は、「文体」の表記揺れとして扱う。
外部の辞書や用例を調べても、対象で採用すべき表記が一つに決まるとは限らない。

空白の有無も、それだけでは誤記にしない。
散文中の区切りや Markdown の強調境界は文体の観点で扱う。
コマンドや正式名称など、空白も含めて文字列が定まっている場合は、正本との差を誤記として確認する。

## 指摘と再確認

誤った原文をコード表記で引用し、その位置と、正しい文字列を確定した根拠を示す。
同じ誤記が複数ある場合は、一つの指摘にまとめ、検査対象内の全出現箇所を示す。

確認方法には、原文と正本の文字列を比較し、対応後に全出現箇所を再走査して解消を確かめられることを示す。
この比較を一意に示せないものは、誤記として確定しない。
レビュー担当は置換を実行せず、対象本文や生成物を変更しない。

## 外部資料

外部資料は、対象が採用する表記規則を照合するため、または用例を調べる手掛かりとして使う。
資料に表記があることだけで、対象の訂正を一意に決めない。

- [文化審議会「公用文作成の考え方」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93651301_01.pdf): 公用文に適用する用語と表記を確認する。別種の文書へ自動適用しない。
- [日本翻訳連盟「JTF日本語標準スタイルガイド（翻訳用）」](https://www.jtf.jp/tips/styleguide): 対象が採用する実務翻訳の表記規則を照合する。表記統一の選択と文字の誤りを区別する。
- [国立国語研究所「現代日本語書き言葉均衡コーパス」](https://clrd.ninjal.ac.jp/bccwj/): 文脈、分野、年代を伴う用例を調べる。頻度だけで文法的な正誤や一意な訂正を決めない。
