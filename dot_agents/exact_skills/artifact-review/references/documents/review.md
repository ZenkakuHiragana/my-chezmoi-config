# 文書レビュー

自然言語で書かれた成果物を、実際の読者が利用できるかという観点で検査する。
読者が元の情報の意味と確かさを保ったまま必要な内容へ到達でき、文や媒体の構造を余計に復元せずに理解、判断、操作を行える状態かを確認する。

構成、利用、表示の検査は、文書の言語にかかわらず適用する。
日本語に固有の文法・語彙・表記の基準は、日本語の箇所に適用する。

検査観点が指定されていない場合は、構成、文法、文体、誤記のすべてを検査する。

## 検査の前提を確定する

検査対象は、読者へ渡す最終の文書または生成物とする。
依頼と判断根拠となる正本から、文書の目的、想定読者、利用場面、文章の種類、基準とする時点を確認する。
元の情報がある場合は、要求の強さ、成立条件、例外、確かさ、責任を対象本文と照合できるようにする。

読者の文脈に含めてよい情報は、成果物を受け取った時点で読者が持つと確認できる知識と、通常の利用経路で本文から到達できる情報に限る。
レビューのためだけに渡された正本は、本文の正しさを照合する根拠にはなるが、読者も到達できる場合を除いて既知の前提にはしない。

読者や利用場面を確定できない箇所では、特定の読者にとっての適否を推測しない。
元の意味や確かさを照合できない箇所では、意味の不一致を断定しない。
判断に必要な情報と、その情報がないために確認できない内容を `判定不能` として示す。

## 読者の利用を再現する

読者が実際に使う入口から成果物を読み、目的に応じて情報を探し、参照をたどり、説明を理解し、必要な判断または操作へ進む。
文章の途中では、その位置までに得られた情報だけで用語、指示対象、条件、理由、参照先を解釈できるかを確認する。
後から現れる説明や、書き手とレビュー担当だけが知る作業経緯を先取りして補わない。

問題の候補を見つけた場合は、前後の文章、到達可能な参照先、判断根拠となる正本を使って再読する。
読者が現実に取り得る解釈と、その解釈によって理解、判断、操作のどれが成立しなくなるかを確認できたものだけを指摘する。
特定の語形、記号、文の長さ、箇条書きの形が現れたことだけでは問題としない。

各観点では次の検査を行う。

- [構成](concerns/structure.md): 情報の選択、順序、関係、参照、表現形式が読者の利用に対応しているかを検査する。
- [文法](concerns/grammar.md): 文の構造が成立し、助詞、時制、態、否定、推量を含む形式が意図した意味を表しているかを検査する。
- [文体](concerns/style.md): 語彙、文体、表記、補足、強調が読者、場面、媒体に合っているかを検査する。
- [誤記](concerns/typo.md): 意味判断を伴わず一意に特定できる文字の誤りを検査する。

## 不成立の種類を分ける

同じ表現でも、何が成立していないかによって指摘の根拠が異なる。

| 種類                 | 判定する内容                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 文法的な不成立       | 語形や助詞の接続、構文が成立しない                                                           |
| 意味の不一致や曖昧さ | 正本とは異なる意味を伝える、または読者に必要な区別が複数の解釈に分かれて定まらない           |
| 用途や文体の不適合   | 意味は保たれていても、読者、場面、文章の種類、媒体での利用に合わず、必要な理解や操作を妨げる |

文法的に可能な省略、受身、推量、否定を、用途に合わないという理由だけで文法誤りにしない。
反対に、自然に読める文でも正本と意味が違えば、文体の好みではなく意味の不一致として扱う。

読者に必要な区別が定まらないことは、書き手が意図した答えを知らなくても本文から確認できる場合がある。
その場合は、成立する複数の読みと利用への影響を示して曖昧さを指摘する。
正しい意味を選ぶ材料が足りないことは、訂正内容についての `判定不能` と分ける。

## 文書と参照を検査する

対象に適用できる文法検査、リンク検査、描画、記載例の実行確認を、与えられた権限内で行う。
リンクは構文だけでなく、想定読者が通常の利用経路から到達でき、本文が示した目的の情報を得られるかを確認する。
コードや操作例は、実行が認可されている場合に限り、記載どおりの結果になるかを確認する。

機械的な文法検査が示す結果は再読する箇所の候補として扱う。
指摘数、文字数、特定の語の出現だけで日本語の正誤を決めない。
検査手段がない場合や権限内で実行できない場合は、実施済みの検査と分けて、理由と未確認の内容を報告する。

## 最終生成物の表示を検査する

PDF、スライド、描画後の Markdown のように表示結果を持つ文書では、読者へ渡す最終生成物を実際に開く。
元ファイルの構文検査や生成処理の成功を、表示確認の代わりにしない。
途中の生成物を確認していても、最終生成物について次の項目を確認する。

- 見出し番号が意図した順に振られている。
- 表が表示領域に収まり、内容を読める。
- 長いパス、コード、識別子が欠けず、配置を壊していない。
- 箇条書きと節の間隔から、まとまりを目で追える。
- 表紙と節の順序が、読者の読み進め方に対応している。

表示確認後に本文、生成条件、参照する素材が変わった場合は、変更後の最終生成物で同じ検査をやり直す。
表示を確認できない場合は、生成の成否と見た目の確認を分け、見た目を `未確認` として報告する。
表示の正常性が受け入れ条件なら、未確認のまま合格としない。

## 結果を返す

指摘には、問題を再現できる対象箇所、読者に起きる破綻、判断根拠を含める。
成立する条件や再確認の方法がなければ問題を特定できない場合は、それらも示す。
担当した検査で問題を確認しなかった場合は、その旨を返す。

レビュー担当は対象本文や生成物を修正せず、巻き戻しも行わない。
検査自体が失敗しても対象を巻き戻さず、失敗した検査と未確認の範囲を返す。
指摘への対応方法は決定せず、結果を成果物の本文へ書き込まない。
