# 成果物レビュー

## 適用する検査

レビュー全体で実行する検査を決めるときは、検査対象に当てはまるすべてのレビュー入口文書を読む。
一つの検査対象が複数の種類に該当する場合は、それぞれを適用する。

- `references/code/review.md`: 実行可能なソフトウェアコード
- `references/documents/review.md`: 人間や LLM が読む自然言語で書かれた文章、コメント、プロンプト、スキルの本文
- `references/instructions/review.md`: スキルの本文、システムプロンプト、AGENTS.md など LLM への指示として用いられる文章

各レビュー入口文書に従って、検査する観点、種類固有の検査方法、および該当する補足を決める。
検査すべき観点が指定されている場合は、その検査に必要な観点だけを使う。

## 検査

検査対象と、判断根拠となる依頼・要件・仕様その他の正本を直接確認する。
対象の意味や挙動を確定するために別の資料や実体を確認する必要がある場合は、検査対象からその関係を辿って確認する。

レビュー入口文書に定められた検査方法と、担当する観点に定められた着眼点に従って対象を調べる。
問題の候補を見つけたら、その結論を左右する前提を、対象と判断根拠から確認する。
候補を支持する記述だけでなく、その前提や結論を変える定義、適用条件、入力、責務、参照先も確認し、併せて適用する。
それらを適用すると主張した問題が成立しない候補は指摘にしない。
適用しても問題が残る場合は、その成立条件と、満たされない性質を示す。

判断に必要な情報を確認できない場合は推測で補わず、何を確認できなかったために判断できないかを返す。

検査対象で具体的に成立することを確認した問題だけを指摘する。
指摘には、問題を再確認するために必要な対象箇所、問題の内容、直接の根拠を含める。
成立条件や確認方法がなければ問題を特定できない場合は、それらも示す。

検査すべき観点について、必要な性質が欠けていないかと、不要な記述や責務を持ち込んでいないかの両方から、検査対象全体を調べる。
問題候補を一件成立または不成立と判断しても、未確認の対象部分と関係先の検査を続ける。
成立した独立の問題は、一部を代表例として返すのではなく、すべて返す。問題を確認しなかった場合はその旨を返す。

レビュー結果は検査で確認した内容に限定する。検査対象の変更や指摘への対応方法の決定は行わない。
