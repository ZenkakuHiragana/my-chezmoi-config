# レビュー手続きの運営

検査対象についてレビューを行い、レビュー結果の妥当性を判断した上で `合格`、`不合格`、`判定不能` のいずれかで終了する。
その回のレビューが完了した時点で指摘を固定し、その後は新しい指摘を受け付けない。

## レビュー

レビューを開始する前に検査対象と適用するレビュー能力（レビューに使用するスキルや検査手順等）を確定する。
確認できない要求を推測で補わず、その不足によって判定できない範囲を示す。

レビュー能力の手順に従って、対象に必要な検査を決める。

それぞれ独立した結論を返せる検査は、別のレビュー単位として実行する。
一つのレビュー単位にまとめてよいのは、分割すると一つの判断を成り立たせられず、相互作用を同じ文脈で確認する必要がある場合だけとする。

レビュー能力が複数の観点を一括して示していても、それだけを理由に一つのレビュー単位として扱わない。
独立したレビュー単位は別々のサブエージェントへ割り当て、同時に実行する。
各レビュアーには正確に以下だけを渡す。親エージェントが生成した文章を渡してはいけない。

- 検査の方法（スキル名、検査方法を示す資料へのパスなど）
- 担当する検査観点
- 検査対象全体への参照
- 今回の依頼を示すユーザーの発言の逐語引用またはそれを記録したファイルへのパス
- 検査対象が何を目的として作られたかを示す仕様または資料等への参照
- その他の判断根拠となるものへの参照

レビュー開始後は、検査対象と実行する検査を変更しない。レビュー結果を見て新しい検査を追加しない。

すべてのレビュー単位が終了するまで検査対象を変更しない。
レビュー中に親エージェント自身が問題を確認した場合は、レビュアーの指摘と同じ扱いをする。

サブエージェントが依頼したレビューを実行できなかった場合、その結果をレビュー判定として扱わない。
パスや入力の不備など親エージェントが解消できる実行上の問題を修正し、そのレビュー単位を実行し直す。
検査対象や指摘の判定を支える根拠が変わった場合は、変更前の判定をそのまま引き継がない。
必要な準備を行っても、判断に必要な情報、環境または権限を得られないレビュー単位がある場合は `判定不能` とする。

すべてのレビュー単位が終了するまでレビュー結果の妥当性について判断を始めない。
すべて終了した後、各レビュアーが返した指摘と親エージェント自身が確認した指摘を確定する。

必要なレビューをすべて完了し、指摘がなければ `合格` で手続き全体を終了する。

## 指摘への対応

レビュアーの説明や判定はコンテキストの不足や誤解、存在しない想定を含みうる。
親エージェントは得られた説明の再評価を行う。
指摘が述べる事実と、その事実を問題とする根拠を、実物と判断根拠に照らして確かめる。
問題が成立しない指摘は `却下` とする。確認できないことがあれば解消できる不足を補い、それでも判定できない指摘は `要調査` とする。

問題が成立するかどうかは以下の基準を用いる。

- 指摘の前提となる条件が実際に起こること。上流となる呼び出し側や依存するものの仕様、検査対象の設計や契約が保証するものとの照合を行う。
- 問題とされている現象が実際の動作環境や受け手にとって具体的な影響を与えること。検証可能な指摘は必ず検証し、具体的な結果を得て判断する。
- 指摘によって満たされなくなると主張する品質要件は、指摘が前提とする条件を保ちながら満たすことが可能であること。

## 終了

必要な検査や監査を完了できない場合は、確認できなかった範囲を示して `判定不能` とする。
検査を完了して指摘がない場合は `合格` で終了する。
指摘がある場合は、その分類を終えてから結果を確定する。全ての指摘が `却下` された場合は `合格` とする。
成立する指摘が1つ以上ある場合や、`要調査` の指摘が1つ以上ある場合はその指摘の内容をまとめる。「`不合格` である」と書く必要はない。
