# レビュー手続きの運営

## 用語

- レビュー: サブエージェントに検査対象の妥当性を確認してもらい、その判定と指摘を受け取ること。
- 監査: レビューで得られた指摘への対応を、レビュー担当者や成果物作成者とは異なるサブエージェントに確認してもらうこと。

## 概要

検査対象についてレビューを行い、指摘がある場合はその対応と監査を行って、`合格`、`不合格`、`判定不能` のいずれかで終了する。

判断根拠として、まず `要件契約` を確認し、あわせて検査対象に適用される既存の正本を用いる。
この手続きにおいて判断根拠とはこれらの正本を指す。

レビュー中に何を達成すべきかは `要件契約` とその他の判断根拠によって決まる。
レビュー指摘は依頼や要件を変更する根拠にはならない。
指摘への対応方針と修正候補も、依頼と要件による拘束を維持しなければならない。

その回のレビューが完了した時点で指摘を固定し、その後は新しい指摘を受け付けない。
監査で指摘への対応に不一致を確認した場合は、固定した指摘の範囲内で対応を修正して再監査する。

## レビュー

レビューを開始する前に検査対象と適用するレビュー能力を確定し、`要件契約` とその他の判断根拠へ到達できることを確認する。

レビュー能力の手順に従って、対象に必要な検査を決める。

それぞれ独立した結論を返せる検査は、別のレビュー単位として実行する。
一つのレビュー単位にまとめてよいのは、分割すると一つの判断を成り立たせられず、相互作用を同じ文脈で確認する必要がある場合だけとする。

レビュー能力が複数の観点を一括して示していても、それだけを理由に一つのレビュー単位として扱わない。

独立したレビュー単位は別々の `reviewer` サブエージェントへ割り当て、同時に実行する。

各レビュアーには正確に以下だけを渡す。

- 担当する検査観点
- 検査対象全体への参照
- 現在有効な依頼および要件を示す `要件契約` への相対パス
- その他の判断根拠への参照

レビュー開始後は、検査対象と実行する検査を変更しない。レビュー結果を見て新しい検査を追加しない。

すべてのレビュー単位が終了するまで検査対象を変更しない。
レビュー中に親エージェント自身が問題を確認した場合は、レビュアーの指摘と同じ扱いをする。

サブエージェントが依頼したレビューを実行できなかった場合、その結果をレビュー判定として扱わない。
パス、入力、権限、環境、ツール実行など、親エージェントが解消できる実行上の問題を修正し、そのレビュー単位を実行し直す。
検査対象または判断根拠そのものを変更する必要が生じた場合は、変更前のレビュー結果を変更後の対象へ引き継がない。

必要な準備を行っても、判断に必要な情報、環境または権限を得られないレビュー単位がある場合は `判定不能` とする。

すべてのレビュー単位が終了するまで指摘への対応を始めない。
すべて終了した後、各レビュアーが返した指摘と親エージェント自身が確認した指摘を一つの指摘集合として確定し、以後はその集合だけを指摘への対応対象とする。

必要なレビューをすべて完了し、指摘がなければ `合格` で手続き全体を終了する。

## 指摘への対応

レビュアーの説明や判定は親エージェントによる再評価の対象である。
以下の通りに親エージェント自身が判断して指摘された状態を分類する。

まず、各指摘について問題が成立するかを確認する。
いずれの判断でも、必要な情報を確認できない場合は親エージェントが解消できる不足を解消して判断を続ける。
それでも判断できない指摘を `要調査` とする。

- 指摘された状態が検査対象で実際に成立する
- その状態が `要件契約` とその他の判断根拠に照らして実際に問題である

問題が成立しない指摘は `却下` とする。

成立した指摘について、その問題の解消が現在有効な依頼と、
それに基づいて許される変更の範囲に含まれるかを `要件契約` とその他の判断根拠に照らして判断する。

- 含まれる場合は `修正対象`
- 含まれない場合は `未対応`

## 修正候補

`修正対象` となる指摘があって、かつ現在の依頼が成果物の修正を含む場合は、それらをすべて反映した修正候補を作成する。

修正候補は、指摘への対応として必要で、かつ現在有効な依頼や要件に従う変更だけで構成する。

修正候補は現在の成果物とは別に保持し、監査に合格するまで採用しない。
監査を開始する時点で、そのまま採用できる状態まで完成させる。

現在の依頼が成果物の修正を含まない場合は修正候補を作成しない。
この場合も、各指摘の分類と対応方針は最後まで確定する。

## 監査

指摘へのすべての対応を、サブエージェント `review-audit` に監査させる。

監査者には正確に次だけを渡す。

- 指摘の逐語引用
- 各指摘と、親エージェントが決めた分類との対応
- 現在有効な依頼および要件を示す `要件契約` への相対パス
- その他の判断根拠への参照
- レビューした検査対象全体への参照
- 修正候補がある場合は、その修正候補への参照

監査者が依頼した監査を実行できなかった場合、その結果を監査判定として扱わない。
親エージェントが解消できる入力や実行上の問題を修正して監査を完了させる。
必要な準備を行っても判断に必要な情報、環境または権限を得られない場合に `判定不能` とする。

監査で指摘への対応または修正候補に不一致を確認した場合は、
指摘と現在有効な依頼・要件の範囲内で対応方針または修正候補を修正し、再度監査する。
監査で確認した不一致を新しいレビュー指摘として扱わない。

## 終了

指摘がある場合は、固定したすべての指摘への対応を完了し、その対応について監査を行った後にレビュー手続きの結果を確定する。
指摘がなかった場合は、その時点でレビュー手続きの結果は `合格` となる。

監査が `合格` し、監査済みの修正候補がある場合は、その修正候補を採用して修正を適用する。

以下に従って結果を確定する。

- `要調査` の指摘が一件以上残っている場合は `判定不能` とする。
- `要調査` の指摘がなく、`未対応` の指摘が一件以上残っている場合は `不合格` とする。
- `修正対象` の指摘について修正を適用した場合は修正後の検査対象についてもう一度このレビュー手続き全体をやり直す。
  修正前後は別物として扱い、それまでの指摘や対応結果を引き継いではいけない。
- `要調査`、`修正対象`、`未対応` の指摘がなくて、修正も適用していない場合は `合格` とする。

`合格` は、その時点の検査対象について所定のレビュー手続きを完了し、問題を確認しなかったことを表す。
`合格` した検査対象をその後変更した場合、その変更後の内容にレビュー結果を引き継がない。
