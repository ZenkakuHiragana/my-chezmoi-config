# コードレビュー

コードまたは差分を読み、仕様、利用経路、実行環境、言語、依存関係と照合して、実際に起きる欠陥だけを指摘する。対象を編集せず、設計の好みや一般論を破綻として返さない。

## 境界

レビュー対象はコード、差分、コードに直接結び付く設定・スキーマ・生成物・テストである。文章の自然さ、設計案の比較、実装の編集、未確認の要件決定は行わない。コードが実行する利用者向け文言の意味を確認する場合も、コードの挙動と結果との一致だけを扱う。

対象の一部、依存先、実行環境、テストを読めない場合は、その範囲の無欠陥を主張せず、未確認の範囲と理由を返す。

## 検査観点

以下は利用可能な検査観点である。対象・目的・差分との関係を確認し、必要な観点だけを適用する。

### 正しさと仕様適合

- 受け入れ結果、仕様、事前条件、事後条件、不変条件を識別し、正常、境界、空、重複、順序、部分成功、失敗を追う。
- 分岐、早期終了、既定値、変換、単位、丸め、時刻、ロケール、再試行が意図した意味と一致するか確認する。
- 実装が仕様を満たす経路だけでなく、仕様にない入力をどう扱うかも確認する。
- テスト、コメント、名称より、実際の制御フロー、データフロー、実行結果を優先する。

### 状態とライフサイクル

- 初期化、更新、再読込、再接続、再試行、キャンセル、終了、破棄の順序を追う。
- 状態の所有者、正本、更新者、観測者、許可された遷移を確認する。
- 失敗途中、部分初期化、二重終了、再入、再利用、解放後の利用を確認する。
- 導出できる値を独立状態として保持していないか、複製された状態の同期条件があるか確認する。

### エラーと回復

- エラーの種類、文脈、原因、利用者への意味、上位への返却を確認する。
- 例外、戻り値、Result、空値、既定値、ログだけの処理が、失敗を成功へ変えていないか確認する。
- 部分的な変更、資源の解放、ロールバック、再試行、キャンセルを確認する。
- 回復できない層が判断材料を捨てたり、回復できる層へ無意味な内部詳細を漏らしたりしていないか確認する。

### インターフェイスとデータ

- 引数、戻り値、型、順序、単位、文字コード、null、所有権、寿命、可変性、例外、副作用を利用側と照合する。
- データ形式、シリアライズ、スキーマ、設定名、列挙値、互換性、既定値を確認する。
- 呼び出し側が内部形式、保存方式、処理順序、回復手順を推測しなければならない状態を確認する。
- 公開インターフェイスを変えた場合、全利用者、生成物、文書化された利用経路を確認する。

### 並行性と非同期処理

- 共有データ、所有権、可視性、原子性、ロック、ロック順序、競合を確認する。
- データ競合、デッドロック、ライブロック、飢餓、再入、処理の重複、順序逆転を確認する。
- タイムアウト、キャンセル、終了、待機、再試行が、資源とタスクの寿命へ対応しているか確認する。
- 非同期の例外、タスクの未観測、完了前の破棄、実行コンテキストの切り替えを確認する。

### セキュリティ

- 信頼境界、入力検証、出力エスケープ、認証、認可、秘密情報、パス、権限、外部通信を確認する。
- SQL、コマンド、テンプレート、正規表現、パス、URL、シリアライズ、ログへの注入を確認する。
- 機密情報の露出、過剰な権限、再利用された資格情報、予測可能な識別子を確認する。
- 大きさ、回数、深さ、待機時間、資源枯渇によるサービス拒否を確認する。

### 互換性

- 対応する言語版、基盤、OS、実行時、データベース、プロトコル、設定形式を確認する。
- 旧データ、旧設定、混在する版、段階的な更新、ロールバック、読み書きの方向を確認する。
- 破壊的な変更、非推奨化、機能切り替え、生成物、ABI、依存ライブラリの版を確認する。
- 対応外の環境へ無言の代替処理を入れていないか確認する。

### 依存関係

- 直接依存、間接依存、任意依存、版の制約、ロック、生成物、外部契約を確認する。
- 依存の導入理由、所有者、更新経路、ライセンス、実行時に存在するかを確認する。
- 暗黙の初期化、輸入順、循環依存、環境依存、依存性注入の寿命を確認する。
- 既存の標準機能や依存で解ける問題に、新しい依存を足していないか確認する。

### 複雑性と性能

- 時間、空間、入出力、割り当て、コピー、直列化、ネットワーク、データベース、キャッシュを確認する。
- ループ内の高価な処理、入力による計算量の増大、最悪経路、保持期間、キューの増加を確認する。
- 大きな入力、同時実行、低速な外部資源、失敗時の再試行で実用上の限界を越えないか確認する。
- 性能改善を理由に、正しさ、可観測性、安全性、回復性を削っていないか確認する。

### 可観測性

- 失敗、重要な状態遷移、外部呼び出し、再試行、遅延、資源枯渇を判断できるログ、指標、追跡情報があるか確認する。
- 記録が原因、対象、相関、結果を追えるか確認する。
- 秘密情報、個人情報、入力全体を不要に記録していないか確認する。
- ログだけで成功扱いにせず、可観測性と回復を区別する。

### 保守性と責務

- 一つの変更理由に対応するまとまり、責務、依存方向、名前、局所性を確認する。
- 同じ判断、条件、変換が複数箇所へ複製されていないか確認する。
- 現在の問題に不要な抽象、層、状態、設定、フック、互換層を増やしていないか確認する。
- 機能追加しやすそうという推測だけで、現在の理解と変更を難しくしていないか確認する。

### コメントと文書

- コメント、公開APIの説明、例、設定説明、利用手順が実装と一致しているか確認する。
- 回避策、制限、寿命、失敗、前提を記した文書が古い挙動を示していないか確認する。
- コメントがコードを言い換えるだけでなく、現在も有効な理由や不変条件を説明しているか確認する。
- 文章の文法や表現の良し悪しはこの観点の対象にせず、コードの意味との不一致だけを指摘する。

### ビルドと配布

- コンパイル、型検査、静的検査、生成、パッケージ、起動、配布、配置の各経路を確認する。
- 変更したソースがビルドに含まれるか、生成物が古いままにならないか確認する。
- 開発時だけ成功し、清潔な環境、別の構成、継続的な確認、実配布物で失敗しないか確認する。
- ビルド設定、環境変数、機能切り替え、資源ファイル、移行処理の変更を確認する。

### テストの正しさ

- テストが実際の対象経路を通り、重要な条件、境界、失敗、再現手順を検査しているか確認する。
- モック、スタブ、固定値、時刻、無作為性、順序、並行性が、問題を隠していないか確認する。
- 成功だけでなく、失敗が適切に検出されること、資源が解放されること、再実行できることを確認する。
- テストの期待値が実装の現在の出力を写しているだけで、要求を検査していない状態を確認する。

### 差分の範囲

- 変更理由に直接必要なファイル、行、設定、生成物だけが含まれるか確認する。
- 無関係な整形、名前変更、依存更新、死んだコード、未使用の機能切り替えを確認する。
- 差分に含まれる削除が、利用経路、設定、文書、生成物、互換性を壊していないか確認する。
- 差分が小さくても、公開境界、正本、実行経路を変えていないか確認する。

## 言語・基盤別の補足

対象に該当する補足を実施する。該当しない補足は適用しない。

### C++

所有権、寿命、RAII、裸ポインタと参照、コピー・ムーブ、コンテナの反復子無効化、例外安全性、未定義動作、符号変換、テンプレート境界、ロック、ABI、標準版、コンパイル設定を確認する。

### C# と .NET

null可能性、IDisposable、using、非同期処理、キャンセル、例外、遅延実行と列挙、等価性とハッシュ、文化依存の文字列・時刻、依存性の寿命、設定・シリアライズを確認する。

### Lua と Neovim

暗黙のグローバル、nil、テーブルの形と共有変更、コロン記法とドット記法、メタテーブル、コールバック、コルーチン、モジュールの寿命、Neovim APIの非同期・バッファ・ウィンドウ・自動コマンドの状態を確認する。

### Python

可変オブジェクトと別名、既定引数、等価性とハッシュ、例外とfinally、反復子と生成器、非同期処理、コンテキストマネージャー、正規表現の境界、サブプロセス、資源の寿命、実行時型、時刻とタイムゾーンを確認する。

### Rust

所有権と借用、clone、collect、Option と Result、unwrap とパニック、match、寿命、unsafe、Send と Sync、非同期処理、Drop、エラー文脈、機能フラグ、クレートの版とCargo設定を確認する。

### シェル

引用、展開、単語分割、グロブ、終了値、パイプ、set -e の例外、`--`、コマンド置換、一時ファイルと終了時処理、配列、eval、ロケール、コマンドの有無、空入力、パスの空白と改行を確認する。

### ビルド・設定・データ

CMake、Cargo、CI設定、YAML、JSON、SQL、スキーマ、マイグレーション、環境変数を対象に、型、既定値、引用、順序、版、生成物、清潔な環境での再現性を確認する。構文が通ることだけで意味の正しさを認めてはならない。

## コード固有の入力

- 対象言語、実行時基盤、ビルド・配布方法
- 検査する観点。指定がなければ、全観点を必須にせず、対象・目的・差分に実質的に関係する観点だけを選ぶ。全観点を確認する場合は明示する

## コード固有の手順

1. 正常、境界、空、重複、失敗、再試行、並行、終了、互換の経路を追う。
2. 対象に該当する言語・基盤別の補足を適用する。

## コード固有の完了条件

- 該当する言語・基盤別の補足を検査した。
