# 公開根拠の参照本文

## 機密保護

外部探索の前に検索語を確認する。非公開のリポジトリ内容、秘密情報、内部 URL、ローカルパス、未公開の識別子、公開可否が不明な固有名を検索語にしてはならない。一般概念へ言い換えられない語は検索せず、未決の理由として記録する。

## 根拠の優先順

1. 公式文書
2. 仕様または標準
3. 一次提供元のリリースノートまたは提供元文書
4. 上流リポジトリまたは公式の課題管理
5. 原論文または標準的な参照資料
6. 一次資料が弱いときの信頼できる二次資料

## 手順

1. 主張を逐語で確認し、事実確認、手順確認、文脈確認、一般確認のどれかへ分類する。分類を主張の言い換えに使ってはならない。
2. 版と範囲が判定へ影響するときは、対象版と対象範囲を記録する。
3. 必要最小限の根拠を決め、機密保護を通過した検索語で一次資料を先に探す。
4. 既知の権威ある URL があるときは直接取得する。検索結果ページは発見にだけ使い、採用する根拠ページを取得する。
5. 検索語を変えるときは、変形の操作と上限を記録する。上限へ到達しても、検索で得られない不在を確定してはならない。
6. 重要な主張は複数の根拠で突き合わせ、公式資料と二次資料が矛盾するときは、主張の所有先と版を明示して判定する。所有先が決められないときは `未決` とする。
7. 取得した根拠の引用、URL、節、版、取得操作を記録する。

## 不在の扱い

公開情報の検索は列挙可能な全体を保証しない。検索語の上限到達、検索結果の空集合、アクセス不能は、指定した検索手続きで根拠を取得できなかったことだけを示す。概念全体の不在へ一般化せず、`未決` と停止理由を返す。

## 返却

確認済みの事実、注意点、不確実性、推測、引用、根拠の制限を分けて返す。推測を支持または反証の根拠として扱ってはならない。
