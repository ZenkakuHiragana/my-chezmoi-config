# 仕様照合レビュー

実装が固定済みの仕様、要件契約、設計書、公開 API 契約、互換契約と一致するか確認する。

## きっかけ

- レビュー対象の正否を要件契約、設計仕様、仕様書、公開 API 文書、標準、互換契約、生成仕様のいずれかで判定する。
- 仕様が識別子、引数、設定項目、プロトコル項目、ファイル形式、単位、値域、戻り値、制約、副作用、順序、割当を定義する。
- 実装が外部道具、実行環境、公開 API、生成物、永続形式へ接続する。
- 仕様未確認のまま、局所実装やコンパイル成功、テスト成功だけで正しさを判断している。

## 確認

### 差分トークンの根拠強制

仕様照合レビューでは、他の照合より先に、差分に新しく現れた、または意味、用途、割当が変わった契約関連トークンを列挙する。
契約関連トークンとは、意味や許容範囲が差分内だけでは決まらず、公開 API、外部道具、実行環境、仕様、既存実装契約、スキーマ、設定、生成物、永続形式のいずれかで定義されるものを指す。純粋に差分内で完結する局所識別子は対象外とする。

各トークンについて、そのトークンを許容または定義する根拠を `file:line`、URL、文書節のいずれかで示す。表には少なくともトークン、出現箇所、文脈層、根拠引用、状態を含める。

- 根拠を確認した結果、トークンが仕様に無い、仕様と食い違う、または許容されない場合は重大指摘とする。
- 根拠の存否を確定できない場合は判定保留とし、`investigation` / `public-research` で確認すべき根拠を示す。
- 必要なトークン一覧が無い場合、または必要な根拠種別に未確認が残る場合は、「指摘なし」と言ってはならない。レビュー未完了として不足根拠を示す。

### 他の確認事項

- 照合に使う仕様を明示する。仕様が複数ある場合は、どの仕様がどの実装面を決めるか分ける。
- 仕様が定義する各項目を、実装、テスト、文書、生成物の対応箇所へ対応づける。
- 仕様が表形式でなくても、要求、禁止、値域、単位、順序、戻り値、制約、副作用を項目として切り出して照合する。
- 識別子、引数、設定項目、プロトコル項目、ファイル形式内の項目などの名前や割当は、仕様側の定義と実装側の出現を突き合わせる。
- 仕様に無い割当、仕様と食い違う割当、二重割当、未定義識別子、値域外、単位違い、順序違い、戻り値または副作用の取り違えを指摘する。
- 仕様が未確認で判断できない項目は判定保留とし、`investigation` または `public-research` で確認すべき根拠を示す。

## 重大度

- 明示仕様、公開契約、要件契約、互換契約に反する実装は重大指摘とする。
- 仕様との対応が欠け、取り込み後に契約違反を見逃す可能性が高い場合は高重要度とする。
- 仕様根拠が足りず危険度を確定できない場合は判定保留とする。

## 出力

- 照合した仕様
- 仕様項目と実装箇所の対応
- 未照合の仕様項目
- 仕様違反または未確認事項
