# 文脈整理

依頼本文と後続の訂正をそのままの基底として扱う。その上で、基底に存在しないが現在では後段を拘束するに至った拘束を識別し、まだ決められない内容を分ける。基底にある意味を別表現で書き直さない。実装上の好みや推測を要求へ昇格させない。

## 確認するもの

- 基底となる依頼本文と後続の訂正・追加・選択が、後段から直接読める状態にあるか
- 依頼本文の指示対象が、会話、正本、確認済みの事実によって具体的な対象へ解決されたか
- 複数の選択肢のうちどれを採るか、判断主体が確定させたか
- 正本や実行結果の照合によって、今回の受け入れ結果を変える技術制約が確定したか
- ある確認結果の意味について、判断主体の判断が確定したか
- 未決の問い、その判断を持つ主体、決めない場合の影響

必要な事実の根拠が不足している場合は、未確認の事実、必要な照合内容、再開条件を返す。資料や実行結果への接触を推測で開始してはならず、確認できない事実は未確認のまま残す。

## 手順

1. 依頼本文と後続の訂正を基底として固定する。基底を要約、言い換え、再列挙してはならない。書かれていないものを補わない。
2. 観測事実、認可された拘束、仮説、未決の判断を分ける。現在の実装、テスト、設定、実行結果、一般論だけで新しい要求を作ってはならない。
3. 具体的な事実を使う場合は、所有先または提示された根拠へ直接対応付ける。提示された根拠がない場合は、照合が必要な未決として返す。根拠のない要約やモデルの好みを事実として扱ってはならない。
4. 複数の選択肢で受け入れ結果、公開インターフェイス、永続状態の所有先、結果を生む実経路、確認結果の意味が変わる場合は、その選択を持つ主体へ質問する。選択を内部で閉じてはならない。
5. 判断が必要な質問には、何を決めるのか、決めないと何が変わるのか、選択肢が結果へどう影響するのかを示す。質問は不足した判断を確認するためだけに行い、調査不足を新しい要求へ変えない。
6. 基底に存在しないがすでに認可され、今後の実行者を拘束する拘束だけを列挙する。達成方法、具体的な探索、下位実装の選択を、明示要求がない限り拘束しない。
7. 列挙した拘束が基底の意味を狭めて、広げて、または覆していないかを読み直す。不足する判断、根拠、対象、範囲、結果があれば、推測で閉じず不足の所有者と再開条件を返す。

## 結果に含める内容

結果には、基底へ直接到達できる参照、基底に存在しない認可済みの拘束とその認可元・根拠、未決の判断と判断主体、実行者へ委ねる選択を含める。形式は固定しない。

加えるべき拘束が一つもない場合は、拘束が空の結果を正規の状態として返す。空欄を埋める作文をしてはならない。

次は拘束として列挙してはならない。依頼の言い換えや要約、依頼に既にある要求の再列挙、一般論から補った要求、現在のコード・テスト・設定・作業ツリーの状態を見ただけで作った規範、実装方法や探索手順や便利な確認方法、下位実装裁量、仕様を完成した形に見せるための補完、未知の未決事項を網羅するために生成した仮説や質問。

観測事実を規範的な要求として書き換えてはならない。既存の正本や取り決めが所有する実装詳細を、依頼者の要求として複製してはならない。

## 停止条件

- 必要な判断を持つ主体が選択を確定するまで、実行へ進める結果として閉じてはならない。
- 根拠へ到達できない場合は、確認できなかった範囲と再開条件を返す。
- 受け入れ結果、公開インターフェイス、永続状態の所有先、実経路、確認結果の意味を変える未決を残したまま、実行開始を認めてはならない。
- 結果を作るために新しい構造、条件、識別子、固定形式を追加してはならない。

## 使わない場面

- 事実だけを資料や実行結果へ照合する作業
- 設計案そのものを比較する相談
- 固定済みの文章、コード、指示を検査するレビュー

## 完了条件

- 依頼本文と訂正を基底として扱い、別表現へ書き直していない。
- 観測事実、認可された拘束、仮説、未決を混同していない。
- 根拠のない要求、推測による選択、未確認事項の形式的な解消がない。
- 判断が必要な選択を判断主体へ返した。
- 実行者が任された下位実装と、依頼者へ戻すべき判断を分けた。
- 不足時に停止し、再開条件を示した。
