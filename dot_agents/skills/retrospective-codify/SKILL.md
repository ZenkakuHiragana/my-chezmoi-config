# 振り返りの規則化

作業終盤に「最初に知っていれば遠回りしなかった」知見を取り出し、静的検査、AGENTS.md、スキルのどこへ残すべきか判定する。
承認なしに書き出さない。まず提案だけ返し、ユーザーが採用した項目だけ反映する。

## 手順

1. 最初の失敗、最終解、橋渡しの気付きを対応付ける。
2. 「最初に知るべきだったこと」を命令形で 1 から 3 文にする。
3. 適用範囲、静的検出可能性、手順性、既存成果物への依存を判定する。
4. 既存スキル、AGENTS.md、規則ファイルを検索して重複確認する。
5. 出力先を選ぶ。
6. 提案だけ返す。ユーザーが採用を指示した項目だけ書き出す。

## 重複確認

気付きから 2 から 3 個の検索キーを作る。

最低限、既存スキル、共通規則、プロジェクト規則置き場を確認する。

分類:

- `新規`: 既存なし
- `既存追記`: 既存を補完する
- `既存と重複`: 完全カバー済み
- `判断保留`: 重複判定できない

## 出力先

| 条件                             | 出力先                      |
| -------------------------------- | --------------------------- |
| 構文レベルで機械検出可能         | `ast-grep` / 静的検査ルール |
| 言語横断・ツール横断の短い一般則 | AGENTS.md                   |
| 手順、判断、テンプレートが必要   | スキル                      |
| 単一作業固有                     | 採用しない                  |

静的検出できる内容なら、プロンプト本文より静的検査を優先する。

## 提案形式

```markdown
## 振り返り

### 学び 1: <短いラベル>

- 最初の失敗: <1 行>
- 最終解: <1 行>
- 気付き: <1 行>

## 提案

採用候補:

- [静的検査] <規則>: <1 行>（学び 1 由来）
- [スキル追記] <スキル>: <1 行>（学び 1 由来）
- [スキル新規] <スキル>: <1 行>（学び 1 由来）
- [規則] AGENTS.md: <1 行>（学び 1 由来）

重複検出（提案不要）:

- 学び 1: 既存 <スキル/規則> の <節/行> が完全に覆う

不採用:

- 学び 1: <理由>
```

空の節は省く。
採用候補がない場合は、末尾を `採用候補なし。記録目的でレビューしてください。` にする。

## 危険な兆候

- プロジェクト固有の知見を汎用スキルに入れる。
- 承認前に書き出す。
- 静的検査で扱える内容を自然言語ルールだけにする。
- 薄い学びを無理に残す。
- 重複確認を省く。
- 最初の失敗を省く。

## 完了チェック

- 失敗と最終解を対応付けた。
- 重複確認をした。
- 出力先を分類軸で選んだ。
- 提案と書き出しを分けた。
- 採用候補、重複、不採用を明示した。
