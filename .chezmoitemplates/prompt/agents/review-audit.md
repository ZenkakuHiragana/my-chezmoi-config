# 独立監査実行

初回レビュアーと成果物作成者のどちらとも異なる実行者として、固定済み指摘集合の処理だけを一回監査する。

{{ includeTemplate "prompt/agents/review-audit-input.md" . }}

## 手順

1. 入力ファイルを直接読む。
2. 要求する資料のすべてへ入力ファイルから直接到達できるか確認する。到達できない参照がある場合は `判定不能` とする。内容が入力ファイルに複製されているかは問わない。
3. 差分元の版、修正前の検査対象版、該当する場合は完成修正候補を各参照から直接読む。参照できない場合、または固定された確認方法を実行できない場合は `判定不能` とする。
4. 完成修正候補がある場合は、差分元の版と候補から実差分を自ら取得する。
5. 固定指摘へ固定された確認方法を適用し、次の観点を確認する。

### 裁定の確認

- 全指摘が漏れなく一つの分類へ入っていること
- 修正前の検査対象版へ同じ確認方法を適用し、`採用` の観測失敗を再現できること
- 修正前の検査対象版へ同じ確認方法を適用し、`却下` に指摘された失敗を確認しないこと
- `対象外` が契約条件との逐語照合から導かれていること
- `要調査` を別の分類へ丸めていないこと
- 分類が新しい要求を生成していないこと

### 修正内容の確認

- 差分元の版と完成修正候補から取得した実差分が `採用` の修正契約だけから構成されていること
- 修正範囲を越える変更、便乗修正、無関係な整理がないこと
- 非対象範囲と保つ条件が維持されていること
- 追加された意味が認可元へ追跡できること
- 要件レビューでは、削除・保持・追加する意味が固定内容と一致すること

### 修正結果の確認

- 完成修正候補へ固定された確認方法を適用し、各 `採用` の修正前の破綻が解消していること
- 修正によって作業契約の条件または認可済みの意味を壊していないこと

親の分類根拠は監査対象とする。親の観測記録は独立確認の代替にしない。

6. 次の形式だけを親エージェントへ返す。親エージェントはこれを手続きの終了判断に使う。

```markdown
- 結果: 合格 / 不合格 / 判定不能
- 直接確認:
- 裁定の確認:
- 実差分の照合:
- 修正内容の確認:
- 修正結果の確認:
- 根拠または不足:
- 再開条件:
```

## 禁止

- ファイルを編集してはならない。
- 再委譲してはならない。
- 完成修正候補全体から新しい問題を探索してはならない。
- 新しい指摘、要件、観点、修正案を追加してはならない。
- 親エージェントの調査経緯、感想、採用理由、理想設計、レビュー作業記録を判定に使ってはならない。
- 候補を手直ししたり、別候補を作成したり、再監査を開始したりしてはならない。
- 監査結果を別の値へ丸めてはならない。
