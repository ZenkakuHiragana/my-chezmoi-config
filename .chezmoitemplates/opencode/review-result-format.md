固定した検査項目を全件記録し、検査完了主張と指摘を分離する。無欠陥主張は扱わない。

### 検査結果

各検査項目を次のいずれかで判定する。

- `破綻確認`: 指定した確認方法で失敗を観測した。
- `反例未確認`: 指定した確認方法を完了し、失敗を観測しなかった。
- `判定不能`: 確認を試みたが、情報、環境、権限の不足により結果を決められなかった。

`判定不能` は検査被覆の欠損である。指摘または調査待ちの指摘へ変換してはならない。

### 検査単位

- `code-review`: 開始前に固定した各観点 / プロファイル
- `requirement-review`: 各明示要求、各契約条項、各受け入れ条件、各範囲行
- `japanese-doc-review`: 開始前に選択した各観点

各検査項目を検査被覆表へ一度だけ記録する。検査中に項目を追加してはならない。

### 出力形式

```markdown
# <レビュースキル> 結果

## 入力

- 対象:
- 基準版または正本:
- 作業契約:
- 固定した検査項目:

## 検査被覆

| 検査ID | 検査項目 | 確認方法 | 結果 | 根拠または判定不能理由 |
| ------ | -------- | -------- | ---- | ---------------------- |

## 指摘

### 指摘-001

- 検査ID:
- 対象箇所:
- 破綻:
- 根拠:
- 確認方法:
- 侵害する条件: <受け入れ条件 / 不変条件 / 該当なし>

## 判定

- 状態: 合格 / 不合格 / 判定不能
- 破綻確認:
- 反例未確認:
- 判定不能:
```

### 指摘生成

- `破綻確認` からだけ指摘を生成する。
- 指摘が0件なら `指摘` へ `なし` と書く。
- 1件の独立原因を1件の指摘として記録する。
- 同じ確認方法を修正前後で使える形にする。
- 好み、一般論、完全化、未確認の懸念を指摘にしてはならない。

### 単位判定

- `破綻確認` が1件以上なら `不合格` とする。
- `破綻確認` が0件で `判定不能` が1件以上なら `判定不能` とする。
- 全項目が `反例未確認` なら `合格` とする。
- 状態と3値の件数を検査被覆表へ一致させる。
