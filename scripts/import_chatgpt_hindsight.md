# ChatGPT の会話と画像を Hindsight に取り込む

`import_chatgpt_hindsight.py` は、展開済みの ChatGPT 会話フォルダから本文と添付画像を取り出し、Hindsight Retain APIへ送る。Python 3.10以上の標準ライブラリだけを使う。Hindsight 0.10.2のAPIと保存形式を対象とする。

## 変換

このリポジトリの作業ディレクトリで実行する。

```text
python -B scripts/import_chatgpt_hindsight.py convert ".opencode/work/ChatGPT_AI系質問" ".opencode/work/ChatGPT_AI系質問2"
```

入力フォルダ直下の各会話の `conversation.json` を読み、`current_node` から親をたどって選択中の分岐を取り出す。可視のuser／assistant発言を採用し、ツールの出力・呼び出し、内部推論、非表示の発言は含めない。本文の要約や内容分類は行わない。

本文には `## User` と `## Assistant` の見出しを付け、各発言の日時とメッセージIDをHTMLコメントで添える。引用記号を含む発言本文を、その順番で保持する。会話本文をJSON配列にする方式ではない。

画像は元JSONの添付参照・名前を基に、同じ会話の `images/` から解決する。`conversation.md` の保存名と発言位置も照合の補助に使う。画像は本文中の添付位置へ、Retain APIの `image` ブロックとして入れる。実ファイルをBase64で符号化し、再圧縮・縮小・文字起こしはしない。保存時の再符号化によりバイト数が変わった画像も、対応を確認できれば採用する。欠落画像は省いて記録する。対応が曖昧な画像は推測で選ばず、変換エラーとして返す。

同じ会話IDのログが複数あれば `update_time` が新しい方を採用する。同値なら `__local_exported_at`、最後にファイルの更新時刻で比較する。APIの代表日時は最後の可視発言の日時とし、なければ会話の更新日時・作成日時を使う。いずれもなければ `unset` を送る。

変換結果の既定の保存先は `.opencode/work/chatgpt-hindsight-import/converted-markdown/`。`manifest.json` に採用元、重複、欠落画像、使用画像、未使用画像を記録する。要求本文はハッシュ値を名前にしたJSONファイルへ保存する。この段階ではサーバーやモデルへ送信しない。別の出力先は `--output` で指定できる。

## 送信

まず一会話だけを指定する場合:

```text
python -B scripts/import_chatgpt_hindsight.py upload --bank dev --only chatgpt:<元の会話ID>
```

変換結果の全会話を送る場合:

```text
python -B scripts/import_chatgpt_hindsight.py upload --bank dev
```

1会話を1文書・1入力として非同期で送る。`document_id` は `chatgpt:<元の会話ID>`。画像の有無にかかわらず、`items` は1要素、その `content` に話者付き本文と画像を順番に並べる。発言ごとや画像ごとに別の文書を作らない。

出所タグは `source:chatgpt` と `collection:chatgpt-ai`。collection名は変換時の `--collection` で変更できる。元の会話ID・タイトル・入力フォルダ名をmetadataに残す。strategy、mission、`observation_scopes` は指定せず、対象bankの設定を使う。本スクリプトはbankの設定変更や削除を行わない。

既定の接続先は `http://localhost:8888`。`--api-url` または環境変数 `HINDSIGHT_API_URL` で変更できる。認証が必要なら `HINDSIGHT_API_TOKEN` を環境変数に設定する。トークンは引数や変換結果に保存しない。本文と画像は対象サーバーが利用するモデルへ送られ、利用料金や利用枠を消費する。画像の抽出には画像対応のモデル接続が必要である。

現行の変換結果は `schema_version: 3`。旧形式の結果や、変換後に変更された要求ファイルは送信しない。各要求の受付応答を受けたら、処理完了を待たずに次の会話を送る。HTTP要求は一つずつ送るが、未完了の会話数で送信を止めない。受け付けた会話はHindsightの永続的な待ち行列に入り、実際の処理数はサーバー側の設定で制御される。`--max-in-flight` は廃止した。

全会話の受付を終えてから、処理完了と保存内容を確認する。`--request-timeout` はHTTP要求ごとの待機秒数で、既定1800秒。非同期処理全体の待機期限ではない。

## 完了確認と再実行

非同期処理のoperation IDは、要求内容・接続先・bankから決定的に作る。受付応答を受け取れなかった場合や途中で中断した場合、同じ要求の再実行では既存処理を確認する。完了済み・保留中・実行中の要求を再送せず、まだ受け付けられていない会話だけを送る。以前の4会話制限版と同じoperation ID・進捗ファイルを使うため、その途中から再開できる。サーバーが処理情報を削除した場合は再受付になり得るが、文書IDは変わらない。同じ文書IDへのRetainは既定で置換処理となる。

処理が完了したら文書を読み戻し、次を照合する。

- 文書IDと元の会話ID。
- 話者・日時を含む本文全体と、画像参照の位置・出現回数。
- 保存画像のSHA-256ハッシュ。

Hindsight 0.10.2は、保存本文中の画像をSHA-256の先頭12桁を含む参照記号に置き換え、その前後を空行で区切る。この保存形式と照合するため、別のサーバー版で保存形式が変わると検査が失敗する可能性がある。

結果は出力先の `upload-*.json` に記録する。サーバーで完了済みでも保存内容を再照合するまでは `awaiting_verification` と記録し、照合後に `completed` とする。過去の処理が完了済みでも、文書が削除されていれば保存確認に失敗し、完了とは報告しない。その場合は自動で再送しない。失敗した処理も自動再試行せず、原因とサーバーの状態を確認してから扱う。

スクリプトが確認するのはRetainの完了と本文・画像の保存までである。後続の統合処理や、抽出記憶・検索回答の正確さは別に確認する。過去の試験では、画像付きの保存・抽出が完了しても、引用投稿者をユーザー本人と取り違える記憶が生成された。処理成功だけを、記憶が正しい証拠にはしない。

## 検査

```text
python -B -m unittest discover -s scripts -p test_import_chatgpt_hindsight.py -v
```

分岐と可視発言の選択、最新ログの選択、話者と日時、画像の対応・欠落・出現位置、保存内容の照合、非同期処理の失敗と再実行を検査する。検査自体は実サーバーやモデルへ接続しない。一時ファイルは `.opencode/work/` 以下に置く。
