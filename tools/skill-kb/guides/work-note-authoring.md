# 作業メモの執筆規則

作業メモは、作業中に明らかになった暗黙の前提、未文書化の観測結果、再調査に費用がかかる調査結果、再利用できる探索経路を残す低権威の補助情報である。

## 権威

- 作業メモは、正式な仕様、設計資料、公式資料、現在のコード、ユーザーの現在の明示判断より権威が低い。
- 正本と矛盾する場合は正本を優先する。
- 重要な判断へ使う前に、根拠、適用範囲、反証条件、再確認条件を現在の状態へ照合する。
- 作業メモを根拠として正式な情報源を自動更新しない。

## 保存までの流れ

1. 将来の別タスクでも利用価値がある知見が明らかになったら、完了応答で「知見候補」を提示する。
2. 候補には、主張、根拠、適用範囲、その範囲まで言える理由、反証または再確認の条件、対応する既存情報源、新規作成または既存更新の案を含める。
3. 人間が作成または更新を明示的に承認した後に限り、`create_work_note` または `update_work_note` を呼び出す。

- 候補の提示だけでは作成も更新もしない。
- 保存価値のある候補がない場合、空の候補欄を出さない。

## 情報源との対応

- `source_names` は、現在の統合済みカタログに存在する情報源名を1件以上持つ。
- この対応は、どの情報源を調査するときにメモを検索するか、将来どの正式資料への反映を検討できるかを示す。自由なタグや分類階層ではない。
- 一つのメモを複数の情報源へ対応づけてよい。
- 作業メモ自体を `KNOWLEDGE.yml` の独立した情報源にしない。
- 対応先に迷う場合は、その知見が将来反映されうる正本を持つ情報源を選ぶ。

## 保存先と検索範囲

保存先は、対応する情報源の最も狭い範囲で決まる。

- 全ての対応先がグローバル情報源の場合: グローバル保存先
- 一つでもプロジェクト情報源を含む場合: プロジェクト保存先

検索範囲は次のとおりである。

- グローバル情報源: グローバル保存先と現在のプロジェクト保存先
- プロジェクト情報源: 現在のプロジェクト保存先だけ

- 一つのメモを両方へ複製しない。
- `file_name` は、現在見えるグローバル保存先とプロジェクト保存先の間で一意にする。
- 実際の保存先パスは資料 `skill-kb://state/catalog` で確認する。

## 各項目の書き方

`file_name` はメモの識別子である。内容を推測できるハイフン区切りの `.md` 名にする。ディレクトリ区切り、絶対パス、パストラバーサルは拒否される。

| 項目 | 書く内容 |
| --- | --- |
| `title` | 一覧から内容を識別できる表題 |
| `claim` | 将来の判断へ利用する解釈または一般化 |
| `evidence` | 資料、観測結果、実行結果など追跡可能な根拠 |
| `reasoning` | その根拠から `claim` を導ける理由 |
| `scope` | 主張を適用できる対象、版、条件、環境 |
| `scope_basis` | その範囲まで一般化でき、外へ広げない理由 |
| `defeaters` | 主張を撤回すべき反例、条件、観測結果 |
| `revalidate_when` | 版、環境、実装、前提など根拠を再確認すべき変化 |

- `evidence` と `claim` を混ぜない。確認した事実は `evidence` へ、解釈は `claim` へ書く。
- 確認していない対象、版、環境を `scope` に含めない。
- `defeaters` と `revalidate_when` を形だけの文で埋めない。撤回条件を書けない主張は、まだ保存しない。

## 観測・再現情報

実験、実行結果、計測、再現操作に基づくメモは `observation` も指定する。

- 必須: 対象、対象の版または commit、実行環境、前提条件、方法、入力、観測結果
- 任意: 生の成果物、反復回数または再現状況、既知の限界
- `observed_result` には解釈を加えず、実際に確認した内容を書く。
- 観測に基づかないメモでは `observation` を省略する。空の節を作らない。

## 更新

- 呼び出す前に `read_work_note` で現行全文を確認する。
- `change_reason` に、更新の理由と何が変わったかを書く。
- `source_names` は現行メモと同じ集合を指定する。対応する情報源は更新で変更できない。
- 存在しないメモは作成されない。作成と更新を兼ねる操作はない。
- 更新前の全文は保存先の `.history/<file_name>/` へ退避され、通常検索の対象にならない。

## 検索と読取り

- `grep_work_notes` は、指定した情報源に対応する現行メモの全文を正規表現で検索し、ファイル名だけを返す。一致行、抜粋、要約は返さない。
- 一致なしは正常な空結果である。
- 返却は100件が上限で、超過時は `truncated` が真になる。`pattern` を絞って再検索する。
- 利用するときは `read_work_note` で全文を読む。ファイル名から内容を推測しない。
