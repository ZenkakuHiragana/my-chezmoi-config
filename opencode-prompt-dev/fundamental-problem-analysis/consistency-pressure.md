# 一貫性圧による問題像の固定

## 位置づけ

本稿は、`../fundamental-problem-map.md` で定義した**一貫性圧**の機序を詳述する。

一貫性圧は、生成器が文脈全体と整合する出力を優先し、未解決の unknown を周囲と整合する値で無音に埋める性質を指す。本稿は新しい根源課題を追加しない。一貫性圧が、単発の補完に留まらず、形成済みの問題像を固定し、反証後も維持させうる過程を整理する。

本稿が扱わないもの:

- そもそも何を確認対象として取り上げるべきかという**認識対象の発見**
- 認識対象に対して、どの情報源をどの順序でどう検索するかという**根拠収集**
- 原因候補や中間成果を得た時点で作業を終える **premature closure 一般**
- 問題解決の価値を判定する一般的な評価基準

根拠収集は `evidence-retrieval.md`、問題解決の評価は `problem-solving-evaluation.md` に分離する。

## 中心命題

LLM が早期に形成した問題像や完成像は、単なる暫定仮説として残るとは限らない。

その仮説に沿って探索、要件化、設計、実装、説明が生成されると、それらの成果物が後続文脈へ再入力される。すると、最初は一つの補完にすぎなかった内容が、互いに整合する複数の成果物によって支持された既成事実のように振る舞い始める。

```text
未確認の空白
  ↓
文脈と整合する値で補完
  ↓
その補完に沿って探索・要件・設計・実装
  ↓
成果物が後続文脈へ再入力
  ↓
補完を前提とした世界像が強化
  ↓
反証が入っても既存世界像へ吸収
```

ここで主張するのは、モデル内部で意識的に「先に結論を決めて後付けで正当化する」処理が行われていることではない。

観測上重要なのは、次の性質である。

> **早期に生成された補完が後続生成物の前提となり、その生成物がさらに前提を補強することで、問題像の撤回コストが上がりうる。**

## 固定が生じる過程

### 1. 空白を補完する

依頼、コード、仕様、環境について未確認の部分があるとき、モデルは一般的な慣習、学習済み知識、周囲の文脈からもっともらしい値を補う。

たとえば、

```text
resource は発見しにくいかもしれない
→ 別の導線も必要だろう
```

という補完が生じる。

この時点では、まだ撤回可能な仮説である。

### 2. 補完を成果物へ展開する

一度採用された補完は、その後の作業へ伝播する。

- 要件に入る
- 設計上の責務になる
- コードとして実装される
- テスト対象になる
- 文書で説明される

すると、同じ補完を前提とした複数の成果物が相互に整合する。

この整合性は、補完の正しさを独立に証明しない。しかし後続の推論から見ると、既に存在する要件、設計、コード、説明が同じ方向を向いているため、その出発点を疑う契機が弱くなる。

### 3. 成果物が後続文脈として再入力される

生成済みの要件、計画、設計、実装、説明は、その後のターンや別工程の入力になる。

ここで、最初の仮説と、その仮説から派生した成果物の区別が失われやすい。

```text
仮説 A
  ↓
A を前提とした要件
  ↓
A を前提とした設計
  ↓
後続処理から見ると「既存の要件と設計が A を要求している」
```

結果として、A は「まだ確認していない推測」から「現在の作業世界の構成要素」へ昇格する。

### 4. 問題像が探索と解釈を支配する

形成済みの問題像は、後続の情報取得にも影響する。

本来は、

```text
暫定仮説
→ 区別に必要な事実を取得
→ 事実によって仮説の重みを変更
→ 必要なら問題像を変更
```

と進むべきである。

しかし、問題像 A が既成事実化すると、

```text
問題像 A
→ A に関係する情報を探索
→ A の語彙で結果を解釈
→ A に沿った成果物を追加
→ A がさらに強化
```

という自己強化が成立しうる。

したがって、検索精度の改善だけではこの故障を解消できない。

**完全に正しい情報を取得しても、その意味を既存の問題像へ吸収すれば、誤った問題像は維持される。**

### 5. 反証後も整合性を回復する

固定が最も明確に現れるのは、元の前提が反証された後である。

期待した更新は、

```text
仮説 A
→ A を前提に成果物を作る
→ A が反証される
→ A と A に依存する成果物を撤回・修正する
```

である。

しかし実際には、

```text
仮説 A
→ A を前提に成果物を作る
→ A が反証される
→ 成果物を維持できる別理由 B を生成する
```

という形で整合性が回復されうる。

この場合、現実との衝突自体は発生している。失敗しているのは、**衝突の結果が問題像の撤回へ伝播すること**である。

## 仮説の文章化と固定

問題像を早期に文章として完成させることは、この固定を強める可能性がある。

```text
曖昧な内部仮説
  ↓
首尾一貫した文章へ整形
  ↓
要件・計画・説明などの中間成果物になる
  ↓
後続処理が正式な入力として扱う
```

文章化そのものが問題なのではない。

問題は、**較正前の仮説と、根拠によって較正された確定事項を、同じ強さの成果物として扱うこと**である。

問題像を外部化する場合でも、少なくとも次の状態差は保たれなければならない。

```text
支持された仮説
  → 維持する

反証された仮説
  → 捨てる、または修正する

新しい拘束
  → 既存の問題像へ統合する

未決
  → 未決のまま保つ
```

重要なのは成果物同士を常に整合させることではなく、**現実との衝突に応じて、既存成果物の前提を壊せること**である。

## `fundamental-problem-map` への含意

`../fundamental-problem-map.md` では、成果物や主張を反証可能な対象と突き合わせる**衝突の予定**を中心法則としている。

本稿から得られる追加条件は次である。

> **衝突は発生するだけでは足りない。衝突の結果が、その主張に依存する問題像・要件・設計・実装を撤回または変更できる経路へ接続されなければならない。**

一貫性圧の下では、衝突結果さえ既存フレームを維持する材料へ変換されうる。

したがって、P4への介入を評価するときは、

- 外部の現実へ接触したか
- 反証を取得できたか

だけでなく、

- 反証によって既存の問題像が実際に変更されたか
- 反証された前提に依存する成果物が残存していないか

までを見る必要がある。

## 結論

一貫性圧は、unknown を一度もっともらしく補完するだけの現象ではない。

補完が成果物へ展開され、その成果物が後続文脈となり、探索と解釈を同じ方向へ偏らせることで、問題像は自己強化されうる。さらに反証後も別の理由を生成して整合性を回復できるため、正しい情報を取得すること自体は問題像の更新を保証しない。

したがって、一貫性圧に対する重要な設計条件は、**仮説の撤回可能性を保存し、現実との衝突を既存問題像の変更まで伝播させること**である。
