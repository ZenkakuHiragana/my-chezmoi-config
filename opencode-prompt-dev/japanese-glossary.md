# 日本語用語集

プロンプト階層の規則群で使われる用語を、統一した語彙で定義する。
この用語集は管理資料であり、システムプロンプトには展開されない。
各ファイルの本文は、この用語集に依存せず単体で伝わる語を使う。

## 語彙の原則

- 機械的に照合される値・ID のうち、外部コード（テンプレート変数、ファイル名、スキル名）と一致するものだけ英語のまま維持する。文脈状態（confirmed 等）と不足の分類（user_decision 等）は英語のままとする。
- それ以外の制御語彙は、バックティックで囲んだ日本語で表す（文字列照合は言語非依存なので、英語である必要はない）。
- 区別する必要のない概念は、1つの語に統一する。同じ概念を別の語で呼ばない。
- 定義が必要な語は命名が悪い。語は単体で伝わるものにする。

## 1. 手続きと段階

| 用語         | 意味                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| 要件レビュー | 要件契約候補または派生契約を、意味上の義務の有限集合として検査すること                     |
| 初回レビュー | review-orchestration の第1段階。固定した検査集合を観点別に展開して実行する                 |
| 独立監査     | review-orchestration の第2段階。新規のエージェントが、固定した指摘集合の処理だけを確認する |
| 裁定         | 親が指摘を 採用 / 却下 / 要調査 / 対象外 の4値へ分類すること                               |
| 採否         | 監査結果に基づき、監査対象（完成修正候補または元の対象）を採用するか不採用にするか         |
| レビュー対応 | 凍結した指摘集合を現成果物と作業契約へ1回だけ再現し、4値分類と修正契約を決めること         |
| 準備完了判定 | 実作業の前に文脈の充足を判定し、準備完了記録と要件契約を産出すること                       |

## 2. 主体

| 用語                 | 意味                                                                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 親                   | サブエージェントを起動し、手続きを所有・運営するエージェント。入力の固定、裁定、候補作成、採否を担う。呼び出し側、成果物作成者、契約作成者の区別はしない |
| 新規のエージェント   | 手続き内のどのタスクも引き継がないで起動したエージェント。独立監査の実行者はこれに限る                                                                   |
| 実行者               | レビューまたは監査を割り当てられたサブエージェント                                                                                                       |
| 汎用サブエージェント | general-fast / general-strong                                                                                                                            |
| 専用エージェント     | requirement-reviewer / review-audit                                                                                                                      |

## 3. 入力と成果物

| 用語               | 意味                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入力               | スキル・サブエージェントが要求する情報一式。本文に直接書く場合も、ファイルパスで渡す場合も同じ。固定入力、レビュー束、監査束、使用する資料、外部化済み入力はすべてこれに統一する |
| 内容識別子         | 入力・版の同一性を照合する識別子。実行者が実物と一致を確認する                                                                                                                   |
| 制御入力           | 手順、禁止、出力形式などの指示。レビュー対象の入力と混ぜてはならない                                                                                                             |
| 依頼引用           | レビュー対象のユーザー要求と後続訂正の逐語引用                                                                                                                                   |
| 判定根拠版         | レビュー判定の根拠となる資料の版                                                                                                                                                 |
| 要件契約候補       | レビュー前の契約ドラフト。レビューを通過して要件契約になる                                                                                                                       |
| 要件契約           | レビューを通過し正式に固定された契約                                                                                                                                             |
| 準備完了記録       | context-clarification の出力。文脈層の状態、不足、判定結果等                                                                                                                     |
| 完成修正候補       | 採用した指摘の修正契約だけから作られた隔離済み成果物                                                                                                                             |
| レビュー対応成果物 | review-response の出力。4値分類とレビュー対応契約                                                                                                                                |
| 手続き記録         | review-orchestration の手続き記録書式                                                                                                                                            |

## 4. 検査と観点

| 用語     | 意味                                                               |
| -------- | ------------------------------------------------------------------ |
| 検査集合 | 固定した検査の集まり                                               |
| 検査単位 | レビュースキルが固定する検査の単位（例: RR-OBL-\*、RR-CONTRACT-1） |
| 検査項目 | 検査単位内の個別項目                                               |
| 全検査   | 検査の全部。必須検査という別語は使わない                           |
| 観点     | レビュースキルが提供する関心（関心 / プロファイル）ごとの分割単位  |
| 検査ID   | 検査単位を特定するID（RR-OBL-\<連番\>、RR-CONTRACT-1。英語のまま） |
| 検査被覆 | 検査の実施状況（検査被覆表）                                       |
| 確認方法 | 検査や指摘を再現する手順                                           |

## 5. 結果の値

| 用語                             | 意味                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 反例未確認 / 破綻確認 / 判定不能 | 検査項目の3値。破綻確認は失敗を観測した、反例未確認は失敗を観測しなかった、判定不能は情報・環境・権限の不足  |
| 合格 / 不合格 / 判定不能         | 手続きの結果（旧 pass / fail / indeterminate）。検査単位の状態としての合格・不合格は廃止し、件数から判断する |
| 判定結果                         | 準備完了判定の値。合格 / 仮定付き合格 / 不合格（旧 verdict / pass_with_assumption）                          |
| 採用 / 却下 / 要調査 / 対象外    | 指摘の4値分類（旧 accepted / rejected / needs-investigation / out-of-scope）                                 |
| 指摘                             | 破綻確認から生成される。検査ID、対象箇所、破綻、根拠、確認方法、侵害する条件を持つ                           |
| 侵害する条件                     | 指摘が侵害する条件。種類（明示要求/範囲/受け入れ条件/不変条件/該当なし）＋IDまたは逐語引用                   |

## 6. 文脈整理の概念

| 用語                                                                                       | 意味                                                                                            |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 作業段階                                                                                   | 診断/選択肢比較/方針決定/計画/実装/レビュー/レビュー対応/対応後監査                             |
| 文脈層                                                                                     | 依頼/サブシステム/ワークスペース/外部基盤の4層                                                  |
| 文脈状態                                                                                   | confirmed / not_needed / missing / blocked（英語のまま。状態値として照合）                      |
| 不足の分類                                                                                 | user_decision / repo_derivable / subsystem_derivable / public_fact / contract_gap（英語のまま） |
| 判断と認可                                                                                 | 判断の確定状態と認可元の表                                                                      |
| 発見境界                                                                                   | 基準化/判断/実現/実行/評価の五境界                                                              |
| 意味上の義務 / OBL-\<連番\>                                                                | 依頼と確認済み制約を分解した義務                                                                |
| 明示要求 / 範囲 / 受け入れ条件 / 不変条件 / 保つ条件                                       | 要件契約の欄。指摘の侵害する条件の種類も同じ語を使う                                            |
| 必要な結果 / 対象範囲 / 結果を生む実経路 / 観測する結果と判別対象 / 利用者または情報所有先 | 要件契約の欄                                                                                    |
| 作業契約                                                                                   | 完了までに満たす結果、制約、確認方法をまとめた実行契約                                          |
| 作業枠                                                                                     | 今回の依頼を処理するための枠。返すもの、制約、必要な根拠、確認方法をまとめる                    |

## 7. 作業票の項目（日本語化）

| 旧（英語）        | 新（日本語） | 意味                                                                                        |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------- |
| work_class        | 作業分類     | 作業の広さと不確実さ。値: 単発 / 限定 / 広域                                                |
| mode_constraint   | 実行モード   | 書き込み可否。値: 読み取り専用 / 書き込み可                                                 |
| goal              | 目的         | 到達点                                                                                      |
| scope             | 範囲         | 担当範囲                                                                                    |
| inputs            | 入力         | 親が把握している文脈                                                                        |
| read_set          | 読取可能     | 自分で読める資料のリスト。ファイル一覧（例: 読取可能: `./AGENTS.md`）が続くことで意味が通る |
| write_set         | 編集可能     | 編集してよいファイルのリスト。ファイル一覧が続くことで意味が通る                            |
| constraints       | 制約         | 保つべき条件                                                                                |
| must_not_do       | 禁止事項     | 明示的な禁止                                                                                |
| evidence_required | 必要な根拠   | 主張・判断ごとの根拠の種類                                                                  |
| output_schema     | 出力形式     | タスク固有成果物の形式                                                                      |
| verification_hint | 検証のヒント | 実行してほしい確認事項                                                                      |
| stop_conditions   | 停止条件     | 止めて返す時点                                                                              |
| join_instructions | 統合方法     | 親がどう取り込むか                                                                          |

## 8. 旧語との対応（表記揺れの解消記録）

| 旧語                                                                           | 新語                                                   |
| ------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 固定入力 / レビュー束 / 監査束 / 外部化済み入力 / 使用する資料 / 束 / パケット | 入力                                                   |
| pass / fail / indeterminate                                                    | 合格 / 不合格 / 判定不能                               |
| verdict / pass_with_assumption                                                 | 判定結果 / 仮定付き合格                                |
| accepted / rejected / needs-investigation / out-of-scope                       | 採用 / 却下 / 要調査 / 対象外                          |
| 親 / 呼び出し側 / 成果物作成者 / 契約作成者                                    | 親（独立性が必要な箇所は「新規のエージェント」で表現） |
| 検査単位の状態（合格 / 不合格 / 判定不能）                                     | 廃止。検査被覆の件数から判断する                       |
| 必須検査                                                                       | 全検査                                                 |
| 作業票のフィールド名（work_class 等）                                          | 日本語名（7節参照）                                    |
