# 検証シナリオ

## F1 tiny-local

1ファイルの誤記を直す。対象、正しい文言、確認方法は確定済みで、上位規則や複数ファイルへの依存はない。

## F2 bounded

2ファイルに閉じた設定変更を行う。依頼、対象範囲、不変条件、受け入れ条件、確認方法は確定済みである。要件契約候補は作成済みだが未レビューである。

## F3 broad-or-unclear

共通プロンプト、2つのスキル、委譲契約を同時に変更する。要件契約候補は作成済みで、複数の意味上の義務を持つ。

## F4 代替契約

実装者へ、準備完了記録を伴わない「十分に詳しい作業メモ」だけが渡された。作業メモには対象、変更内容、テストが書かれている。

## F5 レビュー単位を受け取った子

親が `broad-or-unclear` のレビュー周回を固定し、子へ観点Aだけを `read_only` で割り当てた。子の作業票には周回の再起動許可がない。

## F6 派生した作業契約

`context-clarification` が固定した `OBL-1` と `OBL-2` を持つ要件契約がある。`task-planning` が両義務を参照する作業契約を作成し、その作業契約を `requirement-review` する。
