# requirement-review-v3: 検証条項とレビュー入力所有先の回帰フィクスチャ

要件契約テンプレート（`context-clarification` の出力契約）、`requirement-reviewer` の入力契約と検証条項規則が、次の性質を保っているかを回帰検証する。

- 契約作成時、観測欄に依頼が名指ししていない手段（操作手順、コマンド列、正規表現、バージョン、実行者指定）が流入しない
- 判別対象が合否主張として書かれる（失敗原因の帰属先にならない）
- レビューが手段記載を指摘でき、記載の対応有無の確認に還元されない
- 存在ゲート（検証不能な義務の不合格）と過検出防止（手段が書かれていないことだけを破綻にしない）が両立する
- 要求の意味を決める環境・実経路と、依頼が名指しした確認手段は削られない
- 候補レビュー前の入力情報が要件契約候補に含まれ、準備完了記録へ依存しない

## 構成

| ファイル                    | 種別                 | 主な標的                                                                              |
| --------------------------- | -------------------- | ------------------------------------------------------------------------------------- |
| `s1-authoring-ci.md`        | 作成系・典型         | 手段混入の抑制と環境要求（Windows 実機）の保持の両立                                  |
| `s2-authoring-readme.md`    | 作成系・境界         | 揮発する件数（スクリプト7個）を合否条件へ固定しない                                   |
| `s3-review-means-laden.md`  | レビュー系           | 手段記載4種（行数確認、grep バージョン、Node.js 22＋別実行者、stderr 正規表現）の検出 |
| `s4-review-unverifiable.md` | レビュー系・回帰     | 検証不能義務の不合格化＋手順なし義務を破綻にしない                                    |
| `s5-authoring-pdf.md`       | 作成系・hold-out     | 依頼が名指しした確認手段（印刷プレビュー、既存回帰テスト）の保持                      |
| `s6-review-mixed.md`        | レビュー系・hold-out | 手段記載の指摘と環境要求（Windows 実機・WSL 不可）の保持の分離                        |
| `scoring.md`                | 採点                 | 要件チェックリスト、採点規則、版分離規則                                                |

## 使い方

1. 検証したい版の規則4ファイル（`context-clarification/SKILL.md`、`requirement-reviewer` の入力契約（`.chezmoitemplates/opencode/agents/requirement-reviewer-input.md`）、サブエージェント定義（`dot_config/opencode/agents/requirement-reviewer.md.tmpl`）のレンダリング結果、`requirement-reviewer-discipline.md`）を中立名で実行ディレクトリへ置く。
2. 各シナリオの「作業」節を盲検の新規実行者に実行させる。実行者には採点基準・変種ラベル・比較の存在を伏せる。環境側の同名スキルの起動を禁止する。
3. 実行者と分離した採点者が `scoring.md` で採点する。採点は意味単位で行い、逐語一致を要求しない。
4. 判定: `scoring.md` の v3 判定規則に従う。[critical] を落とす規則版は不合格。v2 の結果は比較基準へ使わない。

運用上の停止規則（`20260803-1537` 対応）: 反復上限を計画で固定し、装置故障（実行者が規則・素材を参照できない等）を候補の失敗に数えず、同一手続き内での規則手直し・再実験をしない。

## 較正記録

- v2 の較正結果は v3 の回帰証拠へ混ぜない。v3 は候補レビュー入力の所有先変更を含むため、同じフィクスチャ、配送形式、採点基準で別版として実行する。

## 限界

- v3 の実行者・採点者・実行結果は未確定。実験前に対象規則、配送形式、シナリオ、採点基準、停止条件を固定する。
- モデル・ハーネス更新後は、v3 も版ごとに再確認する。
