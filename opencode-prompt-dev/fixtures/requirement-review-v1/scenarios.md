# 検証事例

## S1 明示要求の欠落

依頼:

- WindowsとLinuxで同じコマンドを生成する。
- 既存設定を変更しない。

契約:

- 達成結果: Windows用コマンドを生成する。
- 対象範囲: 生成器だけを変更する。
- 受け入れ条件: Windowsで生成結果を実行できる。
- 確認方法: Windowsで生成と実行を確認する。

## S2 無認可条項

依頼:

- JSONの重複IDを報告する。

契約:

- 達成結果: 重複IDを報告する。
- 対象範囲: 報告スクリプトだけを変更する。
- 不変条件: 実行時間を100ミリ秒未満にする。
- 受け入れ条件: 重複ID一覧が入力と一致する。
- 確認方法: 既知入力と出力を照合する。

## S3 実装詳細の複製

依頼:

- ユーザー発話を持つ親セッション数を月別に出力する。

契約:

- 達成結果: 月別件数を出力する。
- 受け入れ条件: フィクスチャの期待件数と一致する。
- 確認方法: テストを実行する。
- 条項: SQLは`message.session_id = session.id`で結合し、`json_extract(message.data, '$.role') = 'user'`を使う。

既存所有先:

- SQLとDB列は集計スクリプトとそのテストが所有する。

## S4 問題なし

依頼:

- 入力Markdownから見出し一覧をJSONへ出力する。
- 入力ファイルは変更しない。

契約:

- 達成結果: 見出し一覧をJSONへ出力する。
- 対象範囲: 変換器とテストを変更する。入力Markdownは変更しない。
- 不変条件: 入力ファイルのハッシュを実行前後で維持する。
- 受け入れ条件: フィクスチャの見出し順と出力順が一致する。
- 確認方法: フィクスチャテストと入力ハッシュ比較を実行する。

既存所有先:

- 変換器がMarkdown見出しを出現順にJSONへ変換する。
- 既存フィクスチャテストが見出し順を検査する。
- 今回の変更は変換器とテストに閉じる。
