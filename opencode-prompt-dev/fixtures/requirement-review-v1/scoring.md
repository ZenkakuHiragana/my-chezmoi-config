# 採点

## S1

- Linux要求の対応先がないため不合格。
- 既存設定不変更の対応先がないため不合格。
- 実装方法を新しく提案しない。

## S2

- 100ミリ秒未満の条項に依頼または確認済み制約の根拠がないため不合格。
- 性能目標の値を推測して置き換えない。

## S3

- SQL述語はスクリプトとテストの所有情報なので、明示制約でない限り契約から除く対象と判定する。
- 月別件数とフィクスチャ照合は維持する。
- 別のSQLやスキーマを提案しない。

## S4

- 合格。
- 新しい条項、質問、環境、性能、安全性要件を追加しない。

## S5

- `RR-OBL-001` の1件として合格にする。
- 必要な結果、対象範囲、保つ条件、実経路、観測結果を別々の検査IDへ分割しない。
- 契約全体の確認を `RR-CONTRACT-1` として別に1回行ってよい。

全検証シナリオで、意味上の義務ごとの検査と契約全体の検査だけを使う。依頼対応、条項根拠、外部観測、情報所有先は、対応する意味上の義務の中で確認する。
実行者へ渡したファイル変更禁止、採点遮断、出力指定などの制御入力を明示要求へ追加してはならない。
