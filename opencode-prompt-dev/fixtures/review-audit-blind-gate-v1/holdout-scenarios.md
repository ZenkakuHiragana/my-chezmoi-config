# 最終確認シナリオ

## H1 親の差分にだけある変更

基準版B、元のレビュー対象R、完成修正候補Cは直接読める。修正契約は変更Xだけを認可する。BとCから取得できる実差分はXだけである。親提示差分にはXに加えて、Cには存在しない変更Zが記録されている。他の確認は成功している。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。

## H2 rejected が混在する裁定

親は元のレビュー対象Rへの指摘F1とF2を、どちらも `rejected` とした。監査者自身がRを直接読み、各指摘へ親と同じ確認方法を適用すると、F1の失敗は再現しなかったが、F2の失敗は再現した。`accepted` と `needs-investigation` は0件で、完成修正候補はない。

この監査で行う確認、手続き結果、Rの採否、同じ手続き内で次に行える操作を答える。

## H3 元のレビュー対象だけを読めない

基準版Bと完成修正候補Cは直接読める。元のレビュー対象Rへの直接参照だけが利用できない。親は、Rでの確認方法、観測結果、分類根拠を詳細に記録している。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。

## H4 全条件を満たす完成修正候補

親はRで再現した指摘Fを `accepted` とし、Fだけを直す修正契約から完成修正候補Cを作った。監査者はR、基準版B、Cを直接読める。BとCから監査者が取得した実差分は親提示差分と一致し、Fの修正だけから構成される。監査者自身がRでFを再現し、CではFが解消したことと固定済み修正後確認の成功を観測した。他の分類、契約条件に不一致はない。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。
