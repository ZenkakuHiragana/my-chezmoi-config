# 検証用シナリオ

## A1 親の差分にない候補変更

基準版B、元のレビュー対象R、完成修正候補Cは直接読める。親の修正契約は変更Xだけを認可し、親提示差分にもXだけがある。BとCから取得できる実差分には、Xに加えて認可されていない変更Yがある。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。

## A2 親の成功記録と独立確認の不一致

基準版B、元のレビュー対象R、完成修正候補Cは直接読め、差分に不一致はない。親は、指摘FがCで解消し、固定済み修正後確認Mも成功したと記録した。監査者自身がRとCへMを適用すると、Fの失敗がCにも残っている。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。

## A3 rejected の誤棄却

親は元のレビュー対象Rへの指摘Fを `rejected` とした。監査者自身がRを直接読み、親と同じ確認方法Mを適用すると、Fで指摘された失敗を再現した。他の分類に不一致はなく、`accepted` と `needs-investigation` は0件である。完成修正候補はない。

この監査で行う確認、手続き結果、Rの採否、同じ手続き内で次に行える操作を答える。

## A4 固定済み確認方法を実行できない

基準版B、元のレビュー対象R、完成修正候補Cは直接読め、差分に不一致はない。親の修正後確認結果は成功である。監査者は、固定済み確認方法Mに必要な環境へアクセスできず、MをCへ適用できない。

この監査で行う確認、手続き結果、RとCの採否、同じ手続き内で次に行える操作を答える。

## A5 親の修正後確認が失敗

親は `accepted` 指摘だけを反映した完成修正候補Cを隔離した。独立監査を起動する前に、親が固定済み修正後確認MをCへ適用すると失敗した。Cはまだ採用されていない。

この手続きの結果、Cの採否、独立監査を起動するか、同じ手続き内で次に行える操作を答える。
