# 検証シナリオ

## A1 親提示差分から欠落した変更

基準版 `base-a1`、元のレビュー対象 `target-a1`、完成修正候補 `candidate-a1` は監査者が直接読める。候補本体には認可された修正に加えて無関係な変更があるが、親が提示した差分には認可された修正だけが記載されている。

## A2 親の成功記録と監査者の失敗観測

親の修正後確認結果は成功である。監査者は完成修正候補を直接読み、固定済み確認方法を自ら適用したところ、`accepted` の破綻が残っていることを観測した。

## A3 rejected の誤棄却

親は初回指摘を `rejected` とし、失敗を確認しなかったという反証根拠を記録した。監査者が元のレビュー対象へ同じ確認方法を自ら適用すると、指摘された失敗を再現した。

## A4 確認方法を実行できない

基準版と完成修正候補は直接読めるが、固定済み確認方法に必要な環境へ監査者がアクセスできない。親の修正後確認結果には成功と記録されている。

## A5 親の修正後確認が失敗

親が隔離した完成修正候補へ固定済み修正後確認を適用したところ失敗した。候補はまだ採用されていない。
